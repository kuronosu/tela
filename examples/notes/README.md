# notes

A small plain-text notes app, and the acceptance test of phase 12 ("desktop essentials") and of phase 13 ("desktop integration, the rest"), on Linux and Windows. Phase 12: a tray icon, native open and save dialogs, two windows and a remembered window position. Phase 13: it accepts a dropped file, registers a global shortcut, reopens in its running instance from a deep link, registers itself for `notes:` links and `.md` files, and keeps its locked notes encrypted with a key in the system keyring.

Its look is "Graphite, Tela light with amber": stone in the light scheme (the palette of `examples/hello`), graphite in the dark one, and one amber accent in both that Preferences can change. The theme (`theme.go`) is `kit.Theme()` with two tokens of its own, `sidebar` and `gold`, and a radius of 10.

The main window is frameless and draws its own title bar (`kit.TitleBar` with `kit.Plain`, the platform's arrangement in the `sidebar` color) with the app's badge and the Open and Save buttons. Under it are three panes:

- **The rail**: New note, the views (All notes, Pinned, Unsaved), the folders and the #tags of the library, each with its count, and Preferences at the bottom.
- **The list and the editor**, when a note is open: the search field and the cards of the notes of the chosen filter, and the note: a header with its folder menu, its tags, an Unsaved mark and the pin, a title field, the text, and a status line (the file's path or "In your library", words, characters).
- **The overview**, when no note is open: the title of the filter with its count, the search field and a grid of cards.

A rail item always shows the overview of its filter, also the one that is already chosen, and a card opens its note with the list of the same filter next to it. The way back to the overview from a note is the rail's item (again) or Escape in the list: the first Escape clears the search, the second goes back. The app icon is drawn in code (`icon.go`), so the example has no image file.

The library:

- A note has a **title** (the editor's title field, separate from the text), a **text** (the body: the only thing a file holds), an optional **folder**, a **pin** and the date it last changed. With no title, a note is called by its file's name, else its first line, else "Untitled note". Opening a file makes a note titled with the file's name without its extension.
- **Tags** are the `#hashtags` written in the text, as in Bear (a `#` that starts the text or follows a space, then letters, digits, `-` or `_`; `# Heading`, `C#` and URL anchors are not tags). The rail lists all of them and the cards and the header show them: there is no other tag editor.
- **Folders** exist while a note is in one. A note's folder is chosen from its header: a menu of the folders, "No folder" and "New folder…", which asks for a name. A new note (or an opened file) goes into the folder that the rail has chosen, and is pinned in the Pinned view; where it would not show in the list (a tag, Unsaved, a search), the list goes back to all notes.
- **Deleting:** the trash button of the editor's header, Ctrl+Shift+D (Delete and Ctrl+Backspace edit the text, so they are not used), or Delete in the context menu of a card (a right click, or Shift+F10), which also pins. A note with changes that are not saved to a file, or tied to a file, asks first (`kit.AlertDialog`, which says that a file on disk is not deleted); any other is deleted at once, with a toast that has an Undo action. The note after it in the list opens (else the one before, else the overview).
- Pinned notes come first, then the most recently changed. Dates read "Today, 09:41", "Yesterday, 22:03", the weekday within the week, else "Oct 12". The clock is the package variable `now`, which the tests replace.
- The first run has four short welcome notes that show folders, tags and a pin. A `notes.json` of an earlier version (no title, folder, pin or date) loads and its notes look the same, without any of them.

What it shows:

- **Native dialogs** (`desktop.OpenFile`, `desktop.SaveFile`). Open reads a `.txt` or `.md` file into a new note and remembers its path (a file already open just selects its note); Save writes the note to its file, or asks where with the title as the suggested name. Both are modal to the main window (`desktop.Parent`), answer on the UI thread (the callback sets state directly), and treat cancel as "do nothing". Errors are `kit` toasts.
- **A second window.** Preferences is a `tela.Window` declared inside the main window's tree, so it exists exactly while `prefsOpen` is true, and its `OnClose` sets that state to false. It shares the app's component tree: it reads the same settings the main window reads, with no plumbing. It is a column of sections (Appearance, Editor, General, Shortcuts) and the rows of the chosen one.
- **Windows 11 look.** Preferences sets `Backdrop: tela.BackdropMica` and, on Windows, a root of `bg-background/60`, so on Windows 11 22H2 the window is Mica (in its title bar and through the 40% the root leaves clear); everywhere else the backdrop is ignored and the root is opaque.
- **Settings as state.** `desktop.UseSetting(key, default)` is a `useState` stored in `settings.json`: theme, accent, previews in the list, font size, line spacing, word wrap, "Keep running in the tray", "Notify when a file is saved". The Preferences window and the main window call it with the same keys, and a change in one builds the other.
- **Theme and accent at runtime.** Theme (Light, Dark or System) is `tela.SetColorScheme` and the accent swatches are `tela.SetTheme` with a theme whose `primary`, `gold` and `ring` tokens change (`theme.go`, `useAppearance`); both apply to every window. `withAppearance` gives `tela.Main` the stored values, so the first frame already has them.
- **The library** is `desktop.UseStoreSetting` on `notes.json` in `desktop.DataDir()`: every edit is stored (coalesced and atomic), a missing file starts the welcome notes, and a corrupt file is kept as `notes.json.corrupt` with a toast saying so. The store decodes what it reads over the default value note by note, so the welcome notes are the default only when the file has no library: otherwise an old note with no title would take the welcome note's.
- **Window placement.** The main window is `desktop.PersistApp(App)` and Preferences is a `desktop.SavedWindow{Key: "preferences"}`: both open where they were closed (position too on Windows and X11; on Wayland the size and the maximized state, and the position where the compositor restores sessions).
- **A tray icon** (`desktop.Tray`): click toggles the window, the menu has New note, Show Notes or Hide Notes (following the window), Preferences… and Quit. With "keep running in the tray" on and a tray that works (`OnError` clears it), closing the window hides it (`App.OnClose`).
- **A question before quitting** (`desktop.ShowMessage`, Yes/No/Cancel): with the tray off and notes that changed since their last Save, closing asks whether to save them. Yes saves each (a save dialog for a note with no file) and quits only if every save worked; No quits and leaves the changes in the library as drafts; Cancel keeps the app running.
- **A notification** (`desktop.Notify`, "Saved <name>") after a successful save when the setting is on; a desktop without notifications gets a toast instead.
- **Shortcuts:** Ctrl+N, Ctrl+O, Ctrl+S and Ctrl+, (Cmd on macOS), Ctrl+Shift+D (delete the open note), and Escape in the list.

## Phase 13: desktop integration

- **Dropped files and text** (`drop.go`, `intake.go`). The whole main window is a drop target (`h.OnDragEnter`, `OnDragOver`, `OnDragLeave`, `OnDrop`). `.txt` and `.md` files become notes exactly as Open makes them (a title from the file's name, nothing unsaved, a file already open selects its note); several files make several notes and the last one opens. Dropped text becomes a note of its own, unsaved like a typed one. A file of another kind is named in a toast and does not stop the others. While a drag that carries files or text is over the window, the notes pane shows a dashed amber overlay, "Drop to import". It is counted the way `tela.DragEvent` documents (enter adds one, leave takes one off, because the enter of the new element comes before the leave of the old one), so it stays while the drag moves over the cards and the fields and goes when it leaves, drops or is canceled. Any other drag (an image, a custom type) gets no overlay and is refused (`DropNone`). Preferences takes no drops.
- **A global shortcut**: Quick note, `Ctrl+Alt+N`, is a `desktop.GlobalShortcut` (ID `quick-note`) mounted while the setting "Quick note from any application" is on (Preferences, Shortcuts; on by default). Pressed from any application it shows and raises the main window, also from the tray or when minimized, and makes a note with the cursor in its title, in the folder the rail has chosen. Preferences shows the shortcut and what the OS said through `OnStatus`: the keys that were bound (the desktop may choose others: the Wayland portal asks the user), or "Taken by another application", "Refused: the desktop did not bind it", "Removed in the desktop's shortcut settings" and, for `ErrUnsupported`, "Not available on this desktop".
- **One instance and deep links** (`link.go`). `main` is `tela.Main(desktop.SingleInstance(withAppearance(desktop.PersistApp(App))))`: a second process hands its arguments and working directory to the running one and exits, and the running one brings its window up (from the tray too). `desktop.UseLaunch` handles the program's own start and every forwarded launch:
  - files (absolute, relative to the working directory of the process that was started, or `file:` URIs) open as notes, as Open does, whatever their extension: the user named them;
  - `notes://new?title=Groceries&text=milk%20and%20eggs` makes a note (both parameters are optional; with neither, it is a blank note), in the folder the rail has chosen;
  - `notes://open?id=3` shows the note with that ID. A card's context menu has "Copy link", which puts that link on the clipboard.

  `notes:new?...` and `notes:open?id=3` (no slashes), and a slash after the action, mean the same. Another scheme or a flag is not Notes's and is ignored; an unknown action, a missing ID or a note that is not in the library is a toast that says how to write it.
- **Registration** (`links.go`). At start Notes calls `desktop.Register(desktop.URLScheme("notes"))`, which makes it a candidate handler (Linux: its own `.desktop` file in `~/.local/share/applications`; Windows: `HKCU\Software\Classes`) and never the default, never takes what another application holds, and writes nothing when nothing changes. It is skipped when the setting is off (Unregister turns it off), in tests, in `tela snapshot`, under `go run` (a temporary program: the OS would keep running a path that no longer exists) and under `tela dev` (`ErrDevExecutable`, handled quietly). Preferences, General, "Links and files":
  - "Open notes: links": the status (not registered, registered, registered and the default, held by another application), a Register or Unregister button and, when Notes is registered and is not the default, a separate "Make default" button;
  - "Open .md files with Notes": a switch that registers Notes as a candidate for `.md` (`desktop.FileType`), and a "Make default" button. Windows lets only the user choose the default for a file type, so the button opens the Default apps settings (`DefaultAsked`) and the row says so.

  Notes never makes itself the default without that button.
- **Locked notes** (`lock.go`). A note is locked from the lock button next to the pin in the editor's header, or "Lock" in the card's context menu. Its title and text (and the text of its last Save, which would give it away) are stored encrypted in `notes.json`: AES-256-GCM with a random nonce for every write, under a 32-byte random key that is made the first time a note is locked and kept with `desktop.SetSecret` under the name `library-key`. The folder, the pin and the date stay in the clear. The note's JSON then has `"locked": true` and `"sealed": "v1:<base64 of nonce, ciphertext and tag>"` with empty `title`, `text`, `saved` and `path`; both fields are absent from a note that is not locked, so an older `notes.json` loads unchanged. The note's ID is the additional authenticated data, so a sealed value copied to another note does not open there.

  A locked note's card has a lock, the title "Locked note" and no preview; opening it shows "This note is locked" and an Unlock button. Unlocking reads the key off the UI thread (a goroutine that gives the result back with `tela.Post`: the keyring may be waiting for the user), decrypts, and keeps the note unlocked **until it is locked again ("Lock now") or the window is hidden** (to the tray); the key and the text stay in memory only while a note is unlocked. While it is unlocked every edit is encrypted again and stored, so the file never holds more than the ciphertext. "Remove lock" in the card's menu stores an unlocked note in the clear again. Search and tags do not look into locked notes.

  **A locked note is not tied to a file.** Locking a note that was opened from or saved to a file detaches it: its path leaves `notes.json` too, since a file's name can say what the note is about. The file itself still holds the text in the clear, so a `kit.AlertDialog` asks right away: "Move the file to the Trash?", naming the note, the file and its folder, with "Keep file" and "Move to Trash" (destructive). Nothing happens without that answer, and the file is never deleted: Move to Trash calls `desktop.MoveToTrash` in a goroutine (it blocks), which moves it where the user can restore it, and a toast says so. When the desktop cannot move it there (`ErrUnsupported`: no trash, or a file the trash cannot take, such as one on a network drive or another disk), the file stays and a dialog says where it is; for the rest of the session the question after a lock is that notice, without a button that would not work. Any other error is a toast that says the file is still in its folder, and a file that is already gone is a quiet toast. A locked note is never written to a file: the title bar's Save is off while one is open (its tooltip: "Locked notes stay in your library. Remove the lock to save to a file."), Ctrl+S shows the same in a toast, it never counts as unsaved, and quitting never asks about it. "Remove lock" leaves the note in the library, detached. A `notes.json` from an earlier build of this phase that has a locked note with a path loses that path when it is opened.

  The keyring's answers: `ErrSecretCanceled` (the user dismissed the prompt) is a quiet toast, "The keyring stayed locked"; `ErrSecretNotFound` while locked notes exist says that the key is gone and keeps the encrypted notes as they are (a new key is never made then, it would not open them); `ErrUnsupported` (no keyring) turns the lock controls off, with a tooltip that says why. Only `crypto/*` of the standard library is used.

How it handles a hidden window: a hidden window draws nothing, but its components still build and its effects run (ADR-185), so the tray's handlers set state as usual and the tray menu follows the window. The tray is a small component of its own (`notesTray`) that reads `UseWindow().State()`, so only it builds again when the window's state changes; its toggle reads the state when it runs (`win.State()` outside a build only reads), so two quick clicks act on what the window is.

`App.OnClose` is a plain function outside the component tree, but what closing does depends on state (the tray setting, the unsaved notes). The screen registers its latest handler in a small gate (`close.go`) after every build.

## Run it

Build the program first for what registers it: `CGO_ENABLED=0 go build -o notes ./examples/notes` and run `./notes` (`go run` makes a temporary program, which Notes does not register, and under `tela dev` registering is off too). The rest works either way.

- In a window: `CGO_ENABLED=0 go run ./examples/notes`.
- Without a window or a tray: `CGO_ENABLED=0 go run ./cmd/tela snapshot --size 960x640 [--dark] -o notes.png ./examples/notes`; the other screens are previews: `--preview "2 Overview"` and `--preview "3 Preferences" --size 540x440`. Under `tela snapshot` the library is a throwaway one in a temporary folder.
- Try the phase 13 features:
  - Drop: drag a `.md` or `.txt` file from the file manager onto the window; the overlay shows while it is over it.
  - Quick note: press `Ctrl+Alt+N` in another application. On Hyprland and other Wayland desktops the compositor asks the first time (the GlobalShortcuts portal; some bind other keys, which Preferences shows). On X11 and Windows the key is grabbed at once, or Preferences says another application holds it.
  - A deep link from a terminal, with Notes registered (Preferences, General, or the first start of a built program):
    - Linux: `xdg-open 'notes://new?title=Call&text=hi'`; `xdg-open 'notes://open?id=3'`.
    - Windows (cmd): `start notes://new?text=hi`; (PowerShell) `Start-Process 'notes://new?text=hi'`.
    - Without registering, run the program with the link or a file: `./notes 'notes://new?text=hi'`, `./notes todo.md`. Notes already running comes up with the result and the new process exits.
  - Registration: General, "Links and files". Check it with `xdg-mime query default x-scheme-handler/notes` (Linux; Notes is only a candidate until Make default) or, on Windows, Settings, Default apps.
  - Locked notes: open a note and press the lock in its header. The keyring is GNOME Keyring or KWallet on Linux and the Credential Manager on Windows. `grep sealed ~/.local/share/dev.telaui.notes/notes.json` (Windows: `%AppData%`) shows the ciphertext.
- Tests: `CGO_ENABLED=0 go test ./examples/notes`. They use `telatest.TempDesktopDirs`, so no test touches the real folders (nor the real keyring, global shortcuts, applications folder, registry or clipboard: the headless desktop plays them), and drive both windows through the headless window manager: dialogs answered with `AnswerFileDialog`, the message box with `AnswerMessage`, notifications read with `Notifications`, the tray clicked with `ClickTrayItem`, `ExpectWindowState` and `ExpectQuit` for close, and placements checked after a restart. The phase 13 tests: `drop_test.go` (`DropFiles`, `DropData`, `HoverDrag`: files and text, an open file, refused types, the overlay through enters and leaves), `shortcut_test.go` (`PressShortcut`, `SetShortcutStatus`, the setting, the statuses in Preferences), `launch_test.go` (`InjectLaunch` with links, absolute and relative files, bad links, a hidden window), `register_test.go` (`Registrations`, `HoldAssociation`, `SetDefaultHandler`: registering, unregistering, a scheme another application holds, Make default, `.md` files) `lock_test.go` (the cipher, locking, that `notes.json` has no plaintext, unlocking, edits, locking again and hiding, a canceled prompt, a lost key, a wrong key, no keyring, an older library) and `trash_test.go` (`Trashed`, `FailTrash`, `Unsupported(telatest.Trash)`: locking a file's note leaves no path nor plaintext in `notes.json`, Keep file, Move to Trash, a desktop without a trash, a failure and a file already gone, Remove lock staying detached, Save off and Ctrl+S, quitting with locked notes, an older library with a locked note's path). Goldens (`testdata/notes_x1.png` and `notes_dark_x2.png` for the note, `notes_overview*.png` for the overview, `notes_edited.png`, `notes_folder_menu.png`, `preferences.png`, `preferences_dark.png` and `notes.aria.yml`, and for phase 13 `notes_drop*.png`, `notes_locked*.png`, `notes_unlocked.png`, `notes_no_keyring.png`, `notes_trash_dialog*.png`, `notes_trash_notice.png`, `notes_save_locked.png`, `preferences_general.png` and `preferences_shortcuts*.png`; all with a fixed clock) are regenerated with `TELA_UPDATE=1 CGO_ENABLED=0 go test ./examples/notes`.
