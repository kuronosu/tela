# player

A music player built on package `kit`: a card with generated cover art, title, artist, a seek bar (`kit.Slider`) with elapsed and total time, previous / play-pause / next buttons (`kit.Button` with a `kit.Tooltip`), a mute `kit.Toggle` with a volume `kit.Slider`, and a queue of six tracks in a `kit.Card` (from the `lg` breakpoint, 1024 px, up).

The point of the example is the **seek bar**. A goroutine ticker advances the progress ten times a second, and nothing is built or laid out on a tick:

- `Transport` (see `transport.go`) is the state of the player, made of `tela.UseValue`s created by the custom hook `useTransport`. The clock goroutine runs in a `UseGo` and stops on unmount; each tick does `tela.Post(func() { tr.advance(dt) })`, so the update runs on the UI thread in order with the other updates.
- The seek bar is `kit.Slider{ValueSource: tr.Elapsed, Max: total, Step: 1, OnValueChange: tr.SeekTo}`. `ValueSource` (a kit addition for this case) makes the slider follow a `tela.Value`: its knob and range read the Value in paint-phase closures, so a tick repaints them and builds and lays out nothing, and a drag stores each position in the same Value, which is a repaint again (`TestSeekDoesNotBuild`, `TestSecondsOnlyBuild`, `TestProgressAdvancesWithoutBuilding`). A press on the bar or an arrow key starts from the Value's current value (`aria.SliderOptions.LiveValues`), not from the one of the last build.
- `Secs` (whole seconds) is what the time label reads inside `TextFn`, so its paragraph is laid out once per second and nothing builds. `Beat` counts the seconds the clock has played; the `SeekBar` component builds on it, once a second, so `aria-valuenow` (the knob's value, read by assistive technologies) is never more than a second old. A seek does not move it.
- `Playing` and `Track` are read in component bodies, so a toggle rebuilds the controls and a new track rebuilds the card, the seek bar and the queue.

The look: kit's default style with the dark color scheme forced by `App.ColorScheme` (a player is a dark app), so every color is a token (`bg-card`, `text-muted-foreground`, `bg-primary` for the range and the play button). The transport buttons are `kit.Button`s in two extra sizes, `transport` and `play`, added to a copy of the style (`playerStyle`, a recipe edit applied with `kit.StyleProvider`), with filled Lucide icons (`icons/`, generated by `tela icons gen`). The cover art, the violet accents and the glow behind the cards are the example's own.

The rest: click or drag the seek bar, or focus the knob and use the arrows (one second), Home and End; click a queue row to play it (each row is a ghost `kit.Button`); the pause button becomes play when paused and no frames are drawn while paused. The cover shrinks with the window height (`size-[clamp(96px,calc(100vh-356px),332px)]`), so the controls stay visible down to about 700x440.

## Run it

- In a window: `CGO_ENABLED=0 go run ./examples/player` (1280x800).
- Without a window: `CGO_ENABLED=0 go run ./cmd/tela snapshot --size 1280x800 --scale 2 -o player.png ./examples/player` (the preview is a minute and 24 seconds into the first track; the theme and the dark scheme come from `var App`).
- Tests: `CGO_ENABLED=0 go test ./examples/player`. They run the clock faster (`tickEvery` and `timeScale` are package variables) and check the progress, pause (no frames while paused), next/previous/queue, seeking by click, drag and keyboard, the end of a track, the volume and mute controls, the tooltips, the goroutine stopping on unmount, the aria snapshot (`testdata/player.aria.yml`), the damage of a tick, and the goldens (`testdata/player_x1.png`, `player_x2.png`; regenerate with `TELA_UPDATE=1 CGO_ENABLED=0 go test -run TestGolden ./examples/player`).
