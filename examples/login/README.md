# login

A "Welcome back" sign-in screen built on package `kit` in its default (shadcn) style, in the shape of shadcn's login-04 block: one `kit.Card` on a muted page, with the form on the left and a brand panel (gradient, grid, a glass card with a quote) on the right. Below `md:` (768 px) the panel hides and the form takes the whole card. The link under the form ("Don't have an account? Sign up") turns the same card into a **Create account** form, and its own link ("Already have an account? Sign in") turns it back: the mode is a `tela.UseState` in the root, with no routing. It is the example to imitate for forms: the short one with a request in flight (Sign in) and the long one with every kind of text field (Create account).

The fake server accepts any well-formed e-mail with the password `weave-2026` (the alert for a wrong one says so) and creates any account that is valid.

## Sign in

What it shows:

- **A form that asks nothing it should not.** `Form(OnSubmit(...))`: Enter in a field and the Sign in button (`Type: "submit"`) both land in the handler, which marks the form as tried (`Submitted`) and, if it is valid, starts the request. Each field is a `kit.Field` whose `Error` shows once the user tried (`shown(submitted, ...)`), so nobody is scolded for the first letter; the field is `aria-invalid` (red border and ring from the recipe, `[invalid]` in tests) and the message has the `alert` role. The messages are `Values.EmailError` and `PasswordError` in `model.go`; the e-mail syntax is HTML's, the same `Type("email")` checks.
- **A request without a goroutine: `tela.UseTimeout`.** While the status is `Loading` the page asks for a timeout of `signInDelay`; the delay is 0 otherwise, which cancels it, and a change of delay restarts it, so every attempt gets its own. The function it calls is the latest build's, so it judges what is typed at that moment. It is on the frame clock, so a test moves it with `App.Advance` and a screen with no request pending is idle. A real app would use `tela.UseGo` with a context for a real network call.
- **A loading button.** The same `kit.Button` with a spinner (`Icon(icons.LoaderCircle, Class("animate-spin"))`) and "Signing in…" as children, `Disabled` so it cannot be sent twice (the handler checks too: the last line of defense is the handler, not the button). The three other ways in are disabled as well.
- **Show/hide password.** A ghost icon `kit.Button` over the end of the field with `AriaPressed` and a constant `AriaLabel` ("Show password": the state is the pressed attribute, not the name). `Type` is just a prop, so toggling it swaps the dots for the text without remounting the input, and the text and caret survive.
- **An alert.** `kit` has no `Alert`, so `Alert` in `parts.go` is a `Div` with `Role("alert")` and the destructive tokens (`border-destructive/30 bg-destructive/5 text-destructive`), which a screen reader announces when it appears. The next edit takes it away: `OnChange` on the Form bubbles from every text field.
- **Horizontal `Field`, social buttons, a captioned separator.** "Remember me" is a horizontal `Field` around a `kit.Checkbox` (the label toggles it); the other ways in (Passkey, Magic link, SSO) are outline `kit.Button`s with generic Lucide icons, no brand logos; "Or continue with" is two `kit.Separator`s and a caption.

## Create account

The same card with the longer form, in the same visual language: a display name, an e-mail, a password with a strength meter, a bio and the terms. The card's column is a little tighter in this mode so the form fits the 1000x760 window.

- **`kit.Field` around every control.** `kit.Field{Label, Description, Error, Children: kit.Input{...}}` ties the label, the control and its help text with an id: the label names the field (`textbox "E-mail"`), clicking it focuses the field, and the field is described by its error or its description. This holds for both modes, for `kit.Input`, `kit.Textarea` and `kit.Checkbox` alike. The terms are a horizontal `Field` with a `kit.Checkbox`, as in shadcn's docs.
- **Controlled fields.** The name, e-mail and password are `Value: &value, OnValueChange: set.Set`, because the validation and the strength meter read them (and the e-mail and the password are shared with Sign in: switching modes keeps the e-mail). `Values.CanCreate()` (`model.go`) decides whether the submit button is `Disabled`; the e-mail rule is the one of Sign in (`EmailError`), not a second copy. Enter in a field clicks the first submit button and does nothing while it is disabled, as in a browser; the handler checks again.
- **`BindValue` for the bio, and why.** The bio is a `tela.UseValue` in the root passed to the `kit.Textarea` as `Props: h.BindValue(bio)`. Typing in it writes the Value without rebuilding the page, and its counter is an `h.TextFn` that reads the same Value, so a keystroke repaints one span and builds nothing (`TestBio` checks `Stats().Builds` does not move). Nothing else reads the bio, so it needs no state; a submit that sent it would read `bio.Latest()`. Being a Value of the root, it survives a trip to Sign in and back.
- **A growing Textarea.** The recipe's `field-sizing-content` with `min-h-16 max-h-40`: 64 px when empty, taller with every line up to 160 px, then it scrolls. `MaxLength: 160` counts UTF-16 code units as HTML does (an emoji is 2). The counter is a `Span` placed with `absolute` on the label's line, because a `Field` has no slot beside its label; the left column has `min-w-0` so a long line in the textarea cannot widen the grid column in a narrow window.
- **Invalid states.** The e-mail field gets an `Error` once it was left (`OnBlur`) and its value is not an address by HTML's syntax. The button is disabled until the form is valid, so unlike Sign in there is no "try" to wait for, and the field shows its error on blur; the `Field` marks the input `aria-invalid` as in Sign in. The disabled button says why in a line under it.
- **Password button and strength meter.** The same ghost icon `kit.Button` as in Sign in, with a `kit.Tooltip` that names what the next press does and `AriaPressed`. The strength is a `kit.Progress` from 0 to 4 whose `IndicatorClass` is the color of the score (`Strength` in `model.go`).
- **The same request.** A valid form starts the same `UseTimeout`, the button turns into a disabled "Creating account…" with a spinner, and `signInDelay` later the form is replaced by "Account created", a `status` region like Sign in's welcome, with "Continue to sign in".
- **Any language.** The name field is a plain text input; with an input method (IME) it composes Japanese, Chinese or Korean like any browser field. The goldens use Latin text only: `telatest` and `tela snapshot` shape with the embedded fonts, which have no CJK glyphs (ADR-031); a real window uses the system's fonts.

## Both modes

- **Screen readers.** Every control has an accessible name from its `Field` label (or `AriaLabel` for the icon button), the errors have the `alert` role, a request's answer is an `alert` (the wrong password) or a `status` (the welcome, the confirmation), and the mode switch is a real `kit.Button` of the `Link` variant whose `AriaLabel` ("Sign up for an account", "Sign in to your account") says where it goes and contains its visible text, so it makes sense out of the sentence around it.
- **Theme tokens.** `bg-background`, `bg-muted/50`, `text-muted-foreground`, `bg-card` come from `kit.Theme()`, so the screen follows the color scheme with no `dark:` pairs (`tela snapshot --dark`). The brand panel is decoration and keeps its own gradient in both schemes; its headline follows the mode.
- **Responsive.** `md:grid-cols-2` on the card's content and `hidden ... md:flex` on the panel; the card has `md:min-h-[640px]` so it does not shrink around the short welcome. A window shorter than the form scrolls like a page.
- **`var App` and `Previews`.** `var App` is the window (1000x760, the theme and the root class); `Previews` start `Page` in each state (`Mode`, `Initial`, `Submitted`, `Touched`, `Status`): "1 Sign in", "2 Invalid", "3 Wrong password", "4 Signing in", "5 Signed in", "6 Create account", "7 Create account filled", "8 Create account invalid" and "9 Account created".
- **Icons** are a Lucide subset generated by `tela icons gen` (`icons/`: layers, eye, eye-off, loader-circle, circle-alert, circle-check, mail, key-round, building).

Gaps in `kit` this screen works around: there is no `Alert` (a `Div` with the alert role), a `Field`'s label is a string with no slot beside it (so "Forgot password?" shares a row with "Remember me" instead of sitting at the end of the label, the bio's counter is an absolute `Span`, and there is no "(optional)" in a lighter weight or links inside the terms), and a `Separator` has no caption (two separators and a span).

## Run it

- In a window: `CGO_ENABLED=0 go run ./examples/login` (1000x760). Sign in with any e-mail and `weave-2026`, or follow "Sign up".
- Without a window, one image per state: `CGO_ENABLED=0 go run ./cmd/tela snapshot --scale 2 [--dark] --preview "3 Wrong password" -o login.png ./examples/login`; the one-column layout with `--size 600x800`.
- Its aria snapshot: `CGO_ENABLED=0 go run ./cmd/tela inspect ./examples/login` (`testdata/login.aria.yml`; `testdata/login_create_account.aria.yml` is the other mode).
- Drive it as an agent: `tela mcp ./examples/login`, then `fill` the fields (`submit: true` presses Enter), and `wait` 1500 ms for the answer.
- Tests: `CGO_ENABLED=0 go test ./examples/login`. They check the validation (errors wait for the first try, `Invalid`, they go away as the values become valid), the password toggle and its tooltip in both modes, the whole sign-in on the app's clock (`NoSettle` and `Advance`: the spinner, the disabled controls, the welcome and Sign out), a rejected one (the alert, and the edit that clears it), Enter on an invalid form, one timeout per attempt, the checkbox with its label and the keyboard, the labels, the breakpoint; and for Create account: the mode switch, the whole flow (disabled until valid, the spinner, the confirmation), Enter on a form that is not valid yet, the e-mail's error and its red border by pixel, the strength meter, the eight-character rule, the bio (growth, `MaxLength`, builds, survives a mode switch), the terms with the keyboard, the focus ring and any language; plus the goldens of the nine previews at scales 1 and 2, the dark ones and the narrow ones (`testdata/login_*.png`; regenerate with `TELA_UPDATE=1 CGO_ENABLED=0 go test ./examples/login`).
