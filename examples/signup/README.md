# signup

A "Create your account" screen built on package `kit` in its default (shadcn) style: a gradient brand panel on the left (hidden below `md:`) and a form on the right with a display name, an e-mail, a password, a bio and a terms checkbox. It is the example to imitate for forms.

What it shows:

- **`kit.Field` around every control.** A `kit.Field{Label, Description, Error, Children: kit.Input{...}}` ties the label, the control and its help text with an id: the label names the field (`textbox "E-mail"`), clicking it focuses the field, and the field is described by its error or its description. The terms are a horizontal `Field` with a `kit.Checkbox`, as in shadcn's docs. The buttons are `kit.Button`s (the submit button is `Type: "submit"`, "Sign in" is a `Link` variant) and the confirmation is a `kit.Card`.
- **Theme tokens.** The page uses `bg-background`, `text-muted-foreground` and the recipes' classes, so it follows the color scheme with no `dark:` pairs. `App.Theme` is `kit.Theme()` with the brand's indigo as `primary` and `ring` (`signupTheme`), which colors the buttons, the checkbox, the selection and the focus rings. The brand panel is decoration and keeps its own gradient.
- **Controlled fields.** Name, e-mail and password are `Value: &value, OnValueChange: set.Set`, because the validation and the password strength meter read them. `Values.Valid()` decides whether the submit button is `Disabled`.
- **`BindValue` for the bio, and why.** The bio is a `tela.UseValue` passed to the `kit.Textarea` as `Props: h.BindValue(bio)`. Typing in it writes the Value without rebuilding the page, and its counter is an `h.TextFn` that reads the same Value, so a keystroke repaints one span and builds nothing (`TestBio` checks `Stats().Builds` does not move). `OnSubmit` reads it with `bio.Latest()`.
- **Invalid states.** The e-mail field gets an `Error` once it was left (`OnBlur`) and its value is not an address by HTML's syntax (`ValidEmail`, the same syntax `Type("email")` checks, so the button never disagrees with the border). The `Field` marks the input `aria-invalid`: the recipe paints the red border and ring, the label turns red, assistive technologies read `[invalid]`, and the message replaces the help text. Nobody is scolded for the first letter.
- **Password button and strength meter.** A ghost icon `kit.Button` over the end of the field, with a `kit.Tooltip` and `AriaPressed`, flips the `Type` between `"password"` and `"text"`; the field keeps its text. The strength is a `kit.Progress` from 0 to 4 whose `IndicatorClass` is the color of the score.
- **A growing Textarea.** The recipe's `field-sizing-content` with `min-h-[4.5rem] max-h-40`: 72 px when empty, taller with every line up to 160 px, then it scrolls. `MaxLength: 160` counts UTF-16 code units as HTML does (an emoji is 2).
- **Forms.** `Form(OnSubmit(...))`: Enter in a field clicks the first submit button (and does nothing while it is disabled, as in a browser), the button submits too. A confirmation card (`Role("status")`) appears, and a form-level `OnChange` (it bubbles) removes it at the next edit.
- **Any language.** The name field is plain text input; with an input method (IME) it composes Japanese, Chinese or Korean like any browser field. The goldens use Latin text only: `telatest` and `tela snapshot` shape with the embedded fonts, which have no CJK glyphs (ADR-031); a real window uses the system's fonts.
- **Icons** are a Lucide subset generated by `tela icons gen` (`icons/`: eye, eye-off, circle-check).

Gaps in `kit` this screen works around: there is no `Alert` (the confirmation is a `Card` with a status role and an icon in its title), a `Field`'s label is a string (no "(optional)" in a lighter weight, no links inside the terms text), and a `Field` has no slot beside its description (the bio's counter is a `Span` placed with `absolute` in the field, which is `relative`).

## Run it

- In a window: `CGO_ENABLED=0 go run ./examples/signup` (1100x860).
- Without a window, one image per state: `CGO_ENABLED=0 go run ./cmd/tela snapshot --size 1100x860 --scale 2 [--dark] --preview "3 Invalid" -o signup.png ./examples/signup`. The previews are `1 Empty`, `2 Filled`, `3 Invalid` and `4 Created` (`Previews` in `main.go`; each is `Page` with fields that start it in that state; `var App` gives them the theme).
- Its aria snapshot: `CGO_ENABLED=0 go run ./cmd/tela inspect --size 1100x860 ./examples/signup` (`testdata/signup.aria.yml`).
- Tests: `CGO_ENABLED=0 go test ./examples/signup`. They fill the form with `Fill`, type with `Type` and Tab, check `ExpectValue`, the invalid border by pixel and `Invalid`, submission by button and by Enter, the password button and its tooltip, the bio's growth, `MaxLength` and builds, the labels, the keyboard on the checkbox, and the goldens of the four previews at scale 1 and 2 plus a dark one (`testdata/signup_*.png`; regenerate with `TELA_UPDATE=1 CGO_ENABLED=0 go test -run 'TestGolden' ./examples/signup`).

Below 768 px the brand panel hides and the form takes the whole window; a window shorter than the form scrolls like a page.
