## Survivors

Each: claim · evidence · attempted kill and why it failed · cost · payoff.

### C8. The event-forwarder registry outlived its reason and has drifted
- **Claim:** `core.RegisterForwarder` and tela's `init` (hooks.go:10-32) exist because event types once lived in tela (96dc8ac, ADR-051). All event types are now core types (events.go:108-236 aliases), so core's type switch (callback.go:87-111) can name them. The registry has also drifted: `InputEvent`, `ChangeEvent`, `CompositionEvent`, `SelectEvent` and `SubmitEvent` (fields.go:38-70) are not registered, so their handlers go through `reflect.MakeFunc` and allocate on every call. `TestEventCallbacksDoNotAllocate` (hooks_test.go:115-151) covers 5 of the 7 registered types and none of the field types.
- **Kill attempt:** looked for an import cycle, generics, or an ADR that requires the registry. Found none; the original constraint is gone.
- **Cost:** S (about 12 switch cases; delete the registry, the init and the registry half of callback_test.go:84-117; extend the alloc test to all 12 types).
- **Payoff:** locality (adding an event type touches one package); removes a global mutable registry and the init-order coupling; fixes an allocation regression in text-field handlers.

### C2. The `tela dev` swap and promotion rules can only be tested through real processes and pixels
- **Claim:** `supervisor` depends on concrete `exec.Cmd`, `*remote.Host`/`*remote.Child` and the wall clock (dev_super.go:734-777, plus timers at :476, :491, :886, :1012). So the swap, promotion and exit-classification interleavings are tested only through `newDevHarnessHost` (dev_test.go:101-170: re-exec'd children, pixel polling, 5 `still` checks). Those interleavings are where bugs actually landed: 256e6e6, c6a748e, 8cd7635. The build-failure and newer-save rules are already pure (`built`, `startBuild`, :577-628) but have no direct `handle()` tests.
- **Kill attempt:** ADR-115 chose fake children. A launcher plus a clock is not enough, because the events carry `*remote.Child`, whose fields are unexported. The seam also needs a host/child port across `internal/platform/remote`.
- **Cost:** L for the full seam (launcher, host/child port, clock). S for the first step: move `TestDevBuildFailure` (named flaky in the ROADMAP) and `TestDevNewerSaveCancelsBuild` to direct `s.handle(...)` calls with a fake builder.
- **Payoff:** high leverage for the race rules (deterministic, run under `-short`); the S step removes one flaky test from the harness.

### C19. `layout.Round` and the rounded layout are a dead leftover of the Taffy port
- **Claim:** `layout.Round`, `Data.rounded` and `RoundedLayout()` (round.go, node.go:121,142) have no production caller. Paint snaps to device pixels itself (paint.go:108-125, ADR-045), and logical-pixel rounding would be wrong at fractional scales. Every `core.Box` carries the unused second `Layout` (about 100 bytes). The docs (doc.go:67-69,111-115, engine.go:11) say core "may paint either", which is false.
- **Kill attempt:** checked whether the Taffy/Chromium fixtures use the rounded layout as their oracle (they don't), and for ADRs keeping it (none).
- **Cost:** S. Keep `ScrollWidth`/`ScrollHeight` from round.go; re-record `wantLayoutDigest` (determinism_test.go:21) on amd64 and re-check it on arm64 under qemu.
- **Payoff:** about 1 MB per 10k boxes, a smaller interface, and docs that stop misleading readers.

### C13. Two double-click rules disagree, and content ignores the OS setting
- **Claim:** content clicks use a fixed 500 ms / 5 px rule (gesture/consts.go:26,30, recognizers.go:362, fed from core/input.go:309). Self-drawn caption clicks on Wayland and X11 use 400 ms / 4 px (`platform.CaptionClicks`, window.go:127-159; fallbacks at wayland/windowctl.go:45 and x11/windowctl.go:98). Win32 reads `GetDoubleClickTime` into `SystemSettings.DoubleClickInterval`, but nothing reads that value. Core reads only DarkMode and ReducedMotion (host.go:219-221).
- **Kill attempt:** the finder's claim that the system interval reaches captions was wrong: Linux backends return an empty `SystemSettings{}`, and win32 lets the OS handle caption double clicks. No ADR records the split.
- **Cost:** S. Pass `DoubleClickInterval` (one fallback) into the tree, let `ClickCounter` take the limits, align `CaptionClicks`, and delete the per-backend constants.
- **Payoff:** locality (one rule instead of five constants); Windows users' double-click time is honored; Linux caption and content agree. Reading real Linux settings (XSETTINGS/gsettings) is a separate job.

### C9. `damage.go` lists the push/pop command types by hand in five places
- **Claim:** `reaches` (:263/269), `enclosingAll` (:585), the backdrop walk (:698/700), `isPop` (:1036) and `isPushPop` (:1360) each list all 8 push/pop types to classify commands generically. A new push kind silently falls into the draw branch and produces wrong damage.
- **Kill attempt:** `shiftExact` (:856) and `raster/phase.go:103` need per-kind handling on purpose, so those legs died. The five sites above match `pushKind`/`popKind` exactly.
- **Cost:** S, with no new API: `DisplayList.Match(i)` already encodes the answer (`m > i` push, `0 <= m < i` pop). Check which list is in hand at :801.
- **Payoff:** removes a silent damage-correctness trap and about 20 lines.

### C14. Wayland and X11 copy the CSD resize-edge geometry and have drifted; the contract text is stale
- **Claim:** `resizeEdge` in wayland/windowctl.go:610 (band 5, corner 16, nearer side wins when the window is too small) and in x11/windowctl.go:108 (band 6, corner 16, switch order wins) implement the same logical-pixel rule, and the copies have drifted. Separately, internal/platform/doc.go:341 ("the band takes precedence over hit regions") never picked up Win32's OS-forced exception for snap layouts (frame.go:116-120, commit 47ba1a0).
- **Kill attempt:** Win32's band from system metrics and its button precedence are legitimate, and headless resize would be new behavior. Both legs died; the Linux pair stands.
- **Cost:** S. Add `platform.ResizeEdge(p, size) Edge` with one band and the nearer-side rule; backends map it to their protocol codes and cursors. Amend doc.go:341.
- **Payoff:** one place to tune; consistent band width on Linux; correct contract text.

### C11. The host platform flavor is resolved from `runtime.GOOS` in four places, none overridable (convergent: two lenses)
- **Claim:** core's text-editing flavor (fieldkeys.go:72-80), core's word rules (field.go:490), aria's `ctrlKey` (collection.go:671-678) and telatest's `ControlOrMeta` (keys.go:122-131) each read GOOS. No Mac-flavor test can run off-Mac (combobox_test.go:322 only ever exercises Control). Apps have no "primary modifier" query, and our own examples already differ: examples/native/explorer.go:108 checks Ctrl only, examples/notes/screen.go:235 checks Ctrl or Meta.
- **Kill attempt:** the copies agree today. Core needs a three-state flavor (Linux/Windows/Mac binding tables), not a bool, so the proposed `Primary()` fix was reshaped.
- **Cost:** S–M. One unexported three-state host flavor importable by core, aria and telatest, with a telatest override. A public query needs an ADR.
- **Payoff:** low now, medium at phase 14 (cocoa). Best sequenced just before phase 14.

### C6. The aria token lists are hand-copied three times with no drift test
- **Claim:** the `AriaSort` and `AriaCurrent` token lists live in core (aria_state.go:42,63), in telatest (state.go:124,157) and, for the variant subset, in style (variants.go:413-431). The hint string (:408), the named-variant table (:101-110) and the `AriaStates` mask (:76) are also edited by hand. Nothing checks the copies against each other.
- **Kill attempt:** most of the six-file spread is required public surface, and lint already reuses core's lists. The proposed home in semantics breaks §5 (style sits below semantics). The bit count was wrong (18 aria bits, not 33).
- **Cost:** S–M for one table in `internal/style` that derives the variants, hint, core's validation lists and telatest's lists. S for a cheap alternative: one test that cross-checks the three lists.
- **Payoff:** modest. Removes the drift risk and about 4 of the 6-7 edit points per token attribute. New token attributes are rare (4 of 492 commits).

### C16. `cmd/tela` re-parses the aria-snapshot YAML, and no test feeds it the writer's real output
- **Claim:** `parseSnapLine`/`withRef` (mcp_refs.go:53,133) re-implement the key grammar and quoting rules of internal/semantics/snapshot.go:180,335. `TestParseSnapLine` uses hand-written lines only. A format drift would quietly drop MCP refs; the ByRole+Nth count check (ADR-174) prevents wrong refs.
- **Kill attempt:** the format is pinned to Playwright 1.61.1, and structured nodes across the `go test -overlay` process boundary would face version skew. That leg died; the untested duplicate stands.
- **Cost:** S. Either move the parser to `semantics.ParseSnapshotLine` with a round-trip test, or add a cmd/tela test that renders a fixture through `telatest.AriaSnapshot` and parses every line.
- **Payoff:** modest. A format change gets caught at its source.

### C1. The `tela dev` overlay's input routing has no unit test
- **Claim:** `overlayView.handleInput`/`pointer` (dev_overlay.go:133-203) is covered only by supervisor tests whose negative checks rely on sleeps (dev_overlay_super_test.go:143,183). PointerCancel, a release off × after pressing ×, and a release with buttons still held are never exercised.
- **Kill attempt:** the method is not welded to anything. `platform.Window` is an interface and a zero `remote.Host` works, so no extraction is needed. The sleeps are not the cause of the ROADMAP flake (that is the harness's `waitFrame` deadline).
- **Cost:** S, tests only: `TestOverlayRouting` with a fake Window and a zero Host.
- **Payoff:** deterministic coverage of the routing branches. It does not fix the flake.

### C3. Three `remote.Host` routing tests prove "not delivered" by sleeping, though a deterministic barrier exists
- **Claim:** pair_test.go:439, :499 and :522 (freeze, detach, promotion) sleep 30-50 ms before asserting. input_test.go:59-80 already has a `settle` sentinel barrier that these tests don't use.
- **Kill attempt:** two of the five cited sleeps are not about routing. The proposed sink extraction is M for small gain because `deliver` (host.go:676-700) does its own filtering.
- **Cost:** S, test-only. Use `settle`, or a UI-thread barrier for the frozen case.
- **Payoff:** removes timing sensitivity from the routing tests.

### C20. `core.InteractOutside`/`OutsideOptions` and `IsTopOverlay` have no caller outside core tests
- **Claim:** aria uses only `core.Overlay`. Deleting the plain listener removes `desc.outside`, `outsidePress.plain` and about 8 conditions (overlay.go:111-130,180,212,325-332,359-361; element.go:510,635,708; portal.go:50).
- **Kill attempt:** checked every package for a caller (none) and for a constraint. ADR-096 lists them, so this needs an amendment. `TestInteractOutside` is the only test of the shared press rules (right button, pen, chords), so it must be ported to an Overlay-based test, not deleted.
- **Cost:** M. **Payoff:** small. About 40 production lines and one fewer entry into the press path; no behavior change.

### C17. `svg` and `style` each tokenize `rgb()`/`hsl()`, and `style`'s tokenizer is laxer than CSS
- **Claim:** svg/color.go:61-225 and style/colors.go:158-262 are separate tokenizers. style accepts mixed separators and legacy hsl without `%`, and rejects `none`.
- **Kill attempt:** the HSL formulas are equivalent (that leg died), and gen/values.go is generate-time only and has no hsl. svg already shares `gfx.ParseHex`/`OKLCH`, so a shared core in gfx is allowed.
- **Cost:** S–M. Making style strict rejects class strings that are accepted today (for example `bg-[hsl(120,100,25)]`), which needs a changelog note.
- **Payoff:** low to moderate. One CSS grammar for `bg-[…]` and SVG `fill`.
