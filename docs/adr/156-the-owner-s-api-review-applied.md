# ADR-156: The owner's API review applied

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

The owner's API review applied: D2, D3, D7 and the additions of ADR-154 (phase 10; D1 is ADR-155). **D2 (pointers where zero is valid):** `kit.Select.DefaultValue`, `kit.Tabs.DefaultValue` and `kit.MenuItem.DefaultValue` are `*K` (nil: a Select shows its placeholder, Tabs starts on the first enabled tab and a radio group has nothing chosen; `new(0)` chooses the `int` key 0, which an unset default used to choose); `kit.ColorPicker.DefaultValue`, `kit.ColorInput.DefaultValue` and `aria.ColorStateOptions.DefaultValue` are `*tela.Color` (nil starts at opaque black, documented on each; the "zero Color means black" special case of `useColorParts` is gone, so a transparent black can be a start); `aria.CalendarOptions.DefaultValue` and `aria.RangeCalendarOptions.DefaultValue` are values (`aria.Date`, `aria.DateRange`; the zero value selects nothing), as kit's already were, and kit's `ptrIfSet` is removed. Callers migrated: `kit`, `aria`, `examples/kit`, the godoc examples and the wiki. **D3:** `kit.Dialog.ShowClose` is `HideClose`: the close button shows by default. `AlertDialog` never had one. The Chromium dialog sheet keeps its five cells with the same markup (the two that had no X say `HideClose: true`, shadcn's `showCloseButton={false}`). **D7:** `kit.Card.TitleLevel int`: 0 keeps shadcn's `div`, 1 to 6 draws the title as `h1` to `h6` with the same classes; a level outside 0 to 6 panics in dev mode (`devMode()`) and is clamped otherwise. The examples that gave an `H2` or `H3` to `Title` (settings, i18n, pricing, board, dashboard, kit gallery) pass plain text and `TitleLevel`, with the same aria snapshots; the player's "Up next", whose heading carried `text-lg tracking-tight`, moves them to `TitleClass` with `leading-7` (the `leading-none` of the title recipe would otherwise win over `text-lg`'s line height). **A1:** `tela.MergeProps(props ...tela.Child) tela.Prop` wraps `core.MergeProps` (handlers accumulate, the other props are set by the last one) and takes props, style props (`tela.Width`, the zero one of an `If` that is off), nil and the zero Node; anything else panics in dev mode, naming the argument and the fix, and is ignored otherwise; it uses a new `core.PropOf` (exported inside `internal/core` only). The board's task card no longer wraps its `Card` in a `Div` to carry the drag handlers, the test id and the transform: they are the card's `Props` (the goldens are bit-identical). **A2:** `kit.Table.RowProps func(row T) tela.Child` puts props on each body row's element after `Selected`'s aria-selected. A row is a `display: contents` element, and the engine treats it as the cells it holds: pointer and key handlers on it are called for events on its cells (they bubble), and a ref or `telatest.Bounds` on it reports the cells' bounds together, so no wrapper is needed (test: click, hover, key, name, test id and bounds, before and after a sort); classes on a row still do not paint. `examples/native`'s file list uses it for the row's name (`AriaLabel(entry name)`) and its click, context-menu and double-click handlers instead of each cell's content carrying them. **A3:** `AriaLabel` on `Input` and `Textarea` (`aria-label`), on `ColorPicker` (names the picker as a `group`; an unnamed picker adds no role, as before) and on `ColorInput` (names the default button "label, #code", as `DatePicker` does, and the panel, which it named already; "Color picker" is still the panel's default); `ID` on `ColorPicker` (its hex field, the element a label can point at) and on `ColorInput` (the default trigger button; with a `Trigger` of your own, the button you write takes its own id). Inside a `Field`, `ColorPicker` and `ColorInput` take the field's id, description, invalid state and label like the other controls, so the dev check of a label that points at nothing no longer fires; as in HTML, a press on the label of a `ColorInput` presses its button (it opens the panel). The `examples/kit` color page draws its form row with a `Field`, and the examples that gave `Props: AriaLabel("...")` to an `Input` or a `Textarea` use `AriaLabel`. **Goldens that changed, each looked at:** `examples/board` `board_edit_x1/x2.png` and `examples/dashboard` `dialog_light/dark.png` (the edit-card and new-report dialogs now draw their X, 52 pixels at x1, the intended default); `examples/kit` `kit_dialog_open_light/dark/rounded_light_x1.png` (only the "Share link" demo's description, which no longer names `ShowClose`); `examples/native/testdata/native.aria.yml` (the file list's rows are named by the entry, `row "Projects"`, where their text, with its sizes and dates, was); the rename dialog of `examples/native` sets `HideClose: true` (a native toolkit's dialog has no X), so its six goldens are unchanged. Every `kit` golden and Chromium sheet is bit-identical.

## Rationale

The owner's review settled these before the tag: a zero value that is a real value (a key 0, a transparent color) must be expressible, a Go bool's zero value should be shadcn's behavior, and a card title should be reachable as a heading without giving up shadcn's `div`; the additions remove wrappers and name controls that had no way to be named
