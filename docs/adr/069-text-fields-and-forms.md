# ADR-069: Text fields and forms

- **Date:** 2026-10-13
- **Status:** Accepted

## Decision

Text fields and forms (phase 5, T7; implements §11's text editing; the public API is the owner's decision). **API.** `h.Input`, `h.Textarea`, `h.Form`, `h.Label`; values controlled (`Value(s)` + `OnChange`, React semantics: `OnChange` on every edit, and after each event a controlled field shows `Value` again unless the app changed it), uncontrolled (`DefaultValue`) or `Bind(text, set)` (= `Value` + `OnChange` calling `set.Set`) and `BindValue(*tela.Value[string])` (the field writes the Value at once on the UI thread without rebuilding its owner and follows external `Set`); events `OnBeforeInput(func(tela.InputEvent))` (`InputType` with W3C names, `Data`, `IsComposing`; `PreventDefault` cancels, except during a composition), `OnChange(func(tela.ChangeEvent))` (`Value`, `InputType`, `Data`, `IsComposing`), `OnCompositionStart/Update/End(func(tela.CompositionEvent))` (`Data`), `OnSelect(func(tela.SelectEvent))` (`Start`, `End`: UTF-8 bytes; fired when the user makes or changes a non-empty selection and when code changes it), `OnSubmit(func(tela.SubmitEvent))`, all bubbling; `Type` (Input: text, password, email, search, url, tel, number; Button: submit, button, reset; unknown values panic in dev mode with a suggestion), `Rows`, `Placeholder`, `ReadOnly`, `MaxLength` (UTF-16 code units, user edits only), `AutoComplete` and `SpellCheck` (accepted, ignored), `Name`, `Id`, `For`; `ElementRef.Value`, `Select`, `SetSelectionRange`, `SelectionRange` (no-ops or zero elsewhere); classes `placeholder:*` and `selection:*` (pseudo-element variants: the placeholder's text properties; the selection's text and background colors, inherited by descendants), `caret-*` (inherited), `field-sizing-content|fixed`, variants `read-only:` (CSS: every element but an editable field), `placeholder-shown:`, `invalid:` (type mismatch of email and url values after HTML's syntax, and maxlength exceeded by a user edit; no required/pattern); `telatest.Fill` (Playwright's fill: one insertText edit) and `ExpectValue`. **Behavior** (Chromium 152 is the reference). A field is a leaf box owning an `internal/text/edit` Editor and the text.Layout of its display, rebuilt only when the display or style changes. Preflight defaults (inherited font and color, no border, padding or background, inline-block, `cursor: text`; Textarea `overflow: auto`, `pre-wrap`, `break-word`); intrinsic size ceil(19A + M) for an Input (size=20; A is the primary font's OS/2 average character width, rounded to a whole pixel when that is larger, M its bounding box width rounded) and ceil(20A) plus the classic scrollbar's 15 px for a Textarea, Rows (2) line heights tall; field-sizing-content sizes to the text or placeholder, at least the 1 px caret. An Input centers its line in its content box (its baseline), clips it to the content box and scrolls it horizontally itself to keep the caret visible; a Textarea is a scroll container whose extents come from its text, so a keystroke shapes the field's paragraph and records its layer (a `layerField`) without laying the tree out. Text fields match `focus-visible:` on mouse focus; Tab selects the whole value, a programmatic or label focus keeps the selection (initially the start). Keys: per-platform bindings (Windows and Linux now: Ctrl shortcuts, Ctrl+arrows by word with the Windows or GTK convention, Shift+Delete, Ctrl/Shift+Insert, Ctrl+Y and Ctrl+Shift+Z; Up/Down/PageUp/PageDown in an Input go to its ends on Linux and do nothing on Windows; macOS's Command/Option table for Cocoa); text is typed when neither Ctrl nor Meta is held; nothing runs during a composition or for `KeyProcess`. Pointer: caret at the press, Shift extends, double click a word, triple click the paragraph (the whole Input), drag by the press's unit with autoscroll past the edges (the caret revealed every frame). Caret 1 px wide, the line box tall, `caret-color`, blinking 530 ms on and off from the last input, steady after 10 s idle (no timer: 0% CPU), hidden with a non-empty selection, in an inactive window and in read-only fields. Selection colors measured in headless Chromium: rgb(51, 103, 209) with white text in an active window; Chromium's LayoutTheme defaults rgb(200, 200, 200) and rgb(50, 50, 50) in an inactive one (not measured); not painted in an unfocused field; `selection:` classes override them. IME: the Host sets the focused field's `TextInputState` after every event and frame (caret or preedit rect in window coordinates, purpose from `Type`, Multiline for a Textarea, surrounding text except for passwords; nil for read-only fields and no field; nil then the new state when the field changes); `IMEEvent` maps to DeleteSurrounding, the commit (CommitComposition, or typing without a composition) and SetPreedit or CancelComposition, firing compositionstart, then per update beforeinput (insertCompositionText), compositionupdate and OnChange with `IsComposing`, then compositionend (Chromium's order); a blur, the session's end or a click finishes the composition keeping its text (compositionend only), and a click or a programmatic value resets the IME. The preedit is underlined (2 px under the IME's highlighted range). Clipboard through `platform.Clipboard`; a paste applies when the text arrives as one `insertFromPaste` edit, dropped if the field lost the focus. Forms: every click runs the activation behavior of the Button or Label on its path; a Button in a Form submits (default type) or resets (uncontrolled fields back to their DefaultValue); Enter in an Input clicks the form's first submit button or, without one, submits when the field is the form's only Input (HTML's implicit submission); no interactive validation. Labels focus and click their control (`For(id)` or the labelable element inside) and name it. Semantics: textbox (searchbox for `search`) with the value (masked for passwords), multiline and read-only states and setValue; name from AriaLabelledBy, AriaLabel, labels, then placeholder; a Form is a form landmark only with a name.

## Rationale

Owner's API (2026-10-13); browser behavior is what users and LLMs expect, and Chromium is measured: 17 gallery cells agree within 0.016 px at scale 1 (0.5 px at scale 2, where Blink rounds font metrics in device pixels, ADR-048) and within 1.6 mean levels per pixel. A keystroke costs 0.10 ms in an uncontrolled field and 0.85 ms with Bind over a 10k-element tree (frame and damage raster at scale 2)
