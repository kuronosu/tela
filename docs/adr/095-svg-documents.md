# ADR-095: SVG documents

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

SVG documents (phase 8, T1; scope chosen by the owner, decision E1). **Package** `internal/svg`, between `gfx` and `text` in §5 (it imports only `gfx`, `fmath` and the standard library): `Parse([]byte) (*Doc, error)` decodes with `encoding/xml` (internal-subset entities expanded, up to 64 of at most 128 bytes) and normalizes once into an immutable render tree of groups and shapes: styles cascaded (presentation attributes, then the `style` attribute; invalid values dropped; `inherit`; CSS inheritance), lengths resolved (px, unitless, %, em, ex as em/2, rem from the root svg element's font size, mm/cm/in/pt/pc at 96 dpi), shapes and path data turned into `gfx.Path`s (the full path grammar; arcs, circles, ellipses and rounded corners as cubics of at most 45°, start points and directions of SVG 2 for dashes; errors keep the segments before them), `use` instantiated in its context (x/y, `href` over `xlink:href`; references to ancestors and cycles draw nothing), `symbol` and nested `svg` as clipped viewports, and gradients, clip paths and masks resolved for each element's bounding box. Hostile input is bounded: 100,000 source elements, nesting 256, 200,000 render nodes after `use` expansion, 4 Mi path points over all instances, numbers beyond ±1e9 invalid, chains of 32 references; beyond them `Parse` returns `ErrTooComplex`, and it never panics (fuzz test). `Doc` gives `Intrinsic()` (width, height and ratio), `Size()` (falling back to the viewBox, then CSS's 300×150), `Transform(dst)` (viewBox and preserveAspectRatio; without a viewBox the intrinsic size is used as one, like Chromium), `Clips()` (the root's overflow is not visible: browsers always clip an SVG shown by `<img>`), `UsesCurrentColor()`, `Draw(b, dst, Options)` (a viewport clip, the transform and the tree), and `Record(Options)` with `DrawRecorded` for callers that cache a list. **Options** are per draw and need no reparse: `CurrentColor` (the context's color, used unless the root sets `color`) and `Root` (author CSS on the root element, as classes on the element showing it will give: `Fill`, `Stroke` as none, a color or currentColor, `StrokeWidth` in user units, `Color`), which beat the root's presentation and style attributes and are inherited by every element that does not set the property: each computed style records which inherited properties come from the root, and the drawer substitutes them; mask contents that depend on them are recorded again. A shape with one solid paint folds its `opacity` into the color; anything else uses a layer; the order is transform, viewport clip, clip-path, then mask and opacity in one layer. **Paints:** gradients interpolate in sRGB; the gradient space (bounding box, then `gradientTransform`) is folded into the paint when `gfx` can express it (always for linear gradients, for radial ones under similarities or, without focal point, axis-aligned scales); otherwise fills are drawn inside the gradient space with the path mapped into it, and strokes paint the gradient through an alpha mask of the stroke. `fx`/`fy`/`fr` give `gfx.FocalGradient` (SVG 2 cones, as Chromium; no SVG 1.1 focal clamping). **gfx** gains `SpreadMode` (`SpreadPad`, the zero value, `SpreadReflect`, `SpreadRepeat`) on `LinearGradient`, `RadialGradient` and `FocalGradient`: the rasterizer folds the gradient parameter with exact or correctly rounded operations before the ramp lookup; pad keeps its code path, and every existing golden is bit-identical. **Chromium where SVG leaves room:** stops interpolate unpremultiplied (intermediate stops keep the premultiplied ramp within half a level of it where alpha and color both change); references to missing clip paths or masks are ignored; a gradient with no stops paints none, with one its color; an objectBoundingBox gradient on a shape without width or height uses the paint's fallback or none; `stroke-linejoin` `miter-clip` and `arcs` are dropped (the inherited join applies); a clip path with one child is a path clip, with several (or with children's own clip paths) an alpha mask layer. **Not supported** (skipped like unknown content): text, images, filters, patterns (their fallback paints), markers, `switch`, `foreignObject`, `<style>` sheets, animation, scripts, external references, `transform` on the root svg, CSS geometry properties and `transform` in `style`, `paint-order`, `vector-effect`, `shape-rendering` (always anti-aliased), the newer color functions; single-stop gradients with a root currentColor use the default root color

## Rationale

Icons and SVG images (T4: `h.Icon`, `Img` with SVG) need a renderer that is cheap per draw and follows the classes on the element, without a parse per color or size. Measured against Chromium 154 (`TestChromiumSVG`, 36 cells: 32 SVG files shown with `<img>` and 4 inline `<svg>` cells styled by page CSS, scales 1 and 2): mean difference per channel 0.00–0.60 for 29 cells and up to 1.01 for thin strokes at scale 1 (dash ends on circles, anti-aliasing); away from anti-aliased edges flat areas and gradient interiors (linear, radial, focal, cone, reflect, repeat, unpremultiplied stops) agree within 2 levels, and a viewport-clipped circle corner within 6; single edge pixels differ by up to 203 levels (Skia's coverage of curves and thin strokes, and its dash positions measured on its own flattening). Cost on one core (Core Ultra 5 125H): a Lucide-style 24×24 stroke icon parses in 22 µs (133 allocations), draws in 2.8 µs (35 allocations, all inside `gfx.Builder`: command boxing and path copies; `Draw` itself allocates nothing), or 1.4 µs (23) placing a recorded list, and rasterizes at 48×48 device px in 55 µs; a 13-shape illustration with gradients, a clip path, a mask and layers parses in 115 µs, draws in 7.8 µs (87 allocations) and rasterizes at 400×400 in 4.3 ms. Fusion safety is checked by a digest of the display lists of every cell, random arcs and transforms (unchanged with GOAMD64=v3, which fuses like arm64)
