# ADR-114: The `tela dev` child runtime and `App.DevState`

- **Date:** 2026-10-22
- **Status:** Accepted

## Decision

The `tela dev` child runtime and `App.DevState` (phase 9, T3; implements ADR-111 on ADR-112, ADR-113 and the kinds of `internal/devloop`; amends §17). **API (the owner's, G4a).** `tela.App` gains `DevState DevState`, `type DevState struct{ Save func() ([]byte, error); Restore func([]byte) error }`: state outside the component tree (package variables, controllers, a connection's settings). The field is always present (its type information is the only difference in release binaries); it is ignored outside `tela dev`, and `telatest.FromApp`, `tela snapshot` and `tela inspect` ignore it. `Save` runs on the UI thread in the old process when it captures its state; `Restore` runs before the tree mounts in the new one (core registers both with `RegisterDevState`, so they travel in the same snapshot as the hook state); an error or a panic is a warning and that state starts fresh; `Restore` is not called when `Save` returned no bytes, nor on a first start, after `R` or with `--no-state`. The recommended pattern keeps the app's own save/restore code (and its `encoding/json` or `encoding/gob`) out of release builds: `var devState tela.DevState` in a normal file, used as `App{..., DevState: devState}`, assigned in `init` of a `//go:build teladev` file (`ExampleDevState`; `cmd/tela/testdata/devapp`). Implementation: `core.Options` carries `DevSave` and `DevRestore`, which `App.options` fills. **Child runtime** (`internal/core/devrun.go`, `//go:build teladev`; `devrun_off.go` has no-op stubs behind `devStateEnabled`, a constant, so the compiler removes the calls). `core.Run` asks `devBackend` for the backend: with `TELA_DEVLOOP=1` it is `remote.DialEnv()` (whatever `TELA_BACKEND` says), otherwise nil and `Run` uses `auto.New()`, so a teladev binary started by hand behaves as a normal build. Under `tela dev` and without `TELA_DEVLOOP_NO_STATE=1`, before mounting it registers `App.DevState`, sends `tela.dev.state.load` (a request, 15 s at most; an error starts fresh with a line on stderr) and gives the reply to `SetDevSeed`. `devRun` registers the handlers and runs the loop: `tela.dev.quit` calls `Backend.Quit` (the loop ends, `Run` unmounts and returns nil, exit 0, nothing saved) and `tela.dev.state.save` applies the queued updates and returns `Tree.CaptureDevState()` (on the UI thread, between events; not registered with `--no-state`). **State report.** When the process was seeded, `devAfterFrame` (called after each `FrameEvent`) waits until core drops the snapshot (the first 4 frames, or earlier when everything saved was found; it asks for the frames an idle app does not request, at most 8) and sends `tela.dev.state.report` once: kept = slots restored + text fields + scroll offsets + the focus, reset = components that remounted because their hooks changed (the child also prints each on stderr, `tela dev: state reset: Sidebar: hook 2, UseState[string], is new`). The report therefore usually arrives after the promotion, so the supervisor holds the line of a finished swap (its time is taken at the promotion) for at most 300 ms (`supervisorConfig.reportWait`) until the child's report arrives, and prints `reloaded in 700ms (state: 6 kept, 0 reset)` once, or `(state kept)` when none came. **Panics.** `Run` defers `devRecover` (teladev): a panic of the UI thread (a handler, a build, an effect, a handler of the control channel) in a tela dev child is printed on stderr as Go prints it (`panic: v`, a blank line, the stack of the panicking goroutine), sent as `tela.dev.panic` with `devloop.PanicPayload` (waiting up to 1 s for the write), and the process exits with status 2; outside tela dev nothing is recovered. A panic in another goroutine cannot be recovered: the runtime prints it and exits with status 2, and a fatal error (a deadlock, a concurrent map write) the same, so the supervisor keeps the end of each child's standard error (`tailWriter`, 32 KB; `cmd/tela/dev_tail.go`) and, for an unexpected exit whose last `panic: ` or `fatal error: ` line is there, shows the problem as a panic with that text instead of the bare `the app exited with status 2`. **Assets.** `RegisterAssets` calls a teladev hook with each file system; an `os.DirFS` (an unexported string type of package `os`, read by reflection, as is a `fs.Sub` of one) gives its absolute directory, and the full list goes to the supervisor with `tela.dev.assets` when it grows (and at connection, for those registered in `init`); other file systems (`embed.FS`) are ignored, since the embedded files already rebuild through `go list`. **Locale.** `i18n/devstate.go` (teladev) registers the explicit locale of `SetLocale` with `core.RegisterDevState` (i18n is above core, which it already imports): it is saved as its tag, restored before the tree mounts, and a locale that follows the system is not saved, so a `SetLocale` call that the edit adds or changes in the code wins until the user picks another locale at run time. **Focus fix (core).** The remote host sends the window's focus right after the configure event, before the child's first frame, so `SetWindowFocused(true)` ran its focus fix-up while the focus restored by ADR-113 had no computed style yet and blurred it (the caret and `OnFocus` were lost on every reload, found by the end-to-end test); `fixFocus` now leaves a mounted element with no computed style alone, and the frame's fix-up decides. `Tree.devSeedOpen` is the new accessor the report uses. **Tests.** `TestDevEndToEnd` (`cmd/tela/dev_e2e_test.go`, skipped under `-short`) runs the real supervisor (real `go build -tags teladev`, watcher and children) on the headless backend with `cmd/tela/testdata/devapp` copied into a module outside the repository: it clicks, types and scrolls through the host, edits a class and a text, adds a hook to a component and breaks and fixes the build, and checks that the counter, the package variable (`DevState`), the typed text, the focus (a later key goes to the field and `OnFocus` fires) and the scroll offset are kept, that the component whose hooks changed resets while the others keep state, that a slot holding a func resets with its warning while its sibling keeps, that the old build keeps working under a compile error, and that fixing it clears the problem and keeps the state; it takes about 5 s with a warm build cache. Saving to swapped measured 0.67 to 0.71 s there (100 ms debounce, 0.5 s build, 0.5 ms state save, 70 to 90 ms from start to first frame, 0.1 ms promotion). `TestReleaseBuildHasNoDevLoop` (`cmd/tela/dev_release_test.go`) builds `examples/counter` without the tag and checks that `go list -deps` has none of `internal/devloop`, `internal/platform/remote` and `encoding/gob` and `go tool nm` none of their symbols nor `CaptureDevState`, `RegisterDevState`, `SetDevSeed` or the child runtime's functions, and that every one of them is there with `-tags teladev`; a `-trimpath` build of `examples/dashboard` against the commit before this change has the same symbols except `App.options`, `Run`, `Main` (they copy the larger `App`), `fixFocus` (the fix) and `RegisterAssets` (no `defer`).

## Rationale

The supervisor and the app agree on the kinds of ADR-115 without sharing code beyond the standard-library `internal/devloop`; keeping the runtime in core's teladev files lets `Run` choose the backend and the loop without any public hook, and the constant-guarded stubs keep release builds as they were. The state report is sent when core says the restore is complete because anything earlier would count a scroll offset or a virtual list that is not restored yet; holding only the terminal line (not the swap) for it costs no reload time. Recovering in `Run` is the one place that sees every UI-thread panic, and exiting with status 2 as Go does lets the supervisor treat a recovered and an unrecovered panic alike. Reading the directory of an `os.DirFS` by reflection is the only way to know what the app reads at run time without a new public API.
