# ADR-138: `kit` Select, Tabs and Toaster

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

`kit` Select, Tabs and Toaster (phase 10, T5b; builds on ADR-129 and ADR-130; every public shape is listed for the owner's review). **Select[K]** (`aria.UseSelect`): `Items []SelectItem[K]{Value, Label, Icon, Disabled, Group}`, `Value *K`/`DefaultValue`/`OnValueChange func(K)`, `Open *bool`/`DefaultOpen`/`OnOpenChange`, `Placeholder`, `Size` (Default 36 px, Sm 32 px), `Disabled`, `Invalid`, `ID`, `AriaLabel`, `Icon` and `CheckIcon` (slots; the Lucide chevron-down and check are built in as unexported literals, K7), `Class`/`ContentClass`/`ItemClass`/`LabelClass`, `Props` (the trigger's); the root element is the trigger (an `h.Button`, `type=button`), the list is a `Portal` + `Presence` popover (`starting:` and `Exit` fade and zoom with a slide on the side it opens on). Consecutive items with the same `Group` are drawn under that label (`aria` sections: a `group` named by it) and a separator is drawn where the group changes, which is shadcn's `SelectGroup`, `SelectLabel` and `SelectSeparator` without three more types. A value no item has chooses nothing, so the zero `K` shows the placeholder (a select whose keys include the zero value has it chosen: documented). Inside a `Field` it takes the field's id, description and invalid state, and the field's label text is its `AriaLabel` (`fieldInfo` gained `label`), so its name is `value + label` as React Aria's. **Tabs[K]** (`aria.UseTabs`): `Tabs []Tab[K]{Value, Label, Icon, Disabled, Content}`, the value rule, `Orientation`, `Variant` (Default, and `kit.TabsLine`, a component constant since ADR-130 limits the shared `Variant` ones), `ManualActivation`, `AriaLabel`; only the selected panel is built. **Toaster / UseToast:** `kit.Toaster{Position, Duration, VisibleToasts, Expand, CloseButton, Inline, Icons, CloseIcon, Children}` once around the app; `kit.UseToast() ToastHandle` (a comparable struct holding the store pointer) with `Show`, `Success`, `Error`, `Info`, `Warning`, `Loading` (all return a `ToastID`), `Dismiss(id)` and `DismissAll`, options `ToastDescription`, `ToastAction(label, onClick)`, `ToastDuration` (`ToastForever` < 0), `ToastReplace(id)` (sonner's `id`: update in place and restart the timer), `ToastOnDismiss` and `ToastOnAutoClose`; six `ToastPosition`s (bottom right by default). The state is a mutex-guarded store in the Toaster (`UseOnce`) that every method changes from any goroutine and then asks the Toaster to rebuild with a `tela.Setter` bump, which routes through the tree like `tela.Post`; callbacks run on the UI thread through `tela.Post`; the context value is the stable store pointer, so the app below does not rebuild when a toast comes or goes; there is no global. **Look:** sonner's default stylesheet as shadcn's wrapper leaves it (356 px, 14 px gap, 24 px offset, 16 px padding, 13 px text, the popover colors, the 4 px 12 px shadow, 400 ms transitions), the newest toast in front and the older ones behind it at `translateY(14 n px) scale(1 - 0.05 n)` with their content hidden and the front's height, three shown, fanned out by their measured heights while the pointer is over the viewport (or with `Expand`), entering and leaving by `starting:` and `Exit` classes from the edge; each toast measures its body with `tela.UseSize` and tells the store, the cards take explicit heights so they transition. A toast is `status` (an `alert` for errors) inside a `region` named Notifications. **Timer:** the public API has `UseInterval` and no one-shot timer nor clock read, so a toast counts a 100 ms `UseInterval` in a ref (paused with a period of 0 while the pointer is over the stack: sonner's remaining-time rule); ticks change no state, so an idle waiting toast draws no frame (tested), and `Advance` runs it deterministically. **Deviations from shadcn and sonner:** the select list is shadcn's `position="popper"` (below the trigger, centered, at least as wide as it, 4 px away; shadcn's default `item-aligned` over the trigger is not ported) and has no scroll buttons (it scrolls inside a height limited to the room, `aria.Size`); the list's `relative` is dropped (its props fix it to the window); tab triggers are `div`s with the `tab` role (the collection hooks forbid buttons), the line variant's `after:` underline is a real `span`, `group-data-[...]/tabs:` classes are Go conditions per orientation and variant and `data-[state=active]:` is `aria-selected:`; `flex-1` is `flex-auto` in the list viewport (an engine difference, below); toasts have no swipe to dismiss, promise helper, rich colors, mobile layout, RTL or hotkey, and use the app's font where sonner uses the system's; `list-none` and `ol`/`li` are plain boxes; the close button is a `button` with sonner's gray colors written as arbitrary values. **Engine difference found:** in Tela a `flex-1` (`flex: 1 1 0%`) child of a column flex container with auto height gets its padding only (8 px for `p-1`), where Chromium sizes it to its content (88 px in the check made; the same container with `flex-auto` agrees). **Conformance** (Chromium pages with Tailwind 4.3.3, light and dark, scales 1 and 2): tabs, 9 cells (default, selected, line, icons, disabled, vertical, no panel) with box edges within 0.023 px and a mean pixel difference around a cell of 0.59 to 1.48; select, 9 cells (placeholder, value, small, disabled, invalid, icon, three open lists with groups, icons and a disabled item) edges 0.000 px, means 0.33 to 2.77 (the worst is the dark copy of the one list that has the window's focus, whose chosen item has no highlight where the page's has); toast, 6 cells (single, collapsed stack of four, fanned out, the icon kinds, top center, close buttons) edges 0.000 px, means 0.25 to 2.25, the Chromium side being the DOM the real sonner 2.0.7 renders in shadcn's wrapper (`kit/testdata/sonner/`, with the script that captured it). Idle: an open select and a waiting toast draw no frames.

## Rationale

The owner's K6 asks for a handle safe from any goroutine with no global, which a store behind a context and a setter bump gives without making every component below rebuild; the select and tabs are the aria hooks of ADR-104 and ADR-105 with shadcn's look. Rendering the real sonner as the oracle, not a hand-written copy of its markup, keeps the stack's rule (the `--scale` that is `1 - 0.05 n` only by CSS token substitution, the offsets by measured heights) honest, and the same cells run through telatest's pipeline and Chromium
