# ADR-098: Images, icons and masks

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Images, icons and masks (phase 8, T4; every public shape is the owner's: decisions E3, E4 and the paint, tint, mask and object-fit utilities; amends §10, §13, ADR-079, ADR-089 and ADR-095). **Sources.** `h.Src(image.Image)` stays; `h.SrcPath(path)` resolves like `bg-[url(…)]` (ADR-079: the `tela.Assets` file systems in order, the same path rules, cache and report), `h.SrcBytes(data)` and `h.SrcFS(fsys, path)`. The format is detected by content: PNG, JPEG, GIF (first frame), WebP, and SVG (data that starts with `<` after a BOM and white space), which `internal/svg` parses and Tela draws as vectors; the same loader serves `bg-[url()]` and `mask-[url()]`, so SVG backgrounds and masks work too (drawn with currentColor black). Decoding happens once per content when the element mounts or its source changes, never in paint: by cleaned path (the ADR-079 cache), by SHA-256 of the bytes, by (file system, path) when the file system is comparable, and icons by their text, in a 256 MiB least-recently-used cache (`core.mediaCache`; failures are cached too); a box keeps its decoded source while the node gives the same one (same path, same slice pointer and length, same file system and path, same text), so a rebuild costs a comparison. A missing or undecodable source paints nothing and is reported once (`reportOnce`, "tela: Img source: …", "tela: Icon: the SVG cannot be parsed: …"). **Icon.** `tela.Icon{SVG string}` is comparable static data; `tela.ParseSVG(data) (Icon, error)` parses through the same cache, `tela.MustSVG` panics on error; `h.Icon(icon, props...)` is a primitive of the new `style.KindSVG` (kind name `svg`): Preflight's `display: block; vertical-align: middle`, and 1em × 1em as kind defaults (the element's font size, below every class, like the width and height attributes of an inline `<svg>`), so `size-*`, `w-*`, `h-*` or a style override each axis. Icons are `aria-hidden` (an implicit `AriaHidden(true)`, so `aria-hidden:` matches, as lucide-react sets the attribute) unless `AriaLabel` or `AriaLabelledBy` is given; their role is then `img`. `Img` and `Icon` are replaced elements (`Kind.IsReplaced`): image mode, atomic inlines with display inline, `layout.Style.Replaced`. **Drawing SVG.** The content box shows the document per object-fit; `svg.Doc.DrawRecorded` places a list recorded per `svg.Options` and kept by the box (`boxMedia`), so a frame that does not change the options records nothing. Options: currentColor is the element's text color (with a `TextColorFn` that reaches it, ADR-082), also the root's `color` (`Root.HasColor`) when the element sets its own text color, so an inherited color loses to the document's `color` attribute and the element's own `text-*` wins, as CSS on an inline `<svg>`; `Fill`, `Stroke` and `StrokeWidth` come from the element's style. **SVG paint utilities** (Tailwind v4: `fill-*`, `stroke-*` colors with palette, tokens, `/NN`, `current`, `none`, arbitrary colors; `stroke-<integer>`, `stroke-[1.5]`, `stroke-[2px]`, `stroke-[length:…]`; percentages rejected) set `ComputedStyle.Fill`, `Stroke`, `StrokeWidth`, which are inherited (`fill-current` keeps the keyword, `style.SVGPaintCurrent`, resolved with the color of the element that draws). They are root overrides of `Icon` and SVG `Img` documents, whether set on the element or inherited from an ancestor: the owner's decision, so that a class on a `Button` reaches its icons as shadcn's `[&_svg]:…` selectors do; CSS would let the root's presentation attributes win over an inherited value. They apply to SVG `Img` too (in browsers an `<img>`'s document ignores the page's CSS), and so does currentColor = the Img's text color. They are not transitioned. ADR-089's list loses `fill-` and `stroke-`. **object-fit and object-position** (`object-contain`, `cover`, `fill`, `none`, `scale-down`, the nine keyword positions, `object-[…]`) place the image in the content box with CSS Images 3's concrete object size (natural size and ratio; an SVG's `Intrinsic`, else its `Size`), clipped to the content box (with its rounded corners) when it overflows; an SVG is then drawn into that rectangle by its viewBox and preserveAspectRatio, as Chromium does for `<img>`. Fix: an `Img` with both sizes given no longer takes its natural ratio as its CSS aspect-ratio (it was 120×80 for `w-30 h-10` with a 3×2 image; it is 120×40 and fitted, like a browser). A raster image is drawn from the mip level just larger than its device size, like background tiles (ADR-079). **Tint.** `h.Tint(c tela.Color)` on an `Img`: the image (raster or SVG, after object-fit) is the alpha mask of a layer filled with `c` (pixel = `c` × image alpha). **Masks.** `ComputedStyle.Mask` (`style.Mask`: layers as `BackgroundLayer`s, mode, composite, clip, no-clip) makes a stacking context; `pushEffects` pushes `PushMaskLayer` (ADR-074) with the opacity, blend mode and filters (CSS: filter, clip, mask, opacity), whose alpha list is built by `cssMask`: each layer painted by the background painter (size, position, repeat, origin box; clipped to the mask clip box with its radii, or to the ink bounds for `mask-no-clip`), a luminance layer turned into white covered by its luminance, and the layers combined from the bottom up: add as source-over, intersect as nested mask layers, subtract as a mask by the luminance of white with the lower layers painted black (`Brightness(0)`), exclude as both differences added with plus-lighter; opaque gradient layers are skipped under intersect. An image that fails to load is a transparent layer (CSS), so the element is hidden. Utilities (Tailwind 4.3.3, CSS read from the CLI's output): `mask-[url()]`, `mask-[<gradient>]` and lists, `mask-none`, `mask-contain/cover/auto`, `mask-size-[…]`, `mask-[size:…]`, `mask-center` … `mask-bottom-right`, `mask-position-[…]`, `mask-repeat*`, `mask-no-repeat`, `mask-origin-*`, `mask-clip-*`, `mask-no-clip`, `mask-alpha/luminance/match`, `mask-add/subtract/intersect/exclude`, `mask-type-*` (accepted, no effect on elements as in browsers); gradient masks emulate Tailwind's variables: any of them sets `mask-image` to the linear, radial and conic variables intersected, each opaque by default; the linear one is the four edges (`mask-t/r/b/l/x/y-from/to-*`: `linear-gradient(to top, <from> <pos>, <to> <pos>)` per edge) or the gradient of `mask-linear-<angle>`/`-mask-linear-<angle>`/`mask-linear-[…]` and `mask-linear-from/to-*` (default angle 0deg, so bottom to top), the radial one `mask-radial-from/to-*` with `mask-circle`/`mask-ellipse`, `mask-radial-closest-side` …, `mask-radial-[size]` and `mask-radial-at-*`, the conic one `mask-conic-<angle>` and `mask-conic-from/to-*`; stops take percentages, spacing numbers, lengths (angles for conic) and colors (palette, tokens bound per scheme, `/NN`), defaulting to black 0% and transparent 100%; where two classes set one variable the one Tailwind emits later wins, whatever the class order (edges < angle < stops; size < stops; replaced by ADR-103: the last class in the class order wins); a family that is invalid in CSS (an angle or a size without stops, a circle with two or percentage radii, an ellipse with one, a length on a conic stop) makes the whole `mask-image` invalid at computed-value time: no mask, as in Chromium. Mask gradients interpolate in sRGB (CSS's default; Tailwind's masks add no `in oklab`). **`internal/svg` (owner's extension of E1):** `<style>` sheets (no `type` or `text/css`; CDATA, comments; at-rules skipped with their blocks) with type, `*`, `.class` and `#id` selectors and their compounds in selector lists; a list with a syntax error drops its rule, selectors with combinators, attributes or pseudo-classes are skipped; declarations of the supported properties only; cascade: presentation attributes, then the matching rules by specificity and source order, then the style attribute, then the important declarations of the rules and of the style attribute; instances of `use` match as their source elements. Hostile sheets are bounded (1 MiB of text, 4096 rules, 4 Mi selector tests and copied declarations, else `ErrTooComplex`; rules are indexed by id, class and type). `<switch>` renders its first direct child, title, desc and metadata aside, whose conditions pass as usvg evaluates them (`requiredExtensions` always fails, `requiredFeatures` passes only SVG 1.1 static feature strings, `systemLanguage` matches `en` and `en-*`); the chosen child may render nothing. Patterns stay unsupported

## Rationale

The owner's API and decisions. Decoding at mount keeps paint free of I/O and parsing; per-box recorded lists make recolors and resizes cheap; the gradient-mask emulation reproduces Tailwind's cascade of custom properties without custom properties. Measured against Chromium 154 with Tailwind 4.3.3 (`internal/core` `TestChromiumMedia`, 58 cells at scales 1 and 2): SVG `<img>` cells (natural size, height only, fill with letterboxing, contain, cover, none, scale-down, viewBox only, `preserveAspectRatio="none"`, rounded) mean 0.06–0.56 levels per channel; raster cells 0.00–1.12 (downscaled photos: Chromium's filter against the mip level); tinted PNG and SVG 0.09–0.20; icons in buttons and with own or inherited `fill`/`stroke`/`stroke-[1.5]` 0.28–1.09, icons in text 1.7–2.1 at x1 and 4.6–8.3 at x2 (glyph anti-aliasing, and the line half a device pixel lower at x2, ADR-048); image masks 0.00–0.35, but 1.0–4.3 for a 64 px mask tiled at 20 px (`space`, `round`: Chromium's downscaling filter); every gradient-mask cell (edges, two edges, linear with angles, colors and spacing stops, radial with shape, size and position, conic, composites, opacity) 0.000–0.37; box edges within 0.024 px at x1 and 0.503 px at x2 (inline icons). `internal/svg` `TestChromiumSVG/chromium-sheets` (a second page, so the ADR-095 gallery and golden are unchanged): selectors and cascade 0.09/0.05, sheets with CDATA, at-rules, ignored types and `use` 0.44/0.19, switch 0.08/0.07, maxima 37–63 on anti-aliased edges. Costs (Core Ultra 5 125H, one core): placing an icon's recorded list 1.7 µs (25 allocations, in `gfx.Builder`); a frame that recolors a 100-row list with an icon per row 4.3 ms against 3.95 ms for the same list without icons (about 3.5 µs per icon: restyle, a new record, paint; no parse); rasterizing that list at scale 2, 13.6 ms; a frame that resizes an SVG `Img` 19 µs (no parse, no record). Known differences: an SVG with only a viewBox has the viewBox size as natural size (`svg.Doc.Size`), where Chromium makes it as wide as the space available; mask tiles and downscaled images use mip levels and bilinear sampling, not Chromium's filters; fill and stroke are not animated by `transition-colors`. Existing goldens are bit-identical
