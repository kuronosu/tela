# ADR-088: Source-breaking API decisions

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Source-breaking API decisions (phase 7, T3; the owner's decisions D1, D3, D5, D6 and D10; amends §6, §7, §12, §19, ADR-047, ADR-051, ADR-059, ADR-080 and ADR-085). **Struct components (D1).** `tela.Component` is `interface{ Build() Node }` (an alias of `core.Comp`: `core.Component` is the constructor behind `tela.C`); `tela.Child` is a distinct interface with the same method set, no longer sealed: `Node.Build` returns the node, `Prop.Build` a prop node that applies where props go and panics when rendered; `Div(42)` and `Div("x")` still do not compile. Every other Component given to an element, `Fragment`, a Provider, `Presence` or `Portal` becomes a component node with its own hook state; children are an ordinary field (`Children tela.Component`, several via `Fragment`). Identity: the dynamic type (`compDesc.rtype`; `typ` is the Build method's code pointer) and the key. It skips like `CP` when `componentEqual(old, new)` and nothing it read changed: per type (cached), a non-comparable type always changes, a comparable one without interfaces inside uses `==`, one with interfaces is compared field by field with reflect (unexported fields read without `Interface`, blank fields skipped, NaN unequal, an interface whose dynamic types differ or are not comparable counts as changed), so it never panics; a `Node` field compares by identity. Dev mode, when a struct component node is mounted or updated: a pointer type panics (with the value- or pointer-receiver fix), and so does a Prop (or a Prop's node) in an exported field of type Component or a slice/array of them (`reflect.VisibleFields` through exported paths, cached per type; "Card.Children holds a Prop (Class), not a component"); fields of type Child take props and are not checked. Hook boundary (ADR-085): the owner is the normalized name of the Build method, plus the Build methods of embedded types it is promoted from; a hook reached through `Card{}.Build()` called directly panics with "pass Card{...} as a child instead of calling Build" (`Fragment(Card{...})` where a Node is expected), and outside any build says to pass the value. Inspect and messages name a struct component by its full type name. `h.If` returns the zero value of its type parameter, which for a struct component renders, so in dev mode it panics on a type other than Node, Prop or an interface, with the fix `If(cond, tela.Component(Spinner{}))` (decided without the owner; a signature change is the owner's). `telatest.Mount`, `Render`, `AriaSnapshot` and `LayoutJSON` take a `tela.Component` (`core.NodeOf`; a Prop root is an error). `C`, `CP` and `Memo` stay. **Keys (D3).** `h.Key[K comparable](k K) Prop` and `tela.WithKey[K comparable](c Component, k K) Node` (which also makes a Node of a struct component): a slice, map or func key does not compile; an interface holding nil or a non-comparable value still panics. **Renames (D6)**, the old names kept with `Deprecated:` until phase 8: `h.Id` → `h.ID`, `tela.UseId` → `tela.UseID`, `tela.Key` → `tela.KeyName`, `tela.Code` → `tela.KeyCode` (the keys generator writes the new types; the constants keep their names). The wiki generator gives a deprecated function whose anchor equals another's but for case a "(deprecated)" heading. Collisions of `tela` and `h` left once those go: `Ref` and `Value` (reported, not renamed). **`tela.Once` (D5).** A variable of an unexported comparable type (`String()` "tela.Once"), the "mount only" dependency of every deps-taking hook; `UseMount` uses it; the nil-deps warnings suggest it (or `UseMount`, `UseOnce`); `UseUpdateEffect(f, Once)` warns that it never runs; `nil` keeps working, deprecated. **Animation (D10).** `UseSpring[T Animatable](target T, opts...)` and `UseTween` infer T from the target; `tela.Initial[T Animatable](v T) AnimationOption` is the first build's value (default: the target, so nothing moves); later builds ignore it; AnimationOption is not generic, so a type mismatch (type names compared, like `Velocity`) panics in dev mode and is ignored otherwise, as do `Initial` on `Animate` and inside `Spring`. **Left open:** a zero-size `tela.Base` embed giving Component an unexported marker, which would make a Prop in a Component field a compile error; Component and Child being distinct types and core never assuming Component has only Build keep it addable (it would require struct components to embed it).

## Rationale

The owner's decisions. A distinct Child lets a field say whether it takes props and keeps Base possible; the core name avoids renaming ~300 `Component(...)` calls while two other phase-7 tasks edit `core`. Reflect-based equality instead of recovering from `==` keeps panics out of reconciliation and debuggers, at the cost of a cached type lookup per comparison. Checking at reconcile follows the tree's dev mode (`telatest.NoDev`)
