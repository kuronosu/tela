# ADR-081: Layout animations

- **Date:** 2026-10-18
- **Status:** Accepted

## Decision

Layout animations (phase 6, T9; implements §12 "Layout animations"; the public API and the default timing are the owner's decisions; refines ADR-076 for layers and ADR-070 for bounds). **API.** `h.AnimateLayout()` (Motion's `layout`) and `h.LayoutID(id string)` (Motion's `layoutId`), props of any primitive, without options. **FLIP.** Layout runs normally; the paint phase compares each such box's border box with the previous one and draws it through a flip, an axis-aligned scale and translation that maps the new box to the visual box of the frame, folded into its paint-phase transform before its own transform (Motion's order: the flip's scale multiplies the box's scale inside its rotation). Everything that follows `Box.pcs` follows the flip: painting, hit-testing, `ElementRef.Bounds`/`UseBounds` and semantics bounds see the drawn box (the browser's rule for transforms, `getBoundingClientRect`); focus scroll-into-view keeps ignoring transforms, so it scrolls to the final box. A box with a flip is a stacking context and a deferred layer (ADR-076): each frame of the animation marks it for painting only (no build, style or layout) and the compositor pushes the new transform; at rest it keeps no transform and paints exactly as without the prop. **Space.** Boxes are compared in `Box.u` coordinates (layout positions without scroll offsets or transforms, logical pixels), so scrolling, ancestor transforms and the display scale (ADR-075) start nothing. A box inside another box with a layout animation (its layout parent) is measured relative to the parent's box and drawn relative to the parent's visual box (Motion's relative targets): a child that keeps its place moves with its parent whatever their timings. **Size changes are a scale** (Motion's look): the box is painted at its new size and scaled; its radii (lengths divided per axis; percentages need nothing) and box shadows (offsets per axis, blur and spread by the mean scale) are corrected (Motion's scale correctors; borders and outlines are not, as in Motion); a box with a layout animation inside a scaled one is counter-scaled (the parent's map undone: Motion's tree scale), so text that should not stretch goes in children with `AnimateLayout`. Because the corrections are in the box's own layer, a frame that changes the scale of a box with px radii or shadows records the layers again (no placement, no layout). **Timing.** A tween with the box's `duration-*` and `ease-*` (and `delay-*`) when one of the first two is set (`ComputedTransition.DurationSet/TimingSet`; the theme's default fills the other), otherwise Motion's spring for x and y: stiffness 500, damping 25, mass 1, rest speed 10 (`anim.MotionSpec.RestSpeed`). Motion's own default for layout animations is a 450 ms `cubic-bezier(0.4, 0, 0.1, 1)` tween that restarts from speed 0 when interrupted; Tela deliberately uses the spring so that interruptions keep their velocity: a layout change mid-flight starts from the visual box of that frame, as x, y, width and height each with its velocity. Reduced motion and trees without a frame clock (`Render`, `tela snapshot`) jump; a box that mounts or is shown again appears at its place. **LayoutID.** A box with a LayoutID that unmounts leaves its window box (as painted last, transforms included) for that commit; a box with the same ID placed for the first time in that commit, or while another box with the ID is inert under an exiting Presence child, starts from it (converted into its scroll space; the transforms of its ancestors are not undone). The old element is not moved; an exiting one runs its Exit classes. **With ADR-077, ADR-079 and ADR-082.** A sticky box's offset is a paint offset in its own scroll space, not part of `Box.u`, so sticking, unsticking and scrolling start nothing; fixed boxes likewise; the children of an `h.Portal` animate like any others, and the Portal itself rejects both props (its layer covers the window). A clip-path, background images and `bg-clip-text` are in the box's own space and scale with the flip without correction, as under a CSS transform (Motion has no corrector for them). BgFn and TextColorFn keep following their Values while a box animates: the flip is applied to the paint style after the paint-phase props are resolved. **telatest** waits for layout animations (the ticker), and `NoSettle` captures their frames.

## Rationale

Motion is the reference users and LLMs know; the owner chose the spring over Motion's tween for velocity-keeping interruptions. Scale instead of animating the size through layout: with layout per frame, siblings with `AnimateLayout` would be retargeted on every frame (their layout changes under them), text in a box whose width animates would re-wrap on every frame, and nested animations would not compose; FLIP lays out once per change, so every box knows its start and end. Cost measured with the headless host (frame = animate, pipeline, damage raster, present): a card growing 100 → 260 px in a 300 ms tween with 5 rows below costs 2.0 ms/frame scaled against 1.9 ms with a `HeightFn` tween relaying out every frame (x2: 6.3 vs 5.9 ms), and with 60 rows 2.5 vs 2.0 ms (x2: 7.7 vs 7.6 ms): raster dominates both, and the scale pays for recording the layers again (its corrections) and copying the paint style of every moving box. Reversing a list of 100 rows (40 frames, every row crossing the list) costs 4.4 ms/frame at x1 and 13.3 ms at x2, nearly all raster; its frames build, style and lay out nothing. Incremental frames equal full ones in a property test (reorder, expand, tab underline handoff, interruption) at scales 1, 1.5 and 2. Known gaps for the owner: the exiting element of a LayoutID handoff does not follow the new one (Motion's follow and crossfade); inline elements inside a paragraph have no box to animate; rotated or skewed boxes that change size are approximate (Motion's approximation); user transforms of ancestors are not undone for handoffs and counter-scaling; a live window resize that changes layout animates on every configure (Motion blocks layout animations while the window resizes)
