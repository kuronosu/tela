# ADR-150: The `examples/kit` gallery and the kit documentation

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

The `examples/kit` gallery and the kit documentation (phase 10, D6; implements ADR-129's K11). **Gallery:** `examples/kit` has a sidebar (a vertical `kit.Tabs`, one tab stop, arrows select) with a page for each of the 34 components of package `kit` (every exported type with a `Build` method but `StyleProvider`; `Toaster` is the Toast page, `ColorInput` and `DateRangePicker` have pages of their own), each with captioned demos (variants, sizes, states and a small composition) built only from kit components and `h` layout elements with token classes; a header with a `kit.ToggleGroup` Style picker ("Default" is kit's recipes, "Rounded" is `kit.DefaultStyle()` with about 40 class edits, applied to the whole window with `kit.StyleProvider`; each edit panics if the class it replaces is gone) and a `kit.Switch` for `tela.SetColorScheme`; a `kit.Toaster` around everything; a Lucide subset in `examples/kit/icons` (`tela icons gen`). **Previews:** `var Previews` has one entry per component named as the component is (`Button`, `DateRangePicker`...), which shows the page over the window's background in the default style, plus `Gallery` and `Gallery Rounded`; `var App` is the window; the calendars pin `Today` to 25 October 2026 so screenshots do not drift. **Tests:** every preview in both schemes and every page in both styles render with dev mode on and no warning; a test reads the sources of `kit` and fails when a component has no page; goldens of the gallery and nine pages (light and dark, x1) and of overlays open; the sidebar and header by keyboard, the aria snapshot of the shell; behavior of the demos; idle (no frames, except the skeleton and the indeterminate bar) and damage checks. **Wiki:** `docs/wiki/Kit.md` (shape, value rule, slots, trigger slots, three levels of customization with a worked recipe, every component with an example, known gaps), `kit` is added to `internal/gen/wikidoc` so `API-Reference-kit.md` is generated and checked for freshness like the other four packages, and README.md and the wiki Home and sidebar link both (`docs/images/kit.png` and `kit-dark.png`, `tela snapshot --scale 2`). **Found while composing it, not changed in `kit` (to the owner):** (1) a `w-fit` `kit.Calendar` inside a stretching column (`Div(Class("flex flex-col"), kit.Calendar{}, P(...))`, 800 px wide) is laid out 685 px tall instead of 291 (it is right with `items-start`; it looks like the `aspect-square` day cells are measured at the stretched width), worked around with `items-start` in the gallery; (2) `Input`, `Textarea`, `ColorPicker` and `ColorInput` have no `AriaLabel` field (`Props: h.AriaLabel(...)` works); (3) `ColorInput` and `ColorPicker` take no `ID`, so a `Field` around them warns that its label names no control; (4) `Avatar` has no class for the fallback, so a tint in `Class` is hidden by the fallback's `bg-muted`; (5) the known gaps of ADR-145 (a component that returns a kit component needs `Fragment`; `Field` puts a control before its text only, so a label-left form row needs `flex-row-reverse`; no group caption; no `Key` field on kit components, `Props: h.Key(...)`); (6) `ToggleGroup`'s arrows move the focus without choosing, as the doc says, so a segmented control is reached with arrows and chosen with Enter or Space; (7) a `Select` trigger's accessible name is its text followed by the `AriaLabel` ("Select a timezone Timezone")

## Rationale

A gallery with one page per component is the test of the whole kit at once: it found a layout problem and four API holes that no per-component test saw, and the test that reads `kit`'s sources keeps the gallery from falling behind the kit. The page of a component being its preview means `tela dev --preview Calendar` is the way to develop a component. Generating the kit's reference page costs nothing and keeps pkg.go.dev, the wiki and the code in step, as for the other packages
