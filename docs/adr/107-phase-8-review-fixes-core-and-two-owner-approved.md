# ADR-107: Phase-8 review fixes, core, and two owner-approved follow-ups

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Phase-8 review fixes, core, and two owner-approved follow-ups (amends ADR-069, ADR-086, ADR-096, ADR-098, ADR-100, ADR-101 and ADR-106). **Implicit submission (ADR-069, ADR-106).** The Form's default button is its first submit button in tree order (`submitButton`): a `Button` of type submit, or any element that a press hook made a button of type submit (`core.DefaultButtonType`, or an explicit `Type` over it), so a `Div` made by `aria.UseButton{Type: "submit"}` is clicked by Enter in any field of a multi-field form (ADR-106 said a Div was not found). An element with a `Type` and no hook is not one (its click does nothing). A disabled default button blocks the submission, as HTML does (it is not skipped for a later one). **`telatest` widget states (ADR-086).** `HasPopup(kind)` ("true" is "menu", "false" is ""), `ActiveDescendant(loc)`, `NoActiveDescendant()` and `Controls(loc)` read `semantics.Node.HasPopup`, `.ActiveDescendant` and `.Controls`; a reference state holds when the node's ID is that of the one element `loc` locates (strictness applies to `loc`), and its failure names the element the reference points to. `State.check` takes the `App` to resolve locators. `examples/aria` checks the combobox's highlighted option with `ActiveDescendant` instead of its `bg-accent` class. **Touch pan (ADR-100).** When a scroll container's pan wins a touch, the pointer is cancelled for good: after the `pointercancel` at the pressed element nothing more of that touch is dispatched until it lifts (`pointerState.panned`: no `pointermove`, `pointerup`, `mouseup`, nor a second `pointercancel` if the platform sends one), and the interact-outside listeners the press started outside of are forgotten, so `OnEnd` and `OnInteractOutside` do not run at the release (ADR-100 said the later pointer up still arrived). The gestures still see the moves and the release (the pan scrolls and flings). The pressed elements stop being `active:` when the pan wins, not at the release, as Chromium clears `:active` when a touch scroll begins. **`SrcFS` cache key (ADR-098).** "When the file system is comparable" becomes "when its value is hashable": `hashable` walks the dynamic value (interfaces, struct fields, array elements; maps, slices and functions are not hashable; pointers are not followed) without `recover`, because a comparable struct whose `fs.FS` field holds an `fstest.MapFS` panicked in the cache's map, under its mutex, and the next load deadlocked. Such a file system loads without the cache. **Nested flushes (ADR-096, ADR-101).** The interact-outside listeners, `OnInteractOutsideStart`/`OnInteractOutside`, `OnEscape` and `OnFocusOutside` run under `handlerDepth` like handlers, and so do the passive effects run by `FlushEffects`: `ElementRef.Click` and a button hook's activation from them queue their updates for the event that is running (the pointerdown reaches its target before the build) or, after the effects, for the host's next step, which the setters wake. **Float limits (ADR-096).** Limits that still change after `maxFloatRelayouts` are no longer dropped with their key recorded (which kept them from ever applying): the box is forced, and the next frame is requested after the frame and calls Place again, up to `maxFloatRetryFrames` (3) frames in a row; after those, the limits wait for a frame that runs for another reason. **Not changed: a rebuild places again.** Comparing `FloatOptions` by content so that a rebuild does not force Place is unsound: `Place` and `AnchorRect` are closures, not comparable, and the same code capturing other options (aria's `Offset(8)` then `Offset(16)`) must place again; `BenchmarkFloatingRebuild` measures the forced call at 46.7 µs per frame against 46.3 µs with an unsound skip, with the same allocations.

## Rationale

Each finding was reproduced by a test that fails without its fix (`TestTouchPanEndsThePress`, `TestSrcFSUnhashable`, `TestOverlayCallbacksDeferNestedFlush`, `TestEffectClickDefersFlush`, `TestFloatingLimitsAfterSpentBudget`, `aria`'s `TestImplicitSubmissionHookDiv`); `TestFloatingRebuildPlaces` keeps both sides of the rebuild rule. `NoActiveDescendant()` is a function rather than `ActiveDescendant` of the zero Locator, which every other API rejects as a mistake. Browsers send no pointer events for a pointer after `pointercancel`; the documented contract of `ElementRef.Click` is that the event or frame that runs applies and builds. Every golden is bit-identical. The same rule covers programmatic focus: `afterFocusEvent` (after the focus, blur and compositionend events of a focus change) is `flushNested`, so `ElementRef.Focus`, the focus manager (`FocusNext`, `FocusFirst`...) and focus scopes called from a handler, an overlay callback or a passive effect fire the focus events at once and leave applying and building to the running event, frame or host step (`TestProgrammaticFocusDefersFlush`); a focus change outside them (a press, Tab, the window gaining focus) still applies and builds at once.
