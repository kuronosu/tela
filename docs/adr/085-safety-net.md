# ADR-085: Safety net

- **Date:** 2026-10-20
- **Status:** Accepted

## Decision

Safety net (phase 7, T1; the public API and decisions D2, D4 and D5 are the owner's; amends §7, §19, ADR-051, ADR-053 and ADR-059). **Dev mode by default.** `tela.App.Dev *bool` (nil = automatic) and `telatest.NoDev()`: `telatest.Mount`, `Render`, `AriaSnapshot` and `LayoutJSON` default to dev (`Dev()` stays, a no-op alias); `TELA_DEV=1`/`0` overrides both (other values are ignored). Automatic means "not a release build", decided once by `core.ReleaseBuild` from `runtime/debug.ReadBuildInfo`: a test binary (path ending in `.test`) never is one; a binary built with `-trimpath` is; one whose main module has a version other than `(devel)` and no `vcs*` setting is (`go install pkg@version`, built from the module cache); everything else is not (`go run` has `(devel)`, and `go build` in a checkout stamps a pseudo-version, `+dirty` with local edits, together with `vcs.*` settings since Go 1.24); no build info counts as development. Node constructors, which know no tree (`Role`, `Type`, the call sites of `Map`/`List` and of anonymous `CP`), follow a process default: `ResolveDev(nil)` at init, on when a dev tree is created, the app's mode once `Run` starts. **Messages.** `core.Config.Warn` (nil = `Log`) separates warnings from errors: unknown classes and unloadable images stay errors (stderr; a failure in telatest unless `AllowDev`), dev panics stay panics, and warnings, once per call site or subject, are stderr lines and telatest log lines: lists without keys and duplicate keys (per call site of `Map`/`List`, captured in dev mode; per parent for hand-written siblings), anonymous `CP`/`Memo`, deps that cannot be compared or change in number, **nil deps** (D5: `UseX(f, nil)` keeps meaning "mount only" and warns with the replacement, `UseMount`, `UseOnce`, or a constant dependency for `UseLayoutEffect`/`UseGo`; a later version rejects it), **`Value.Get` with queued changes** outside a tracked evaluation (D4: `Get` unchanged; the warning names the call site and `Latest`), `UseContext` without a Provider when the default is nil or holds a nil func, pointer, map, channel or interface or a zero `Setter`/`Callback`/`Dispatcher` in an exported field (once per context; pointers are not followed), and a `Label` that neither wraps an Input, Textarea or Button nor names a mounted one with `For` (checked after the build phase). **Hook boundaries (D2).** The first build of each hook slot walks the stack from the hook (`runtime.Callers`, dev mode only): frames of Tela's packages outside `_test.go` files are skipped; the component's function, or a function literal defined in it (names compared without `[...]` and `-fm`; `F.func1.2`, `F-range1`), accepts; a function named `UseXxx`/`useXxx` passes the decision to its caller; anything else panics naming the function and the fix (`tela.C`/`tela.CP`, or a custom-hook name); reaching the build or the end of 32 frames accepts, and accepted stacks are cached. `compDesc.boundaryFunc` is the hook point for struct components (T3: their `Build` method). A hook outside any build names its caller and, for a named function that no Tela frame called (`telatest.Mount(t, Counter())`), says to wrap the root in `tela.C`. **API.** `tela.Main(app)` (runs `Run`; on error prints `tela: <err>` on stderr and exits 1), `Setter.IsZero`, `Callback.IsZero`, `UseMount(effect)` (a constant dependency), `UseOnce(init)`, `UseEffectDo(f, deps...)`, `UseUpdateEffect(effect, deps...)` (skips the first build), `UseGo(f(ctx), deps...)` (an effect that starts a goroutine and cancels its context at cleanup; the goroutine is not waited for), and `UseInterval(d, f)` on the tree's frame clock: a deadline like the long press (`NextDeadline`, `TickGestures`), started by an effect after the frame that shows it, restarted when `d` changes, paused for `d <= 0`, calling the latest `f`, once per late tick

## Rationale

The owner's decisions (D2, D4, D5, D9). Reading the build info needs no flag or ldflags convention: `-trimpath` and module-cache installs are what release builds are, and Go 1.24's VCS stamping makes "version is not (devel)" alone wrong for `go build`. Warnings must not fail tests (an example with a nil dependency would), while errors still do, so a class typo fails every test. The boundary check fired on the examples whose `Preview` (or `Player`) called a stateful component directly (board, counter, motion, pricing, settings, virtuallist, player): `tela snapshot` runs in dev mode, so they now return `tela.C(...)`/`tela.CP(...)`. It costs one stack walk per new hook slot in dev mode and nothing otherwise. A frame-clock interval is deterministic in tests and needs no goroutine
