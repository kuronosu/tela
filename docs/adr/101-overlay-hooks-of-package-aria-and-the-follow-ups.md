# ADR-101: Overlay hooks of package `aria`, and the follow-ups to ADR-100

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Overlay hooks of package `aria`, and the follow-ups to ADR-100 (phase 8, T5b; every shape is the owner's decision; amends §14, ADR-069, ADR-096 and ADR-100). **ADR-100 amended.** (1) `ToggleOptions.Selected` is a `*bool`: nil is uncontrolled (`DefaultSelected` is the start), a pointer is controlled (`Selected: &on, OnChange: setOn.Set`: the control shows it and only asks `OnChange`); `OnChange` is also called for an uncontrolled control, so `DefaultSelected` and `OnChange` coexist (ADR-100 made `OnChange` the switch to controlled, which could not express an uncontrolled control with a listener). The same rule, `Open *bool`, `DefaultOpen`, `OnOpenChange`, holds for every overlay hook (`boolState` in `aria/state.go`, whose `request` also updates an uncontrolled value at once, so a second request in the same event sees it). (2) One `h.Ref` per element: two different refs on one element panic in dev mode (`AttachRef` keeps the ref and, in dev mode, its call site in `desc.refSite`; the message names both sites, the call of the hook when the ref comes from a hook of `aria` (`apiFrame` skips its `Use…` frames), and the fix, `aria.PressOptions{Ref: ref}`); outside dev mode the last one wins as before; the same ref twice is fine; the dev mode is that of the Tree being built (ADR-093). No example or test needed a change. (3) `ElementRef.Click()` (public through the `tela.ElementRef` alias) is `element.click()`: a click with the primary button and a click count of 1, at the center of the bounds, made by no pointer (a virtual press for `UsePress`), then the activation behavior of ADR-069 (a Button in a Form submits or resets by its type, a Label focuses its control and clicks it); a disabled or unmounted element ignores it. Called from a handler, an effect or a posted function it must not rebuild under the code that called it, so `Tree.handlerDepth` (every event dispatch and `ApplyUpdates`) and `Tree.inFrame` make `flushNested` do nothing there: the event or frame that runs applies and builds the updates. (4) `UseButton` gains `Type` (`"button"` by default, `"submit"`, `"reset"`; a typo panics in dev mode with the closest value): when a press completes, after `OnPress`, `core.ActivateButton(ref, type)` submits or resets the Form that contains the element, whatever the element is (a Div too; the press still prevents the click's own activation, so a Button is not activated twice); it is the activation of ADR-069, so `ref.Click()` on a hook-made submit button submits through the virtual press. (5) `ToggleOptions` gains `OnPress`, `OnPressStart`, `OnPressEnd`, `OnPressChange`, `OnPressUp`. **Overlay hooks.** Options struct in, result with `Props` out; the overlay is rendered by the caller (in a `Portal`, in a `Presence` to fade out) and the hooks that put props on its element share its ref (`OverlayTriggerResult.OverlayRef` is passed as their `Ref` option; the two-refs panic says so). `UseOverlay(OverlayOptions{Open, OnClose, Dismissable, KeyboardDismissDisabled, ShouldCloseOnBlur, ShouldCloseOnInteractOutside, Modal})` puts `core.Overlay` on the element only while `Open`: Escape calls `OnClose` (not with `KeyboardDismissDisabled`, which still swallows the key); with `Dismissable` a press outside asks `ShouldCloseOnInteractOutside(tela.PointerEvent)` (nil: yes) and, when it will close, is stopped and prevented at the pointer down, and at the release is stopped, prevented (its click is cancelled) and calls `OnClose`, as React Aria's `useOverlay`; `ShouldCloseOnBlur` uses a new engine callback (below); `Modal` is `core.Overlay{Modal}`. `useModalOverlay` is folded into it (`Modal`), and there are no `underlayProps`: a press outside a modal overlay hits no element below (ADR-096), and a scrim is an ordinary element. `UseDialog(DialogOptions{Role, Modal, AriaLabel, Ref})` returns `{Props, TitleProps, Manager, Ref}`: `Props` are a focus scope (`Contain` when modal, `Restore`, `AutoFocus`), the role (`dialog` or `alertdialog`, else a dev panic), `TabIndex(-1)` (so the dialog takes the focus when nothing inside is tabbable), `aria-modal` and the name (`AriaLabel`, else `AriaLabelledBy` the element with `TitleProps`); an alert dialog is an overlay that is not `Dismissable`. `UseOverlayTrigger(OverlayTriggerOptions{Type, Open, DefaultOpen, OnOpenChange, Disabled, Ref, OverlayRef})` returns `{TriggerProps, OverlayProps, Open, SetOpen, Toggle, Close, Pressed, Ref, OverlayRef}`: the trigger is a button (the press of `usePressCore`, role, tab stop) with `aria-haspopup` from `Type` (`dialog` by default, `menu`, `listbox`, `tree`, `grid`; React Aria omits it for dialogs, ARIA 1.2 allows `dialog`), `aria-expanded` and, while open, `aria-controls` the overlay's ref; `OverlayProps` holds just that ref. `UsePopover(PopoverOptions{Trigger, Open, OnClose, Placement, Offset, Floating, Modal, KeyboardDismissDisabled, ShouldCloseOnInteractOutside, Ref})` returns `{Props, ArrowProps, Placement, Side, Align, Ref}`: `UseFloating(Trigger, Placement (bottom), Offset, Flip, Shift(12), Floating..., Arrow)` and the overlay (always `Dismissable`, with `ShouldCloseOnBlur`); a press outside a non-modal popover does not close it when it is over the trigger's bounds (the trigger's press toggles it; `OnInteractOutside` has no target element to compare, so the bounds decide), and the focus moving to the trigger does not close it; a modal popover closes for the trigger's presses (the trigger is inert, so it is outside). Popovers are non-modal by default (React Aria: modal unless `isNonModal`; the zero value of `Modal` is false). `UseMenuTrigger(MenuTriggerOptions{Trigger ("press", "longPress"), Type, Open..., Disabled, OnPress, Ref, MenuRef})` returns `{TriggerProps, MenuProps, Open, FocusStrategy, SetOpen, Toggle, Close, Pressed, Ref, MenuRef}`: a mouse or a pen opens the menu at the press start and toggles it when open (the non-modal case; a modal menu's trigger is inert), a touch at the release, a virtual click with `FocusFirst`; Enter, Space and ArrowDown toggle it with `FocusFirst`, ArrowUp with `FocusLast` (constants `"first"` and `"last"`; `""` for the menu itself); `longPress` uses `h.OnLongPress` (500 ms), opens with `FocusFirst`, leaves the quick press to `OnPress` (not run for the release of a long press) and needs Alt for the arrow keys; `MenuProps` are the ref, `aria-labelledby` the trigger and a focus scope with `Restore`, for T8's `UseMenu` (which reads `FocusStrategy`, calls `Close` when an item is chosen, and adds the `menu` role, items and keys; `Direction` is not offered). `UseTooltipTrigger(TooltipTriggerOptions{Delay, CloseDelay, Disabled, Trigger ("", "focus"), Open..., Ref, TooltipRef})` returns `{TriggerProps, TooltipProps, Open, Ref, TooltipRef}` (React Aria's `useTooltipTrigger`, `useTooltip` and `useTooltipTriggerState`; there is no separate `UseTooltip`: the tooltip element is rendered only while open, so its props, the `tooltip` role, the ref, hover that keeps it open and Escape, come from the trigger's hook): the pointer must rest `Delay` (1.5 s) on the trigger, a keyboard focus (`core.FocusVisible`) opens at once, `CloseDelay` (0.5 s) closes after leaving, a pointer down or any key down on the trigger and a blur close at once, hover on the tooltip itself keeps it open; the tooltips of a window are a group (`core.TreeLocal`: React Aria's module state, per Tree): opening or warming up one closes the others, and while one is open or for `max(0.5 s, CloseDelay)` after the last closed (`coolAt` on the frame clock) the next opens at once; a zero delay is the default and `aria.NoDelay` (negative) is none. The trigger is `aria-describedby` the tooltip while open (new `h.AriaDescribedBy(ref)`, `core.AriaDescribedBy`: the node's `Description` is the text of the referenced element, `AriaDescription` wins; the snapshot does not print descriptions, as Playwright's). **Engine.** (a) `core.UseTimeout()` is a one-shot timer on the frame clock (an `intervalSlot` with `once`, in `Tree.intervals`, so `NextDeadline`, `TickGestures` and telatest's `Advance` drive it): `Start(d, f)` from handlers at the event's time, `Stop`, `Pending`; no goroutine, and an idle window with a pending tooltip asks for no frame; `core.Clock(ref)` reads that clock. (b) `core.TreeLocal(key, init)` is a value per Tree. (c) `OverlayOptions.OnFocusOutside` (`Tree.focusMoved`, called by `setFocus` once the focus is set, for the overlays that contain the old element and not the new one; a focus that goes nowhere does not call it) and `OverlayOptions.EscapeOnly`: a tooltip is on the stack for Escape (`topEscapeOverlay`: it takes the key before the overlay below, as React Aria's tooltip stops it) but not for presses (`topOverlay` skips it), so a tooltip over a popover does not hide outside presses from it. **Deviations from React Aria**: one hook for modal and non-modal overlays and no underlay props; `ShouldCloseOnInteractOutside` takes the press, not the element; blur closes without asking; popovers non-modal by default; the trigger excluded by bounds; `aria-haspopup="dialog"`; the menu trigger toggles on a mouse press when open; a tooltip has no `getInteractionModality` check (Tela does not emulate hover from touch); the trigger of a tooltip closes on any key down, as React Aria's `onKeyDown` does; `Delay` and `CloseDelay` use zero for the default.

## Rationale

Owner's shapes (options and results with `Props`, state integrated, `*bool` for controlled, `Click`, `Type`). Every behavior is checked in telatest: a modal dialog (the page is out of the snapshot, Tab stays inside, Escape closes, the focus returns to the trigger, an outside press closes a dismissable one and is not delivered to the page, an alert dialog ignores outside presses and the inert page is not clicked), a popover (placed in its first frame under `NoSettle`, closed by Escape, a press outside and the trigger's second press, a press inside a popover opened from it in another Portal does not close it, a press in the outer one closes only the inner, Escape closes the top one only, blur, modal, an exit animation in a `Presence`), a menu trigger (ArrowDown, ArrowUp, Enter, Space with the focus returning, the mouse, a long press and its release, Alt arrows), tooltips (delay, close delay, warm-up and cool-down between two triggers, focus-only, keyboard focus, Escape, press, hover on the tooltip, disabled, controlled, no frames while pending or open), `UseButton{Type}` (submit and reset from a Div with the mouse and Enter), `ElementRef.Click` (from an effect and a handler, a Label, disabled, unmounted), the two-refs panic and its dev-only scope, toggles with `*bool`; core tests for the timeout, `TreeLocal`, the description and the panic. Every golden is bit-identical. Known gaps: no underlay for modal overlays, no `Direction` for the menu trigger, an overlay's `Open` must be passed to `UseOverlay` and `UsePopover` (a component that exists only while open passes `true`)
