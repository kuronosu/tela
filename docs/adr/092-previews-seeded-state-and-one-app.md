# ADR-092: Previews, seeded state and one `App`

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Previews, seeded state and one `App` (phase 7, T5; the owner's decision D8; amends §17, ADR-047, ADR-059 and ADR-085). **Previews.** `tela.Previews` is `map[string]tela.Preview` with `Preview{Root Component; Wrap func(Node) Node}` (it replaces `map[string]func() Node`; Go cannot keep both forms compiling, so every entry becomes `"Name": {Root: tela.C(fn)}`, the CLI explains it when it meets the old form); `Root` is a node or a struct component, so a preview's local state is seeded by the fields of a struct component (`Main{InitialTab: "open"}` with `UseState(m.InitialTab)`) and a context's by `Wrap`, which gets the root as a node and returns it inside the providers (`AppState.Provider(mock, n)`; no hooks in it). `Preview` is itself a `Component` (`Build` returns `Wrap(Root)`, a nil `Root` panics with the fix): the CLI mounts `Previews[name]` and a test mounts the same value. `func Preview()` may return `tela.Node` or `tela.Component`, and the CLI no longer wraps it in `tela.C`: what it returns is mounted, so a function component needs `tela.C` (a hook called directly in `Preview` is the dev panic of ADR-085); `tela inspect --layout` therefore shows no `component` on the screen's root box, which `cmd/tela/testdata/inspect_preview.json` recorded. **One `App`.** `telatest.FromApp(app) Option` applies Width and Height (both set), RootClass, ColorScheme, Theme, ClassAliases, ClassicScrollbars, InstantScroll and Dev, setting only what the app sets (options after it override; Title, AppID and Root are ignored; a test fails when a new `App` field is in neither list) and `telatest.MountApp(tb, app, opts...)` is `Mount(tb, tela.C(app.Root), FromApp(app), opts...)`. The generated runner declares `var telaApp tela.App = App` when the package has a package-level `App` (an `App` that is obviously another type, such as a literal of another type, is left alone) and applies `FromApp` after its defaults and before an explicit `--size`; the app's `ColorScheme` beats `--dark` (a warning says so for Light), and a package that defines only `App` renders `tela.C(App.Root)` (`--preview` is an error). `App.Root` stays `func() Node` (a struct-component root is `Root: func() tela.Node { return h.Fragment(Main{}) }`). **Messages.** The runner points `os.Stderr` at a file during the run and the CLI prints it on its own stderr, on success and on failure, so dev warnings and class errors of the screen are no longer hidden by the passing `go test`; standard output stays the command's output

## Rationale

One value (`App`) drives `main`, tests and the CLI, so a PNG matches the window; component fields seed local state without globals and `Wrap` seeds context without a second provider copy. Not wrapping `Preview` matches what `tela.Main` mounts. The migration of `Previews` is a source break the compiler flags at every entry; the reflection test over `App`'s fields keeps `FromApp`, `app.options` and the CLI from drifting when a field is added. All 15 examples render bit-identically at the CLI's defaults, none declaring a package-level `App`
