# ADR-149: Example `native` rebuilt on `kit`, one recipe per look

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

Example `native` rebuilt on `kit`, one recipe per look (phase 10, migration D6, the last of ADR-129's K12: "native (Win11, Adwaita and Breeze as three styles)"; the done criterion "native built only on kit, no hand-made control nor hand-drawn icon"). **A look** (`look.go`, `win11.go`, `adwaita.go`, `breeze.go`) is the three levels of K17 plus data: a `tela.Theme` (the tokens: shadcn's names with each platform's colors in light and dark, the example's own `field`, `edge`, `toolbar`, `sidebar`, `selection`, `selection-foreground`, `folder` and `kind-doc`/`kind-pdf`... named after what they paint, `Radius` 5 / 10 / 6.25 so that `rounded-md` is 4 / 8 / 5 px, `FontSans` the platform's family), a `kit.Style` (`win11Style()`, `adwaitaStyle()`, `breezeStyle()`, each an edit of `nativeStyle(fontSize)`, which is `kit.DefaultStyle()` made flat) and a `Frame` (about 20 class strings for the regions the explorer lays out itself, written with tokens only), plus the columns, formats and texts. The old `Look`/`Base`/`Light`/`Dark` structs, the reflection that merged them and the `dark:` twins are gone: **no class in the example says `dark:`**, and following the system draws the same pixels as the forced schemes (`TestFollowsTheSystem`). Switching look (More menu, "Look" radio group) sets the `kit.StyleProvider`'s style and calls `tela.SetTheme` from `UseUpdateEffect`; `TestSwitchLook` checks the result is pixel-identical to starting in that look. `App.Theme` has the first look's tokens (every look defines the same token names, so any recipe resolves under any theme). **What is kit:** toolbar and command-bar buttons (`Button` Ghost, `Size: Icon`, with `Tooltip`), crumbs (small ghost `Button`s), search (`Input`), sidebar (one vertical `ToggleGroup` per section: the selected place is the group's choice, the selection mark is a child of the item), view switcher (`ToggleGroup`) and icon-view tiles (`Toggle`), file list (`Table`: sortable headers with `aria-sort`, sticky header, `Selected`), its context menu (`ContextMenu`), the New, Sort, View, See more and More menus (`DropdownMenu` with radio and checkbox items, one radio group being the Look), Rename (`Dialog` with a `Form`, `Input` and `Button`s), Delete (`AlertDialog`), the zoom (`Slider`) and the separators (`Separator`); the 39 icons are a Lucide subset (`examples/native/icons`, `tela icons gen`) and the old 330 lines of box-drawn glyphs are deleted. New variants and sizes of `Toggle` (`sidebar`, `view`, `tile`) are entries in each recipe's maps. The explorer became more real as a result (Rename, Delete with confirmation, New folder, Cut, Copy and Paste over a persistent in-memory tree, an icon view, a details-pane toggle) because the kit components made each a few lines. **What recipes expressed, per look:** Win11: `Radius` 5, a text box with a 1 px edge and `border-b-edge` that becomes `focus-visible:border-b-2 border-b-primary`, 30 px rows whose first and last cells are `first:rounded-l-md`/`last:rounded-r-md`, a gray `checked:` sidebar with a blue mark, a command bar of ghost buttons and menus. Adwaita: `Radius` 10, `bg-foreground/7` entries and nav group, bold `text-[13px]` headers, 40 px rows with `gap-y-px`, rounded-xl popovers and dialogs, a dark tooltip. Breeze: `border border-transparent hover:border-primary hover:bg-accent` toolbar buttons, a solid `selection` highlight on rows, places and menu items (`focus:bg-selection`), a thin `Slider`. **What could not be recipes** (they are the `Frame`, and the example's own): the layout of the regions (kit has no toolbar, sidebar or status bar), a `Table` row's name and handlers (the handlers are on each cell's content; a row is `display: contents`), the sort arrows of unsorted headers (hidden by giving `SortIcon` an empty drawing), and the platforms' real icon shapes (Lucide outlines everywhere). **Accepted differences:** Lucide outlines instead of filled glyphs and two-tone folders; no column resize handles (Win11, Breeze); a sort arrow where there was a caret; the Win11 sidebar mark is a child element; the Windows font falls back to Inter where `Segoe UI Variable Text` is missing (`FontSans` takes one family; the old fallback list `Segoe UI` is lost); Breeze's header has an arrow slot reserved on every column. **API gaps found, not filled:** (1) `Table` rows have no props: a row has no name (it is read from its cells, `HasText` finds it), no `OnClick`/`OnContextMenu` and no `Ref`, so each cell's content carries the handlers and the cell `padding` moved into it; (2) a `Table` sort button cycles to unsorted, which an explorer never is (`OnSortChange` maps it back); and its unsorted icon cannot be hidden without an empty `tela.Icon`; (3) `Input` has no `AriaLabel`, and `Props` is a single prop with no public way to merge several (`core.MergeProps` is internal), so an input with a `Ref` and a label needs the label as its placeholder, and a focusable list needs a wrapping `Div` for its `Ref`, `TabIndex` and `OnKeyDown`; (4) `ToggleGroup` has no section headings or separators inside a group, so the sidebar is one group per section; (5) portals do not inherit the window's text size, so every recipe of a portal (menu, dialog, tooltip) repeats it; (6) `tela.Preview` has no `Theme` or `ColorScheme`, and `tela snapshot` renders one shot and does not run the effect that calls `SetTheme`, so a preview takes the theme of `var App` (here `NATIVE_LOOK`, default the platform's) and a look's tokens must exist before the first build; (7) `telatest` has no right click, so the context menu is tested with Shift+F10. No kit addition was needed. **Hand-made, kept:** nothing that is a control. The regions, the cell contents, the details pane, the status text and the selection mark are layout and content; the empty `noSort` SVG is a placeholder, not a drawing. Goldens: three looks by two schemes at x1 and x2, the icon view, the context menu, the rename and delete dialogs (x1), the aria snapshot (GNOME); no other example's golden changes

## Rationale

The explorer is the proof that recipes restyle a whole app: three platform looks with different geometry, colors, hover models and selection models are `Style` edits and tokens, with no copy of a component's source and no `dark:`. What recipes could not say (regions, row props, one input prop) is a short, specific list for the owner rather than a hack in the example; the example's own classes are tokens, so a look changes colors in one place. Making Rename, Delete and the clipboard real cost a persistent-tree reducer, but let the dialogs, the alert dialog and the context menu be exercised by tests instead of drawn as inert buttons
