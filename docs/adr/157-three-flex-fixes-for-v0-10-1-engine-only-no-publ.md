# ADR-157: Three flex fixes for `v0.10.1`, engine only, no public API change

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

Three flex fixes for `v0.10.1`, engine only, no public API change (amends ADR-039, ADR-043, and ADR-142's deviation (3)). **Zero percentages:** `style.LP` cannot tell 0% from 0px, so Tailwind's `flex-1` (`flex: 1 1 0%`), `basis-[0%]`, `flex-[1_1_0%]`, `h-[0%]`, `max-h-[0%]`, `top-[0%]`, `calc(0% + 10px)` and 0% grid tracks reached layout as lengths: a `flex-1 overflow-y-auto` item of a `max-h-[300px]` column was its padding tall (8 px) instead of its content (88 px, Chromium). `style.Dim` and `style.TrackBreadth` gain `ZeroPct`, set only when a percentage part is written and is zero, so `==` still compares values (`DimPct(0)`, `DimLP`, `Dim.HasPercent`; `String()` gives `0%` and `calc(0% + 4px)`); the class parser's length expressions carry it through `calc()`, negation and the intern cache, and a transition keeps it while a term that has it takes part. LP stays two floats: padding, gaps, radii, translate and positions resolve 0% and 0px alike, and `ComputedStyle` does not grow. core maps a zero percentage to a layout percentage for sizes, max sizes, insets, flex-basis and grid tracks (indefinite against an indefinite basis: auto, none, a content-based basis), and to 0px for min sizes and margins, where CSS gives the two the same meaning. In layout a percentage min main size of an indefinite basis counts as 0 (CSS 2.1 section 10.7), not as auto (`min-h-[50%]` in such a column now lets the item shrink, as in Chromium). **Aspect-ratio items:** a cross size the ratio transfers from the item's own preferred main size is no longer a known or definite cross size, so the automatic minimum is the content's, clamped by the min and max cross sizes transferred through the ratio (Flexbox 4.5): seven `w-full aspect-square` items in 280 px are 40×40, not 280×280 (two `w-[280px]` ones 140×140); a stretched cross size measures a ratio item only when it is definite (an absolutely positioned flex row of `aspect-square` items no longer makes them as tall as the containing block); the hypothetical cross size follows the used main size. A replaced item with a ratio but no natural size (an SVG with only a viewBox, which Tela draws at its viewBox size when nothing sizes it, ADR-098) does not take that fallback for content: its content size suggestion is Chromium's, the container's inner width in a row and the default object size (300 x 150) fitted to the ratio in a column (`layout.Style.NoNaturalSize`, set by core), so the media gallery's `w-16` viewBox-only image keeps its 64 px and the `w-24 h-12` one shrinks to 48 as in Chromium. Taffy 0.14.0 and 0.15.1 have the same gaps, so the rule follows Chromium rather than a port. **Keyword cross sizes:** an item with a `min-content`, `max-content` or `fit-content` cross size is measured at that size for its flex base size and its content contribution instead of stretched (a `w-fit` box of `aspect-square` cells in a stretching column is 88×56, was 88×412; `kit.Calendar` in `flex flex-col` at 800 px is 248×291, was 248×685), and content contributions no longer stretch items with an auto cross margin, as base sizes already did not. `kit`'s Calendar `Day` gets shadcn's `aspect-square` back: the calendar and date picker sheets render pixel-identical with it. **Tests:** layout cases `flex_percent_zero`, `flex_aspect_ratio_min_size` and `flex_fit_content_cross` measured by Chromium 154 (the 25 earlier cases measure the same as with 152), core and style tests with the same numbers, a kit test of the Calendar in a column; the layout determinism digest is recorded again (the new cases and 73 of the 200 random trees, each with a flex item that has a ratio, a keyword cross size or an auto cross margin in a column, change; every Taffy fixture and earlier case hashes the same). **Not changed:** a ratio item with a definite main size is still clamped by its max cross size transferred into a max main size (Chromium: 140×20 for two `w-full aspect-square max-h-[20px]` in 280 px, Tela 20×20); a ratio item with content in a column of indefinite width is measured at its content height, not at its fit-content width transferred (Chromium 30×30, Tela 5×5 for a 30 px wide content)

## Rationale

Each case was measured in Chromium, the reference (ADR-043). A field next to the Kind costs no space, where a third LP field would add 4 bytes to every length of every style; only properties whose percentages can meet an indefinite basis need it. The aspect-ratio and keyword rules are Flexbox 4.5 and 9.2.3 E and css-sizing-4 as Chromium implements them; no Taffy fixture needs them (none shrinks a ratio item below its preferred main size, measures one in a container of indefinite cross size, or gives a column item a keyword width)
