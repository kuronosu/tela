# ADR-099: `aria.UseFloating`

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

`aria.UseFloating`: Floating UI on the same-frame engine (phase 8, T7; the call shape is the owner's, decision E6; amends §14 and ADR-096). **Package `aria`** becomes public with its first files, `aria/floating*.go` (`doc.go` and the press, hover and focus hooks come from other tasks); it imports `tela`, `h` and `internal/core`. **API.** `aria.UseFloating(anchor tela.ElementRef, opts ...aria.FloatingOption) aria.Floating`, a hook, with `fl := aria.UseFloating(anchorRef, aria.Placement("bottom-start"), aria.Offset(4), aria.Flip(), aria.Shift(8), aria.Size(func(a aria.Available) { a.MaxHeight(a.Height) }), aria.Arrow(arrowRef))` and `Portal(Div(fl.Props, Class("rounded-md border bg-popover"), …, Div(Ref(arrowRef), fl.ArrowProps, …)))`. The options are functional options applied in the order given (Floating UI's middleware array; order matters). `Placement(string)` takes the 12 placements (an unknown one panics in dev mode with the closest valid one, and is ignored otherwise; every option validates when it is made); `AnchorRect(func() tela.Rect)` makes the anchor a virtual rectangle when the anchor ref is the zero `tela.ElementRef` (a `Value` it reads places the element again without building; a zero ref without `AnchorRect` panics in dev mode); `Offset(mainAxis float32, …OffsetOptions)`, `Flip(…FlipOptions)`, `Shift(padding float32, …ShiftOptions)` with `LimitShift(…LimitShiftOptions) ShiftLimiter`, `Size(apply func(Available), …SizeOptions)`, `Arrow(ref, …ArrowOptions)`, `Hide(…HideOptions)` and `AutoPlacement(…AutoPlacementOptions)` (the last two are cheap ports of Floating UI's `hide` and `autoPlacement`); `inline` is not ported. The extra options of Floating UI go through one optional variadic options struct per function (a second one panics in dev mode); bools that default to true there are negated (`NoMainAxis`, `NoCrossAxis`, `NoFlipAlignment`, `NoAutoAlignment`) so that the zero value is Floating UI's default, `crossAxis: 'alignment'` is `CrossAxisAlignment`, `alignmentAxis: number \| null` is `AlignmentAxis` with `HasAlignmentAxis`, and `padding` is one number everywhere. **Size.** `Available` has `Width` and `Height` (availableWidth and availableHeight), `Rects` (`Reference` and `Floating`, `tela.Rect`s in window coordinates) and `Placement`, and the methods `MaxWidth(w)` and `MaxHeight(h)` (value receivers over an internal sink, so `a.MaxHeight(a.Height)` works on the value `apply` receives); the limits of the last run become `FloatResult.MaxWidth`/`MaxHeight`, so the element's border box is limited in the same frame by the engine's relayout, and a limit that `apply` does not ask for in a run is removed. **`Floating`** has `Props` (`core.MergeProps` of `fixed top-0 left-0` and `core.Floating`: a later class such as `absolute` wins), `ArrowProps` (`absolute top-0 left-0` and a paint-phase `TranslateFn` that reads the values `Place` publishes: the arrow goes half outside the floating element's border box on the side facing the anchor and along it to the anchor's center, Floating UI's recipe), `Placement` (the final placement after flip, one frame late as ADR-096 says; the requested one before the first position), `Side` and `Align`, `ArrowX` and `ArrowY` (Floating UI's arrow data as `tela.Value[float32]`s, 0 on the other axis), and `ReferenceHidden` and `Escaped` (`Value[bool]`s of `Hide`, read in a paint-phase closure to follow the same frame; an anchor that is not displayed counts as hidden). **The port.** `aria/floating_position.go` and `aria/floating_middleware.go` port `@floating-ui/core` 1.7.5 function by function (`computePosition` with its reset loop of at most 50 restarts and the merged `middlewareData`, `computeCoordsFromPlacement`, `detectOverflow`, the placement helpers of `@floating-ui/utils`, `offset`, `flip` with `fallbackPlacements`, `fallbackStrategy`, `fallbackAxisSideDirection`, `flipAlignment` and `crossAxis` including `'alignment'`, `shift` with `limitShift`, `size`, `arrow` with its alignment-offset reset, `hide`, `autoPlacement`), keeping the MIT copyright notice (`THIRD_PARTY.md`). It is a pure function of the engine's `FloatInput` (the anchor as painted, the floating size, the clipping rectangles of the floating element and of the anchor, direction and arrow size), float32 in window coordinates with the fixed strategy; `-start` and `-end` mirror in a right-to-left floating element exactly as Floating UI's `rtl` platform flag. **Deviations** (each listed in the wiki's Aria page): (1) the size middleware cannot measure the element again inside `computePosition`; the engine's relayout and a second call of the position function (a fresh computation) take the place of Floating UI's `reset: {rects: true}`, which keeps `middlewareData` (flip's index and overflows) across the reset, so the two can end on a different placement when flip, autoPlacement, offset or shift run after size (size goes last in every example); (2) the clipping rectangle is the engine's `Clip` and `AnchorClip` (window cut by the overflow clips of the containing-block chain), so `boundary`, `rootBoundary`, `elementContext`, `altBoundary` as options and per-side padding objects are not offered, `offset` and `limitShift`'s `offset` take numbers only, not functions of the placement; (3) the arrow's client size is the floating element's border box (Floating UI reads the offset parent's `clientWidth`), so with a border the arrow is off by the border's width; (4) an anchor that is not displayed leaves the element where it was (`NaN` coordinates) and publishes `ReferenceHidden`. **Oracle.** `aria/testdata/floatingui/gen.mjs` (node, the real `@floating-ui/core` 1.7.5; `npm install` there) generates `cases.json`, 2,400 seeded random cases (rectangles in quarter pixels, so float32 and float64 agree exactly; the 12 placements, left-to-right and right-to-left, inner clipping rectangles for the floating element and the anchor, arrows, and random middleware stacks in random order with random options, half of them the typical offset, flip, shift, arrow stack). `TestOracleComputePosition` compares 2,148 of them without a size limit: coordinates, final placement, the arrow data (x, y, centerOffset and alignmentOffset), the hide data and every call of the size middleware (available width and height, the reference rectangle, the placement), all equal (709 end on another placement than the requested one, 844 with an arrow, 400 with hide, 775 size calls). `TestOracleSizeLimits` simulates the engine's loop on 252 cases whose `apply` limits the element (and the platform makes the element follow the limit): with size last 2 of 90 end on another placement than Floating UI's reset loop, with size first 28 of 162, and 3 of those need more than the engine's 2 relayouts. Integration tests in telatest: a popover below a button near the window's bottom is above it in its first frame (`NoSettle`) and its `Placement` follows a frame later, shift on both edges, it follows the anchor while an ancestor scrolls with no build, style or layout (and `Hide` reports the anchor scrolled out), `Size` limits the height in the first frame and the content scrolls, flip and size together settle in the first frame, the arrow points at the anchor after a shift and a flip and on the vertical sides, `bottom-start` in a left-to-right and a right-to-left element, a virtual anchor follows a `Value` without building, an idle popover runs no frames.

## Rationale

A faithful port gets Floating UI's behavior, which people know and its documentation describes, and the random oracle turns "port faithfully" into a test: the 12 placements, rtl mirroring, every option combination and the reset loops agree with the real library to the pixel quarter, including ties and the quirks (flip's persisted index, the arrow's single alignment reset). Keeping `computePosition` pure over rectangles lets the engine (ADR-096) place the element in the first frame and run it again on paint-only frames. Functional options in the order given are the shape the owner accepted; one optional options struct per function keeps `Flip()` and `Shift(8)` as short as Floating UI's and adds the long tail without new function names, and negated bools keep every zero value the default. The relayout of the engine replaces the measured reset because the box tree, not the position function, knows the element's natural size; the difference shows only when a middleware that depends on the size runs after size. Rendering is unchanged: every golden is bit-identical
