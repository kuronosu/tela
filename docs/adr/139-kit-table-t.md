# ADR-139: `kit.Table[T]`

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

`kit.Table[T]` (phase 10, T7; implements ADR-129's K9; follows ADR-130's recipe, part and harness rules; amends §10's "kit Table built on grid"). **Shape.** `Table[T any]{Rows []T, RowKey func(T) any, Columns []Column[T], Sort *SortState, DefaultSort SortState, OnSortChange func(SortState), Selected func(T) bool, Caption, AriaLabel string, Empty tela.Component, SortIcon, SortAscIcon, SortDescIcon tela.Icon, Class, TableClass, HeadClass, CellClass, CaptionClass string, Props tela.Child}`; `Column[T]{ID, Header string, HeaderContent tela.Component, Cell func(T) tela.Node, Sort func(a, b T) int, Sortable bool, Width string, Align ColumnAlign, Sticky bool, Footer tela.Component, FooterSpan int, Class, HeaderClass, FooterClass string, CellProps func(T) tela.Child, HeaderProps, FooterProps tela.Child}`; `SortState{Column string, Direction SortDirection}` with `Ascending`, `Descending` (the aria-sort tokens; the zero value is unsorted); `ColumnAlign` is `AlignLeft` (zero), `AlignCenter`, `AlignRight`. One type parameter: the key is `any`, as `h.Key` takes it (a non-comparable dynamic key panics there). A column's name is its `ID`, else its `Header`; dev mode panics on a missing `Cell`, a column with no name, duplicate names, a `Sticky` column after a plain one and a sticky column followed by another one without a px `Width`. **Sorting.** A column is sortable when it has a `Sort` func, or `Sortable` (rows that come sorted from a server: the table shows and reports the state and leaves the order). The header cell holds a ghost `kit.Button` (shadcn's data-table example: a ghost button with `ArrowUpDown` after the title) and `h.AriaSort` on the cell itself, as ARIA requires; the arrow is swapped by Go (arrow-up-down, arrow-up, arrow-down, Lucide, unexported `tela.Icon`s that the three icon fields replace). **The cycle is TanStack Table's default (the engine under shadcn's data table): ascending, descending, unsorted, and another column starts ascending (one column sorted at a time).** shadcn's demo only toggles ascending and descending, which leaves no way back to the data's own order; there is no option to drop the third state (open for the owner), and TanStack's "numbers start descending" is not copied (no `DescFirst`; also open). The sort is `slices.SortStableFunc` and descending negates the comparison, so equal rows keep the order of `Rows` in both directions. State follows ADR-101: `Sort *SortState` controls, `DefaultSort` starts, `OnSortChange` reports (also when uncontrolled); a controlled table that the caller does not update stays as it is. Rows are keyed by `RowKey`, so the state of components in a row's cells follows the row (tested with a counter); without it the key is the position. **Layout.** Tela has no table layout (§10), so the table is a grid: `role=table` element with `grid w-max min-w-full` (as wide as its tracks, at least the container, so that a sticky column's containing block is the whole scrolled width) and `grid-cols-[...]` from the `Width`s (`auto` by default; any track: `200px`, `1fr`, `minmax(120px_1fr)`, spaces in a Width become `_`), inside shadcn's container (`relative w-full overflow-auto`; `overflow-x-auto` there, and a CSS container with one scrolling axis scrolls the other as `auto` too, so the class is the same behavior). Rowgroups and rows are `display: contents` elements with the roles rowgroup and row, so the cells are the grid's items and columns align across rows (a grid per row could not align `auto` tracks); the paint that shadcn puts on `tr` and `tfoot` (the border under a row, `hover:bg-muted/50`, `data-[state=selected]:bg-muted`, the footer's `border-t bg-muted/50`) is on the cells, with `group-hover:` and `group-aria-selected:` of the row (a `group` that has no box), and the last body row's border is `border-b-0` as shadcn's `[&_tr:last-child]:border-0`. Cells are flex containers that center their content (`align-middle`), so a cell takes one node. **Semantics** as Playwright 1.61.1 prints an HTML table (compared by running Playwright on the markup and a div-based table with these roles): `table "caption"` with `caption: text` first, `rowgroup`, `row "A B"` (`[selected]` from `Selected`, which sets `aria-selected`), `columnheader` (a sortable one holds its `button`), `cell`; the caption is first in the tree and in the last grid row (`row-start-N`, since `order` does not apply in Tela's grid), and names the table through `aria-labelledby`; `AriaLabel` names a table with no caption. **Sticky.** The header cells are `sticky top-0 z-20 bg-background`, and a `Sticky` column's cells `sticky left-N z-10 bg-background` (`z-30` in the header: the corner), where N is the sum of the px widths of the sticky columns before it (parsed from `Width`, since the offset has to be known to build; measuring would lag a frame). A translucent hover or footer background would show what scrolls under a sticky cell, so these cells keep the opaque `bg-background` and layer the translucent color above it as a `bg-linear-to-r from-muted/50 to-muted/50` gradient (`StickyColumnHover`, `StickyColumnFooter`; selected is opaque already). The header's background is `bg-background`: on a card, set `HeadClass: "bg-card"`. **Recipe** `TableStyle`: `Root`, `Table`, `Header`, `Body`, `Footer`, `Row`, `Head`, `Cell`, `CellWithLastRow`, `FooterCell`, `Aligns map[ColumnAlign]string`, `HeadSticky`, `HeadStickyColumn`, `StickyColumn`, `StickyColumnHover`, `StickyColumnSelected`, `StickyColumnFooter`, `Caption`, `Empty`, `SortButton` (added to the ghost button's classes). Deviations from table.tsx at the pinned commit: `[&_tr]:border-b`, `[&_tr:last-child]:border-0`, `[&>tr]:last:border-b-0` and the row's classes move to the cells as above; `[&:has([role=checkbox])]:pr-0` and `[&>[role=checkbox]]:translate-y-[2px]` are not ported (there is no selection column; they arrive with a checkbox in a cell if needed); `border-b` is `border-b border-border`; the footer is one row (a column's `Footer` cell, `FooterSpan` for shadcn's `colSpan`; the row is drawn when any column has a `Footer`). Not in scope and absent: row selection, virtualization, column resizing, editing. **Conformance** (`kit/table_test.go`, Chromium 154 with Tailwind 4.3.3, shadcn's markup of the demo with a caption, a footer with `colSpan`, px columns and `1fr` columns, a selected row, no rows, and a sorted header with the data-table's button; the cells' own rectangles are probes, a table sits in a box of fixed height on both sides): Tailwind's preflight makes an HTML table `border-collapse: collapse`, where a row's border is half in the cell above and half in the one below and the table keeps half of its last one, so the cells' boxes differ from the grid's, where the border is inside the cell: **the widths and every cell's left and right edges agree within 0.02 px; the vertical edges differ by at most 1 px (a body row 37 px against 36.5 px for the last, the footer 37 against 36.5, a table 0.5 px taller in Chromium) and the text of a body row sits half a device pixel lower in Chromium (the half border above it), which at scale 1 is a row of pixels: mean difference per channel around a cell 4.5 to 5.8 (bound 6) at x1 and 2.5 to 3.2 (bound 3.5) at x2**. Differences from table layout that the sheet avoids on purpose: with widths in px (or equal `1fr` against `table-fixed`) and a container as wide as their sum the two agree; with `auto` columns a table gives the extra space to the columns in proportion to their content and a grid divides it equally (the shadcn demo's content-sized table, with no spare space, agrees: its columns are the max-content widths); the sheet adds `table-fixed` and `width` styles to shadcn's markup on those cells. Behavior tests: the cycle by click and by Space and Enter, stability both ways, controlled and uncontrolled state, `Sortable`, the aria snapshots, row state following rows, the empty row, the dev panics, the header and the sticky columns at the same place after scrolling down and right (`telatest.Scroll` and `Bounds`), the hovered sticky cell as opaque as a plain one; goldens for the sheet and a scrolled sticky table, light and dark at scales 1 and 2. **Measured** (1,000 rows by 6 columns, 6,000 cells, no virtualization, with the machine under a load of 30, so the wall clock is high): mount 0.2 s in the quietest run and up to 1.1 s under that load (0.36 s of CPU in the profile), a frame of 6,000 cells about 0.12 s of CPU (the paint phase records every cell, scrolled out or not: culling the paint of what a scroll container hides would be an engine change, open), a sort click one rebuild and layout of the same size. Fine for hundreds of rows; thousands want `h.VirtualList`, which a grid of rows that must align across rows does not use

## Rationale

The owner's K9 asked for a sortable, sticky table with no virtualization; a grid with `display: contents` rows is the only layout that aligns content-sized columns and lets the header and leading columns stick without a table layout. The ghost button is shadcn's own data-table header, the cycle is the one its engine has, and the opaque-under-translucent layering is what keeps a sticky column honest when hover and footer colors are not opaque. The Chromium check is of what can be compared (widths, positions, pixels) and the report says what a collapsed-border table makes impossible to match to the pixel
