# ADR-133: Menu bar and context menu hooks of package `aria`

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

Menu bar and context menu hooks of package `aria` (phase 10, T6; the hooks that the kit's Menubar and ContextMenu are built on, ADR-129; every public shape is listed for the owner's review; amends §14, ADR-101 and ADR-104). **`UseMenuBar[K comparable](MenuBarOptions[K])`** (the WAI-ARIA menubar pattern, with the rules of ADR-101's `UseMenuTrigger` and Radix's Menubar): `Keys`, `DisabledKeys`, `Disabled`, `Open *K` (controlled; a key that is not in `Keys`, such as `""`, means all closed), `DefaultOpen *K`, `OnOpenChange(key K, open bool)` (called with the menu that opens, or the one that closes; moving from one menu to another is one call, with the one that opens), `Direction`, `NoWrap` (the pattern wraps, so the zero value is the default), `AriaLabel`, `AriaLabelledBy`, `Ref`. The result has `Props` (`menubar`, `aria-orientation`, the name), `TriggerProps(k)`, `MenuProps(k)`, `PopoverOptions(k) PopoverOptions`, `MenuRef(k)`, `TriggerRef(k)`, `IsOpen(k)`, `SetOpen(k, open)`, `Open`, `OpenKey`, `FocusStrategy`, `Close` and `Ref`. **One hook for the bar, one menu rendered**: a hook cannot be called per key, and only one menu is open, so the open menu is a component of the caller's (keyed with `tela.WithKey(menu, bar.OpenKey)` so that each mounts anew and focuses its first item) that calls `UsePopover(bar.PopoverOptions(k))` and `UseMenu` with `Ref: bar.MenuRef(k)`, `FocusStrategy: bar.FocusStrategy` and `OnClose: bar.Close`, and puts `bar.MenuProps(k)` on the element (the ref, `aria-labelledby` the trigger, a focus scope with `Restore`, and the keys below). `PopoverOptions(k)` is a value to adjust (`Offset`, `Floating`): `bottom-start`, closed through the bar and **not modal**, because a modal popover makes the other triggers inert and hover could not switch menus; a press over any trigger's bounds is not an outside press, so it is the trigger's own. **Triggers**: `menuitem` + `aria-haspopup="menu"` + `aria-expanded` (+ `aria-controls` while open), a button type that is never a Form's default, a tab stop on the trigger that had the focus last (else the first enabled one: `rover`, ADR-132). Their press is the `presser` of ADR-100 built once per key (`pressState` per key in the hook; `usePressCore` is hooks and could not be called in a loop; `presser.handlers()` is the extracted part): a mouse or a pen opens on the press, a touch on the release, a virtual click with `FocusFirst`, and a press on the open menu's trigger closes it. **Keys** (APG, React Aria's menu trigger): ArrowLeft and ArrowRight move the focus (swapped by `rtl`, wrapping unless `NoWrap`, skipping disabled triggers), Home and End jump; ArrowDown, Enter and Space toggle the menu with `FocusFirst`, ArrowUp with `FocusLast`; with a menu open, ArrowLeft and ArrowRight in the menu (and on its trigger) close it and open the neighbor's on its first item, and hovering another trigger (not a touch) opens that menu with the menu itself focused; Escape and a primary press outside close it and the scope gives the focus back to the open menu's trigger; **Tab** focuses the trigger, closes the menu and leaves the key's default action alone, so the focus goes on from the bar's only tab stop (Shift+Tab backwards). A move first focuses the new trigger with `switching` set, so that the blur of the old menu (its popover's `ShouldCloseOnBlur`) does not close the menu that is about to open; the popover's `OnClose` only closes its own key. **Not included**: submenus (ADR-129), typeahead on the triggers and mnemonics (Alt+letter), both optional in the task. **`UseContextMenuTrigger(ContextMenuTriggerOptions)`** (the contextmenu event and Radix's ContextMenu; React Aria has none): `Open *bool`, `OnOpenChange(bool)` (ADR-101's rule; no `DefaultOpen`, a menu opens at a point), `Disabled`, `NoLongPress`, `Ref`, `MenuRef`; the result is shaped like `MenuTriggerResult` (`TriggerProps`, `MenuProps`, `Open`, `FocusStrategy`, `SetOpen`, `Close`, `Ref`, `MenuRef`) plus `OpenAt(x, y)`, `Anchor func() tela.Rect` (the virtual anchor, `AnchorRect`'s argument) and `PopoverOptions()` (an `AnchorRect(Anchor)` in `Floating`, `bottom-start`, flipped and shifted by `UsePopover`). `TriggerProps` has the ref, `h.OnContextMenu` (a right click: at the pointer, no item focused; prevents the default and stops propagation, so the innermost area wins), `h.OnLongPress` (a touch only, `PointerTouch`: at the finger with `FocusFirst`) and `h.OnKeyDown` (Shift+F10 and the ContextMenu key, not on repeat: `FocusFirst`, at the area's top-left corner); the position is a `tela.UseValue(tela.Rect)` that the handlers set and `Anchor` reads, so the menu is placed in the frame that shows it. `MenuProps` are the ref, a focus scope with `Restore` and a contextmenu handler that stops a right click on the menu from reaching the area (the menu has no `aria-labelledby`: the area is not a label; name it with `MenuOptions.AriaLabel`). The popover is **not modal**: a second right click on the area reaches it and moves the menu (the position Value changes and the float pass places it again), a primary press outside closes it. **Limits that need the engine, reported rather than changed**: (1) `OnInteractOutside` is primary-press only (`outsideDown`), so a right click outside the area leaves the menu open; (2) the long press is recognized for every pointer of the area (`OnLongPress` has no pointer filter), so a mouse button held 500 ms on the area or on a child button does not click (`NoLongPress` turns the gesture off); (3) `KeyboardEvent` has no target and there is no focused-element query, so a keyboard menu opens at the area's corner and not at the focused child. **Names the owner has not seen:** `UseMenuBar`, `MenuBarOptions`, `MenuBarResult`, `NoWrap`, `OpenKey`, `PopoverOptions` (as a method of both results), `MenuRef(k)`, `TriggerRef(k)`, `IsOpen`, `UseContextMenuTrigger`, `ContextMenuTriggerOptions`, `ContextMenuTriggerResult`, `NoLongPress`, `Anchor`, `OpenAt`

## Rationale

The kit's Menubar needs the pattern right once (roving focus, the switch between open menus, Tab, hover), and a context menu needs the pointer as an anchor, which `UseFloating`'s virtual rectangles (ADR-099) were made for. Both reuse `UseMenu`, `UsePopover` and the menu trigger's focus rules, so the menu rendered by a dropdown menu, a menu bar and a context menu is the same component. The bar is one hook with a rover and per-key presses because that is what a Go hook can be, as in ADR-132; the popover is non-modal because hover switching is the pattern, and the same choice lets a context menu be moved by another right click. Rendering is unchanged: every golden of the repository is bit-identical
