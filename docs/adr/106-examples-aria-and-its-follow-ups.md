# ADR-106: `examples/aria` and its follow-ups

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

`examples/aria` and its follow-ups (phase 8, T9a; amends ADR-100, ADR-101 and ADR-105). **Example.** `examples/aria` is a "Command center" screen built only from `aria` hooks, `h` elements and theme-token classes: a project combobox, a tooltip, two menus, a modal dialog with a form, tabs and a multiple-selection list box, with `Presence` entrances and exits; its keyboard-only tests (Tab, arrows, Enter, Space, Escape, typing) assert the full aria snapshots of the open menu, the combobox's listbox and the open modal dialog (the rest inert) and the focus restored after each, plus pointer tests, goldens at scales 1 and 2 in both schemes, damage and idle checks. Its Lucide icons are a subset copied into `examples/aria/icons` with Lucide's license and generated by `tela icons gen`, since the core module may not import `icons/lucide`. **Follow-ups (the owner's).** `h.AriaLabelledBy(refs ...tela.ElementRef)` is variadic (it calls `core.AriaLabelledBy`, which already took several; no reference panics with the fix); `ComboboxOptions.ButtonLabel` is the toggle button's accessible name (default "Show suggestions"), the only user-visible English string in `aria` (every other hook's names come from the caller's options). **Bug fixed: a Form's default button.** Enter in a text field presses the Form's first Button of type submit (`implicitSubmit`), and `h.Button` is type submit by default, as in HTML, so the first hook-made Button of a form (a select's trigger, a switch, a menu button, a plain `UseButton`) was pressed instead of the form being submitted: in the example's dialog Enter in the empty field opened the select. A press hook now gives its element the default type "button" (`core.DefaultButtonType`, a prop with no check on the element kind, read by `buttonType` after an explicit `Type`, which still wins whatever the order), or "submit" / "reset" when `ButtonOptions.Type` says so, as React Aria's `useButton` sets `type="button"`. A `Button` made with `UseButton{Type: "submit"}` stays the default button; one made with a Div is still not found by `implicitSubmit` (it submits a one-field form directly).

## Rationale

The example is the phase's done criterion for `aria`: the tests are what a keyboard user and a screen reader get, so they are kept to those (roles, names, states from the snapshot and `ExpectFocused`). The default-button fix follows HTML and React Aria rather than a new rule: the hook runs the activation itself (`ActivateButton`), so the element must not also be the form's default button. Rendering is unchanged: every golden of the repository is bit-identical. Gaps for the owner: `telatest` cannot read `aria-activedescendant`, `aria-controls` or `aria-haspopup` (the snapshot does not print them, as Playwright's does not), so the example checks the highlighted option by its class; `UseListBox` has no typeahead without `TextValue` while `UseSelect` defaults it to `fmt.Sprint` of the key; `Selection.Len` of "all" is 0 (use `len(sel.In(keys))`)
