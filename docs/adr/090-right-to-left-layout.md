# ADR-090: Right-to-left layout

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Right-to-left layout (phase 7, T7b; amends §9, §10, §11). **API:** `h.Dir(string)`, HTML's `dir` attribute (the conservative name, chosen without the owner): `"rtl"`, `"ltr"`, `"auto"`, ASCII case-insensitive so `Dir(i18n.Dir(loc).String())` works, `""` inherits, another value panics in dev mode and is ignored otherwise (as HTML ignores an invalid `dir`); not allowed on `Portal`, whose content inherits from where it is declared. There is no direction class (Tailwind has none). **Style:** `ComputedStyle.Text.Direction` is inherited (ADR-042's list grows by it) and set from `style.Input.Dir` before any class runs, so the `rtl:`/`ltr:` variants (a `Condition` part tested against the element's direction; Tailwind's `:dir()`/`[dir]` selectors amount to the same, since only `dir` sets it) and the logical utilities resolve when the style is computed, with the element's own direction as CSS maps logical properties: `ms me ps pe start end border-s border-e rounded-s rounded-e rounded-ss rounded-se rounded-es rounded-ee`, plus Tailwind v4.2's `inset-s inset-e` and the block-axis `mbs mbe pbs pbe inset-bs inset-be border-bs border-be` (top and bottom; no vertical writing modes); a logical and a physical class of one side follow class order (last wins), like every Tela class. **`dir="auto"`:** the first strong character (UAX #9 P2–P3 as approximated by `text.StrongDirection`) of the text below the element in tree order, skipping subtrees with a `Dir` of their own and text fields, or a text field's value; no strong character is left to right (HTML); auto elements are rechecked at the start of every style phase and after a field edit, and restyled when the result flips. **Core:** the direction becomes `layout.Style.Direction` (`internal/layout` already mirrors flex, grid, block and absolute layout like Chromium, with 53 Taffy RTL fixtures); `space-x-*` margins go on the child's inline end; the inline-block `text-align` emulation of ADR-044 uses the parent's direction; paragraphs and fields take it as their base direction (`text-start`/`text-end` and the default `start` alignment follow; `text-left`/`text-right` do not); an overflowing RTL `Input` line is aligned to the field (runs off to the left) and scrolls in [-overflow, 0]. **Scrolling:** an RTL scroll container keeps its internal offset in [0, max] measured from the right (layout's scrollable overflow is inline-start relative in RTL, so max is unchanged) and converts at every boundary (`scroller.flip`): the painted offset, user deltas (wheel, touch pan and fling, keys, thumb drag, track paging), `ScrollTo`/`ScrollBy`/`ScrollOffset`, `UseScroll`, `OnScroll` and `ScrollIntoView`, so public offsets follow the DOM (0 at the right, negative toward the left); the vertical bar and the classic gutter are on the left, the horizontal thumb starts at the right, a sticky box's scrollable area extends to the left. `tela inspect --layout` adds `"direction": "rtl"`. **i18n:** `i18n.Provider` does not set the direction (a context has no box, and adding one would change layouts); the idiom is `Div(Dir(i18n.UseFormatter().Dir().String()), ...)`, shown by `examples/i18n` (en, es, ar). **Not done:** `Dir` on an inline element inside a paragraph does not isolate its text (no implicit RLI/LRI/PDI), no `divide-x-*` (Tela has no `divide-*`), no logical sizes (`inline-*`, `block-*`), no `scroll-m*`/`scroll-p*` (none at all)

## Rationale

Browser semantics, with Chromium as the reference, where Tela has no reason to differ; resolving logical utilities in style keeps paint, hit-testing and transitions physical and unchanged, and converting scroll offsets at the boundaries keeps the scroll machinery's [0, max] invariant. Verified against Chromium 152: five new layout cases (flex rows, wrapping, grid placement, nested direction changes, absolute static positions) within 1/64 px; three Tailwind scenes in core (`TestChromiumRTL`: logical utilities, variants, `space-x`, grid, positioned and nested boxes; Arabic and mixed paragraphs with alignment, `dir="auto"` and inline chips; RTL scroll containers in three scroll states) with every horizontal edge within 0.05 px at scales 1 and 2 (boxes exact), vertical edges exact at scale 1 and within ADR-048's 0.5 px at scale 2, mean pixel differences 0.004–0.58 for boxes, 0.23–0.34 for the scroll scene and 0.95–1.27 for Arabic text (glyph anti-aliasing). Every existing golden is unchanged
