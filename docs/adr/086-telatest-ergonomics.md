# ADR-086: `telatest` ergonomics

- **Date:** 2026-10-20
- **Status:** Accepted

## Decision

`telatest` ergonomics (phase 7, T2b; the API is the owner's decision; amends ADR-059 and ADR-070). **Changed:** `(*App).Bounds(loc)` returns `tela.Rect` (window coordinates, the rectangle of `ElementRef.Bounds`) instead of `(x, y, w, h float32)`; the callers in the repository's tests were updated. **Added:** `MountFunc(tb, fn func() tela.Node, opts...)` = `Mount(tb, tela.C(fn), opts...)`; `(*App).GoldenScales(name, scales...)` compares one golden per display scale, `testdata/<name>_x<scale>.png` with the scale written `%g` (the naming of the examples' goldens), by moving the headless window to that scale (`Window.SetScale`, as a user dragging it between monitors: the logical size and the state are kept, the original scale is restored) and settling, so each picture equals an app mounted at that scale; `h.TestID(id)` and `telatest.ByTestID(id)` (Playwright's `getByTestId`): the id lives on the element's `desc` (`core.TestID`, rejected on `Portal` like the other props) and is read through `Tree.NodeTestID`, as `NodeClasses` is, so it is **not** a field of `semantics.Node` and never reaches the aria snapshot, `tela inspect` or the platform accessibility API; `ClickAt(x, y, ...ClickOption)` and `DragFromTo(from, to tela.Point, ...DragOption)` act at window coordinates in logical pixels with the same real pointer events as `Click` and `Drag` and fail when a point is outside the window; `PixelAt(x, y) color.RGBA` reads the device pixel that contains the logical point, `(floor(x*scale), floor(y*scale))`, of the settled frame (alpha-premultiplied as stored); `Measure(f) Stats` settles, runs `f`, settles like an action (`NoSettle` respected) and returns the field-wise difference of `Stats`; `Expect(loc, states...)` with the `State` values `Checked`, `Pressed`, `Selected`, `Expanded` (a `bool` each; an element without the toggle, or `mixed`, never satisfies it, and the message names the `h.Aria…` prop that sets it), `Disabled`, `Focused`, `HasName` and `HasValue`: it auto-waits like the other expectations, requires one match, and its failure shows the unmet states, the element's actual states and its line of the aria snapshot. `ExpectValue` and `ExpectFocused` stay (`HasValue` and `Focused(true)` overlap them)

## Rationale

Tests stop matching strings of aria snapshots for state, and the common one-component test, a golden per scale and an assertion on how narrow an update was are one call each. A `Rect` instead of four results because it composes (`r.Right()`, `r.Contains`) and is what `ElementRef.Bounds` and `UseBounds` already return. The test id is on the element rather than in the semantics node so that nothing of it can leak to consumers of the tree. `GoldenScales` re-renders the live app instead of mounting a new one so the state a test built up is kept; the pictures equal fresh mounts (checked in a test)
