# ADR-102: Icon generator and the Lucide module

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Icon generator and the Lucide module (phase 8, T6; E2, E3 and the one-variable-per-icon shape are the owner's; amends §5, §17 and ADR-098). **Generator.** `tela icons gen -pkg <name> [-o outdir] [-r] [-prefix text] [-suffix text] [-skip-invalid] [-minify=false] [-source text] [-license name] [-license-file file] [-deprecated file] <dir>` (CLI flags are public API, ADR-049) reads the `*.svg` files of `<dir>` (case-insensitive extension, dot files ignored, subdirectories with `-r`) through `internal/icongen` (the engine; `cmd/tela` stays a thin command, needs no `go` command or module) and writes `outdir/icons_gen.go`: a `// Code generated by tela icons gen; DO NOT EDIT.` header, the `Source:`/`License:` lines and the license text from the flags, a package documentation (count, source, license, an `h.Icon` example, the note that there is no table), `import "github.com/kuronosu/tela"`, and for each icon, sorted by variable name, a doc comment (`// ArrowUp is the icon "arrow-up".`) and `var ArrowUp = tela.Icon{SVG: "…"}` (a raw string literal; an interpreted one when the text has a backtick, a carriage return, a NUL or a BOM), through `go/format`; the output is the same on every run (golden test, `internal/icongen/testdata/demo_icons.go.txt`) and nothing is written when a file fails. **Deprecated names** (amended, T6b): `-deprecated file.json` takes a JSON object from the name of an icon (its file name without `.svg`, slash separated) to the name of the icon that replaces it (`{"alert-circle": "circle-alert"}`); the variable of each listed icon gets a second paragraph in its documentation, `//\n// Deprecated: use CircleAlert.`, so gopls and staticcheck flag its uses, and the file is still generated. A name that is not an icon of `<dir>`, a replacement that is not one, a name deprecated in favor of itself and a chain (the replacement is deprecated too) are errors listing all of them; the flag is the whole interface (no format other than this object). **Validation:** every file is parsed with `internal/svg.Parse`, the parser behind `tela.ParseSVG` (same errors), not with `tela.ParseSVG` itself, so that the CLI does not link the whole engine and the root package stays out of `cmd/tela`; failures are listed with their paths (50 at most, then a count) and stop the command unless `-skip-invalid` leaves them out with a warning; two files that make one name are always an error (listing all of them: skipping one would hide an icon). **Minifier** (`icongen.Minify`, `encoding/xml` raw tokens, written back with its own escaping): drops the XML declaration, processing instructions, comments and the DOCTYPE; elements and attributes in namespaces other than SVG and XLink (Inkscape, Sodipodi, RDF, Illustrator) and the namespace declarations that nothing uses; `metadata`, `title` and `desc` (Tela reads none of them; icons are `aria-hidden` or labelled by `AriaLabel`) and empty `defs`; `class` (unless the document has a `style` element, whose selectors may use it), `id` unless some attribute or text mentions `#id`, `version`, `baseProfile` and `data-*`; white space between elements, and runs of white space in `d`, `points`, `viewBox`, `transform`, `gradientTransform`, `patternTransform`, `stroke-dasharray`, `preserveAspectRatio`. It keeps the text of `text`, `tspan`, `textPath`, `style` and `script` as written, keeps the attribute order, and returns a document that declares entities (an internal DTD subset) unchanged (trimmed). `width` and `height` stay (the file keeps its intrinsic size for `Img` uses). **Equivalence check:** after minifying, `icongen.Equivalent` parses both documents and compares the intrinsic size, size, viewBox, clipping and currentColor use, and the printed display lists (every number exact) in three boxes (24×24, a fractional offset at 16, a wide one) with four option sets (currentColor black and red, the root overrides of `fill-current`/`stroke-none`, and fixed `fill`, `stroke`, `stroke-[1.5]` and `color`); a difference fails the file (`-minify=false` is the escape hatch). Tests run it on the 35 SVG files of the `internal/svg` Chromium galleries (gradients, clip paths, masks, `use`, style sheets, `switch`, entities) plus the generator's own inputs, and check that the minifier is idempotent. **Names** (`icongen.VarName`): the path without `.svg` is split at every character that is not a letter or digit, each piece is capitalized (`arrow-up` is `ArrowUp`, `volume_2` is `Volume2`, `solid/arrow-up` is `SolidArrowUp`), an underscore keeps apart digits that were apart (`arrow-down-0-1` is `ArrowDown0_1`, `arrow-down-01` is `ArrowDown01`: Lucide has both, as an icon and an alias, and without the rule they collide), a name that does not start with an upper-case letter gets `Icon` in front (`3d-rotate` is `Icon3dRotate`, `日本` is `Icon日本`), `-prefix` (an exported identifier start) and `-suffix` go around; Go keywords cannot occur (names are exported, hence capitalized) and are tested. **The Lucide module.** `icons/lucide` is a separate module, `github.com/kuronosu/tela/icons/lucide`, generated from `lucide-static` 1.61.0 (npm; integrity `sha512-yLAiQB3M…`; 2,171 files, 1,902 distinct drawings: Lucide keeps renamed icons as aliases with the same drawing, and all are generated since an unused variable costs nothing, but the 268 old names, 2,171 minus the 1,903 keys of the package's `icon-nodes.json`, are marked `// Deprecated: use X.` through `-deprecated deprecated.json`; the file, committed in the module, is written from the package by `gen_deprecated.go` (`//go:build ignore`, run first by `go generate`), which reads the old names from the SVG files that are not keys of `icon-nodes.json` and the icon that replaces each from the `export { default as Old, default as New } from './icons/new.mjs'` lines of `dist/esm/lucide-static.mjs`, and fails when one has no replacement; `TestDeprecatedNamesPointAtTheCurrentIcon` checks that every name of the file carries the comment, that it points at a declared variable of the right icon that is not itself deprecated, and that no other variable carries one): `icons_gen.go` (957 KiB with the deprecation comments, SVG data 775 KiB after minifying from 1,029 KiB), `gen.go` (`const Version = "1.61.0"` and the `go:generate` line, which reads the SVG directory from `$LUCIDE_ICONS`; a test checks that the header and `Version` agree, and regenerating from the same package gives an identical file), Lucide's `LICENSE` (ISC with the Feather MIT notice, copied unchanged and into the header of the generated file), `README.md` (usage, versions, regeneration with `npm pack --ignore-scripts`), and tests. Its `go.mod` requires `github.com/kuronosu/tela v0.8.0` (the first release with `tela.Icon`, the phase-8 tag of ADR-049; a placeholder until that tag exists) with `replace github.com/kuronosu/tela => ../..`, which dependents ignore; no `go.work` is committed (the replace is enough for `cd icons/lucide && go test ./...`, and workspace mode ignores replace directives, which would hide a require that dependents cannot resolve). At the repository root a directory with its own `go.mod` is outside `./...`, so `go build`, `vet`, `test` and `staticcheck ./...` skip it and nothing in the root module imports it (the module may import `tela`, `h` and `telatest`, never `internal/`). The package has one exported variable per icon and no table by name (the owner's measurement: the linker drops the unused variables, a map links all of them, +0.9 MB for 1,600 icons). **Versioning:** the module's tags mirror Lucide's release: `icons/lucide/vX.Y.Z` holds the icons of Lucide `X.Y.Z` (Go's tag scheme for a module in a subdirectory); agents never create or push them (ADR-049). A regeneration without a new Lucide release (a change of the generator or of the comments only) is published as the pre-release `icons/lucide/v1.61.0-tela.N` (`N` from 1), which Go orders before `v1.61.0` and `@latest` picks only while no release exists, so it is asked for by version; the next Lucide release goes back to `vX.Y.Z` (amended, T6b). Other sets (Heroicons, Tabler…) are added the same way, with the generator and their own module. **CI:** a job `icons-lucide` runs `go vet` and `go test` there with `CGO_ENABLED=0`, and builds it for windows and darwin; the root jobs are unchanged (unverified until pushed). **Conformance** (the phase's criterion, `icons/lucide` `TestChromiumLucide`): the 1,902 distinct icons in a 64-column grid of 32 px cells (2048×960 px), `h.Icon` with `size-[24px]` and `text-[#1e293b]` through `telatest.Mount` at scales 1 and 2 (16 px was measured too, at first; amended, T6b: only 24 px stays in the module), against Chromium 154 showing the same markup inline with the same CSS (`display: block`, a flex-wrapped grid); the screenshots are committed in the module (`testdata/chromium`, 2.0 MB: 24 px at x1 and x2; 3.6 MB with the 16 px ones) with a digest of the icons that makes the test fail when they are old; `TELA_CHROMIUM=1` takes them again (the pages are made in a temporary directory, not committed: 600 KiB each), `TELA_CHROMIUM_DUMP=dir` writes Tela's renderings and the 40 worst cells side by side (Tela, Chromium, difference). It lives in the module and uses only public API (`telatest`, `h`), which keeps Lucide out of the root module and its screenshots out of its tests. Measured, mean difference per RGB channel over a cell (average of the 1,902 icons, median, p99, worst; the 16 px numbers were measured once and are no longer in CI): 16 px x1 0.93, 0.91, 1.77, 2.17 (Flower); 16 px x2 0.52, 0.52, 0.94, 1.11 (Bacon); 24 px x1 0.91, 0.72, 2.50, 3.10 (Grape; Goal, Target, Shell, Moon follow); 24 px x2 0.55, 0.49, 1.34, 1.76 (LayoutGridCircles). As a share of the ink (sum of the differences over the reference's darkness): 16 px x1 6.7% on average (worst 21%), x2 3.7% (10.4%); 24 px x1 3.0% (11.7%, Moon), x2 1.8% (5.5%). The largest single-pixel differences are up to 128 levels (Squirrel at 16 px x1; 110 at 24 px), on anti-aliased edges. The worst icons are circles, rings and curved shapes at scale 1 (Skia's coverage of curves against exact area coverage, as in ADR-095), and small details at 16 px; looking at the 40 worst cells at 24 px and scale 1, the differences are faint outlines along curves, and no icon is displaced, thicker or missing. The test bounds, for 24 px, are 1.05 on the average mean, 3.5 on any icon's mean and 16% of the ink (25% while 16 px was checked). **Binary size** (a Tela program with a `Div` and a `Text`, Linux amd64, `CGO_ENABLED=0`): stripped (`-s -w`) 19,873,952 bytes with no icon, the same importing the lucide package without using it and with `lucide.Check`, 19,902,624 bytes (+28,672, 28 KiB) with 50 icons; unstripped 25,036,308, 25,036,252 (import only), 25,036,279 (1 icon) and 25,069,127 (+32,819) bytes. **Docs:** wiki page Icons (using `h.Icon`, Lucide, the generator and its flags, the size note), the CLI page and Home/_Sidebar, `THIRD_PARTY.md` (Lucide ISC and Feather MIT, redistributed as data), CHANGELOG. **Not done / for later:** `tela icons gen` writes one file (no splitting), the sources of a set are not committed (npm integrity is recorded), no by-name lookup (a user builds a map of the icons they use), and the CI job is unverified until pushed.

## Rationale

The owner's decisions: Lucide separate from the core module, a public generator, one static variable per icon. A nested module keeps the core free of 957 KiB of icon data and of Lucide's releases; the generator being a `tela` command lets anyone build the same set from Heroicons, Tabler or their own SVGs. Minifying with an equivalence check, and not by regex, keeps the data small without a risk of changing a drawing: none of Lucide's 2,171 files needed the escape hatch, and what cannot be proved equal is rejected. Comparing every icon, not a sample, was possible because the whole set renders in about a second per size and scale; it shows the renderer is within about one level of Chromium on average and three at worst for an icon set, the phase's criterion
