# ADR-089: Theme tokens, scoped color schemes and class aliases

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Theme tokens, scoped color schemes and class aliases (phase 7, T4; implements §10 "Theme and tokens"; the token names and the API shape are the owner's; amends ADR-042 and ADR-077). **Tokens** are shadcn/ui v4's names (`background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent` and their `-foreground`, `destructive`, `border`, `input`, `ring`, `chart-1`…`chart-5`); `style.Theme.Tokens` maps them to a light and a dark value, the default being shadcn/ui's neutral theme of its theming docs converted with `gfx.OKLCH` (extended sRGB, ADR-046; the colorful chart values of the docs, not the grayscale ones of its registry). Every color utility takes a token like a palette color (`bg-`, `text-`, `border-*`, `outline-`, `ring-`, `ring-offset-`, `inset-ring-`, `shadow-`, `inset-shadow-`, `drop-shadow-`, `text-shadow-`, `decoration-`, `caret-`, `from-/via-/to-`; `fill-`, `stroke-`, `divide-`, `accent-` stay unsupported), with `/NN` and every variant; unlike palette colors (ADR-042: resolved at parse time) a token stays symbolic in the compiled rule (`colorSpec.token`, opacity in its alpha) and `Compute` binds it before combining colors, for the element's scheme, so compiled classes serve both schemes and a scheme change only restyles; tokens are rejected inside arbitrary values, which resolve at parse time. **Scheme scoping**: `ComputedStyle.Scheme` (inherit, light, dark) is inherited and set by `Input.Scheme`; `IsDark` gives the override or `Context.Dark`, used by `dark:`, tokens and the scrollbars; core passes the primitive's `h.Scheme(tela.Light/Dark)` prop (`desc.scheme`; `System` removes it; rejected on `Portal`, whose content follows its position), a change restyles the subtree (`restyleChildren` when `Scheme` differs, without layout) and marks the components below that read the scheme. The element with the prop uses the scheme itself (shadcn's `dark` variant, `&:is(.dark *)`, only matches inside it; Tela's `dark:` matches on it too). `UseColorScheme` now returns the scheme at the component's position (the nearest primitive ancestor with the prop, else the Tree's Value), and so does **`UseTheme() ThemeValues`** (`Color`, `Lookup`, `Scheme`, `Radius` = the `rounded-lg` radius, `FontSans`, `FontMono`, `Tokens`; `Color` also takes palette names and panics in dev mode for an unknown name, with the closest token); both mark their hook slot (`schemeSlot`) so that a prop change finds them, and read the Tree's theme Value. **Theme** (`tela.Theme{Colors map[string]SchemeColor; Radius float32; FontSans, FontMono string}`, `core.Theme` has the same fields so both `tela` and `telatest` convert it; `SchemeColor` is an alias of `style.SchemeColor`): `App.Theme` nil is `DefaultTheme()`; colors merge over the default tokens (the shadcn names always resolve); a name must be lowercase letters, digits and inner dashes and not a palette color or `transparent`/`current`/`inherit` (Run and NewTree panic); `Radius` (logical px; 0 keeps Tailwind's scale, so the default theme changes no existing page) sets `rounded-sm/md/lg/xl/2xl/3xl/4xl` to 0.6/0.8/1/1.4/1.8/2.2/2.6 × radius, shadcn v4's current theme CSS (equal to the older −4/−2/0/+4 px rule at its 10 px default), leaving `xs`, the bare `rounded`, `none` and `full`; `FontSans`/`FontMono` are prepended to the `sans`/`mono` family lists (the root text uses `sans`). `tela.SetTheme(t)` (any goroutine, routed like `SetColorScheme`) gives the Tree a new parser with the same aliases, recompiles every element's classes, restyles everything and rebuilds the `UseTheme` readers. **Class aliases** (`App.ClassAliases`, `style.NewParserAliases`): an alias expands where it appears, in the parser before interning; the variants written before it are prepended to every class of its expansion (conjunction with the expansion's own variants), aliases nest, a cycle is an `InvalidClassError`, errors inside an expansion are wrapped in `AliasError` naming the alias written in the class, an alias wins over a utility of the same name, and alias names join the suggestion vocabulary; keys with whitespace, colons, brackets or a leading `-`/`!` are rejected. `telatest.Theme(t)` and `telatest.ClassAliases(m)` configure mounted apps and the headless entry points

## Rationale

The owner's API; shadcn/ui's names because LLMs write them. Measured against Chromium 152 with Tailwind v4.3.3 and shadcn's v4 CSS variables (`internal/core` `TestChromiumTheme`: a card with title, description, field, outline and primary buttons, badges, a focus ring and the chart colors, in a light panel and a `Scheme(Dark)`/`.dark` panel, radius 10): every element's box within 0.039 px at x1 and 0.023 px at x2; mean 0.83 (light) and 0.80 (dark) levels per channel at x1, 0.95 and 0.93 at x2, all of it on glyph edges (Skia's text anti-aliasing) and corner pixels; flat token colors (26 samples: page, card, buttons, field, badges, charts, both schemes, including `bg-input/30` and `bg-accent/60`) are equal but for one channel one level off. Existing goldens are bit-identical: palette colors are still resolved at parse time and no existing class used a token name. Binding tokens costs one pass over the 19 color slots per style computation
