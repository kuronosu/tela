# ADR-113: Dev-loop state

- **Date:** 2026-10-22
- **Status:** Accepted

## Decision

Dev-loop state: capture and restore (phase 9, T2; implements the "State" part of ADR-111 in `internal/core`; the API is core-internal, for the child runtime of T3; amends §7). **Build tag.** The code is in `internal/core/devstate*.go` and `internal/text/edit/devstate.go`, built only with `teladev`; `devstate_off.go` makes `devStateEnabled` false and stubs the hook points, which the compiler removes: slot creation in `useStateSlot`, `UseReducer`, `UseValue`, `UseRef` and `useMotion`, the end of a component's first build (`Tree.build`), the first `Mount`, `Frame` after the scroll phase, `NewHost`, `Tree.SetColorScheme` and `Tree.SetTheme`. A tree's dev state lives in `Tree.locals`, so no type gains a field. An untagged test checks `devStateEnabled` and that `go list -deps` has no `encoding/gob` without the tag (and has it with the tag); a `-trimpath` build of `examples/dashboard` has the same 13,771 symbols with the same sizes as before the change (only build info and pclntab line numbers differ). **API.** `(*Tree).CaptureDevState() ([]byte, DevStateReport, error)` on the UI thread; `CaptureAppDevState(done)` from any goroutine, run on the app's UI thread after the updates queued before it (routed like `Post`); `SetDevSeed(data)`, process-wide, taken by the next `NewHost` (so `Run` mounts with it), and `(*Tree).SeedDevState(data)` before `Mount` for headless trees (after `Mount` it warns and does nothing; nil or empty seeds nothing); `(*Tree).DevSeedReport()`; `RegisterDevState(name, save, restore)` for state outside the tree, saved into the same snapshot and restored before the tree mounts: T3's `App.DevState`, and package i18n's locale, which lives in i18n's process-wide store rather than in hook state (`UseLocale`'s slot is kept, but its effect catches up with the process locale, so a runtime `SetLocale` is lost unless i18n registers it). **Identity.** A slot is its component's path, its index and its signature entry. The path is the Elements from the root, each a step: its type and its key, or without one the (scope, position) reconcile matches by. A component's type is `S:` and its struct type's full name; `F:` and its function's runtime name without closure numbers, `[...]` and `-fm` (`app.Main.func3` is `app.Main.func`: the compiler renumbers the literals of a function when one is added before, and position and signature tell them apart, as for an edited component); `X:` and the context's type for a Provider; `Presence`. A primitive's type is its tag. A key is its full type and `%#v` (a pointer key never matches across processes). A signature entry is the hook's kind (dev mode's record, else the slot's storage kind) and the value's full type with package paths (`UseState[example.com/app.Item]`). Tests simulate an edited function with a test-only alias map of identities (`devIdentAlias`): two functions of one binary cannot share a name. **Signature rule.** A slot is seeded when the component's first build creates it: the signature entries up to it must equal the saved ones, then its saved value is decoded into it. After that build the whole signature is compared: a component whose hooks changed (one added, removed, moved or retyped) drops its saved node, so its subtree mounts fresh, and when some slot was already seeded it builds again from scratch before its result is reconciled and its effects are queued, so mixed state never reaches the screen or an effect; the initializers of that first build (`UseOnce`, `UseMemo`, `UseID` numbers) run twice, effects once. A saved node is taken by the first Element that resolves it; seeding lasts for the first `Mount` and the first 4 frames (the items a VirtualList builds at a restored offset, components shown after a measurement), then the snapshot is dropped. **Keepable rule.** Decided by reflection on the slot's type, cached per type: booleans, numbers, strings, slices, arrays, maps, pointers (flattened: aliasing is lost) and structs of exported keepable fields are kept, and so are types with GobEncode/GobDecode, MarshalBinary/UnmarshalBinary or MarshalText/UnmarshalText (`time.Time`); funcs, channels, unsafe pointers, unexported fields and struct types without exported fields (gob rejects them, `map[K]struct{}` included) are not. Interfaces and types that can hold themselves are also checked on the value: the dynamic value must be keepable (and registered by the app with `gob.Register`, as gob requires), and a cycle is not kept. Each slot is encoded alone: a tag byte, then a varint, the bits or the bytes of a basic kind, or gob. A slot that cannot be kept resets, and dev mode warns once per slot in the dev session (the warned keys travel in the snapshot): `tela: Counter's UseState #2 holds a func() int; it resets on reload (called at app.Counter (counter.go:12)). tela dev keeps what encoding/gob encodes in full: ...`. Reported without a warning: Tela's own types that cannot be kept (the handles `Setter`, `Callback`, `Dispatcher`, `*Value`, `ElementRef`, `Node`, `Prop`, the internal state of Tela's hooks, or a user struct holding one), so a `UseRef` of an `ElementRef` resets silently and the new element attaches it again; and the pointer-following state of `aria.UseHover` and of the press hook (recognized in dev mode by the function that created the slot). **Animations.** A matching `UseSpring` or `UseTween` slot starts at rest at its target, not at `Initial`; a `UseValue` that `Animate` moves is kept at its target; a scroll animation keeps its target offset; CSS transitions and layout animations do not run at mount; effects run again. **Engine state**, keyed by the same paths: the value, selection and undo/redo history of uncontrolled text fields (`edit.Editor.DevState` and `RestoreDevState`, which drops a history that does not fit the value and starts with a closed undo group) and an Input's own horizontal scroll; the selection and history of a controlled or bound field that shows the saved value; the offsets of scroll containers, the viewport and Textareas, set after the first layout and tried again for 4 frames while the content is shorter; the focused element and the focus-visible heuristic, given back before the first style phase without focus events and without scrolling it into view (the Fast Refresh view: the focus did not move; `OnFocus` fires when the window gains the focus), replacing a pending AutoFocus; the color scheme and theme set at run time with `SetColorScheme` and `SetTheme` (the app's configured ones are not saved, so editing them in code shows). Exiting `Presence` children are not kept. **Format.** `"tela-devstate\0"`, a version byte (1), then gob of a tree of the Elements with state below them, with interned identities and signature entries; a foreign, other-version, truncated or damaged snapshot starts the tree fresh with one warning and never panics. **Reports.** `DevStateReport`: slots kept, the slots reset with component, hook, index, type, reason and whether silent, text fields, scroll offsets, focus, extra state and size, with `String()` for one log line; `DevSeedReport`: slots restored, components remounted with the first differing signature entry, saved components with state that nothing took. **Measured** (Core Ultra 5 125H): `examples/dashboard` after a few interactions (637 Elements, 78 components, 10 kept slots, 3 KB): capture 0.07 ms, decoding and seeding 0.17 ms over a 1.4 ms mount; 10,000 keyed rows of 3 slots (about 50,000 Elements, 30,000 slots, 492 KB): capture 16.6 ms, decoding and seeding 15 ms over a 155 ms mount. **Known limits.** A renamed or moved component function resets; unkeyed siblings after an insertion shift position and reset (React's rule); interface values need `gob.Register`; Tela's types with unexported fields (`aria.Selection`) reset silently; a VirtualList's measured sizes are not kept (the offset is restored on its estimates); `OnScroll` fires once for a restored offset; a password field's text is kept (in memory, between local processes)

## Rationale

Fast Refresh's rule, identity by component path plus hook signature, is what users know. Seeding as slots are created lets initializers and children see the restored state, and discarding a build whose signature turns out different keeps a mixed state off the screen and out of effects. Checking types before gob keeps its silent drops (unexported fields) from passing for kept state, and one warning per slot per session keeps reloads quiet. Keeping everything behind the tag and in `Tree.locals` leaves the code of release binaries unchanged
