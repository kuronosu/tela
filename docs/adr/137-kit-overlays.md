# ADR-137: `kit` overlays

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

`kit` overlays: Dialog, AlertDialog, Popover, Tooltip and the trigger-slot rule (phase 10, T5a; builds on ADR-129, ADR-130 and the hooks of ADR-101). **The trigger-slot rule (one for every kit overlay, menu, select and picker).** A `Trigger` slot is a `kit.Trigger`: a component with one method, `WithTriggerProps(tela.Prop) tela.Component`, that returns itself with the props of the trigger merged onto its root element after its own (Radix's `asChild`: the overlay does not wrap the trigger, so the button the app wrote is the one with the press, `aria-haspopup`, `aria-expanded`, `aria-controls`, the ref the overlay is placed against and the hover of a tooltip). `kit.Button` implements it (an unexported `trigger` field applied after `Props`); an app's own component implements it with the method; any other element is made one with `kit.TriggerFunc(func(p tela.Prop) tela.Node)`, which is called as a component of its own, so it may use hooks. A type that is not a `Trigger` does not compile in the slot, and an empty slot (nil) opens the overlay from its state alone. Only one overlay can sit on one trigger element (each puts its own `h.Ref` there, and two refs panic in dev mode, ADR-101). **Dialog** `kit.Dialog{Trigger, Title, Description, Children, Footer, ShowClose, CloseIcon, CloseLabel, AriaLabel, Open *bool, DefaultOpen, OnOpenChange, Class, OverlayClass, HeaderClass, TitleClass, DescriptionClass, FooterClass, CloseClass, Props}` is `UseOverlayTrigger`, a dismissable modal `UseOverlay` and `UseDialog` in a `Portal` and a `Presence`: the page is inert, Tab is contained, Escape and a press on the scrim close it, the focus is restored; the panel exists only while open, so its state starts afresh; the description is the dialog's `aria-describedby` (`h.AriaDescribedBy`). `ShowClose` is off by default (shadcn's `showCloseButton` is on): the zero value of a Go bool cannot default to true, and the owner named the field `ShowClose`; the X is Lucide's, declared in `dialog.go` as an unexported `tela.Icon` (ISC, `THIRD_PARTY.md`) and replaceable with `CloseIcon`. **AlertDialog** adds `Cancel`/`Action` (label slots, "Cancel" and "Continue" by default, drawn as `kit.Button`s: outline and default or destructive), `Destructive`, `OnAction`, `OnCancel` and `Size` (default or `Sm`, the pinned commit's `size`); role `alertdialog`, not dismissable by a press outside (Escape closes it, without calling either handler), first focus on Cancel. shadcn's `AlertDialogMedia` is not ported. **Popover** `kit.Popover{Trigger, Children, Placement, Align, Offset, Modal, AriaLabel, Open..., Class, Props}`: `UsePopover` plus `UseDialog` on one ref (role `dialog`, the focus goes in and comes back), non-modal by default, `Placement` a side (`bottom`) or a full Floating UI placement, `Align` `start`/`center`/`end` (a typo panics in dev mode with the closest), `Offset` 0 meaning shadcn's 4 px and `kit.NoOffset` (-1) none. **Tooltip** `kit.Tooltip{Trigger, Content, Placement (top), Align, Offset (0), Delay, Disabled, Open..., Class, ArrowClass, Props}`: `UseTooltipTrigger` with `Delay` 0 meaning none (shadcn's provider default; `aria`'s 1.5 s is `Delay: 1500*time.Millisecond`), the close delay and the group warm-up of `aria` (per window, so no provider is needed), the arrow of `UseFloating` sunk 2 px into the tooltip (Radix puts the arrow's center 2 px inside the edge, Floating UI on it) by a per-side margin of the recipe. **Recipes** (`kit.Style` gains `AlertDialog`, `Dialog`, `Popover`, `Tooltip`): `DialogStyle{Positioner, Overlay, OverlayExit, Root, Exit, Header, Title, Description, Footer, Close, CloseIcon}` (`Root` is the dialog element; shadcn centers it with `fixed top-[50%] left-[50%]` and a translation, here the `Positioner`, a fixed flex layer with `p-4`, centers it, which gives the same box and keeps the panel's own transform for the entrance; the scrim is `absolute inset-0` inside it), `AlertDialogStyle` (the same, `Sizes`, `HeaderSizes`, `FooterSizes` for the `data-[size=...]` classes), `PopoverStyle{Root, Exit, Sides}` and `TooltipStyle{Root, Exit, Sides, Arrow, ArrowSides}`, where `Sides` (keyed `top`, `right`, `bottom`, `left`) holds the transform origin and the 0.5rem slide-in start of shadcn's `data-[side=...]:slide-in-from-*`, chosen by the side the element is on. Entrances are `transition` plus `starting:` classes and exits are `Exit` classes in a `Presence` (`animate-in`/`animate-out` become transitions of 150 ms, 200 ms for dialogs). **Deviations:** the classes of `DialogContent` are shadcn's minus its positioning; the max width is `max-w-lg` (the 1 rem of room on each side is the positioner's padding, so below `sm` the panel is `100% - 2rem` wide as shadcn's `max-w-[calc(100%-2rem)]`), so a `sm:max-w-[425px]` ported from shadcn's docs still wins above `sm`; the close button's `data-[state=open]:` classes (Radix's Close has no state) are dropped; `text-balance` parses as plain wrapping (the engine does not balance lines; the Chromium cells of wrapped tooltips leave it out of the markup); an alert dialog does not keep the focus on a press on the scrim (the press lands on the window root and the focus goes nowhere until Tab, which the contained scope brings back inside), a gap of the engine's focus containment. **Conformance** (public API plus `StaticDialog`, `StaticAlertDialog`, `StaticPopover` and `StaticTooltip` of `kit/overlay_export_test.go`, which return an overlay's panel in the flow of a cell with its real classes and element tree, because a Chromium cell cannot hold a Portal; the markup is shadcn's `cn()` output without the positioning and `data-[state=...]` classes; the harness `cn` gains the `max-w` group): sheets `dialog` (5 cells), `alertdialog` (4), `popover` (3) and `tooltip` (4) in light and dark at scales 1 and 2: box edges differ by at most 0.012 px at x1 and 0.004 px at x2 (Dialog, AlertDialog and Popover 0.000); mean pixel difference per channel around a cell, worst cell at x1/x2: Dialog 1.14/2.12, AlertDialog 1.01/1.03, Popover 1.63/1.35, Tooltip 4.00/1.72 (three lines of white text on black, bound 4.5 at x1); plus window goldens of each overlay open (`<name>_open_<scheme>_x<scale>.png`), behavior tests in telatest (open and close by pointer and keyboard, Escape, outside press, inert page, Tab containment, focus restore, controlled and uncontrolled, the three ways to make a trigger, placement with flip and shift, delay, warm-up, keyboard focus, arrow pixels, aria snapshots), runnable examples, and idle tests: an open overlay requests no frames once its entrance ends.

## Rationale

The owner's slots (ADR-129) need the overlay to reach the element the app wrote, and a method on the component is the shortest rule that keeps types honest and stays out of the engine (no way to apply a `Prop` to an arbitrary `Node` exists, and a wrapper element would put the role, the tab stop and the name on the wrong box); the same rule serves the menus, selects and pickers that follow. The positioner keeps shadcn's look with the layout Tela has already tested for the same overlays in `examples/aria`. Every existing golden is bit-identical
