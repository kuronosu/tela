# ADR-174: `tela mcp`

- **Date:** 2026-10-26
- **Status:** Accepted

## Decision

`tela mcp [pkg] [--size WxH] [--scale N] [--dark] [--preview NAME]` is a Model Context Protocol server over stdio (JSON-RPC 2.0, one message per line; `initialize`, `ping`, `tools/list`, `tools/call`; written on `encoding/json`, no new dependency) that drives one **headless** instance of the package's screen, the one `tela snapshot` renders (phase 11; amends §17). **Instance:** the package is built as `tela snapshot` builds it (a `go test -overlay` file inside the package, ADR-059) into a child process that mounts the screen with the public `telatest` and serves the server's commands; so it works in any module that requires Tela. A failed action is an error result of that call, never the end of the instance. **Reload:** before every call the server compares the package's sources with the build's (the fingerprint of `tela dev`'s watcher); on a change it rebuilds and mounts afresh (state is reset, and the result says so); a compile error, and the findings of `tela lint` on the package, are returned as the call's error and the last good instance stays. **Tools** (Playwright MCP's model, Tela's names): `snapshot` (the aria snapshot YAML of `tela inspect`, each line that can be acted on carrying `[ref=eN]`); `screenshot` (a PNG image, the whole window or one `ref`); `click` (`button` left or right, `double`), `hover`, `fill` (text into a field, optional `submit`), `press` (a key combo, `telatest.Press` syntax), `scroll`, `drag`; `resize` (logical size and scale, state kept); `open` (another preview, color scheme or size: mounts afresh); `wait` (advances the app clock, for timers and animations); `inspect` (the layout JSON of `tela inspect --layout`, whole or one `ref`); `lint` (`tela lint -json` on the package). An element is a `ref` from the latest snapshot or a `role` and `name`, a `text` or a `testId` (telatest's locators); `click` also takes `x`, `y`. Every acting tool answers with the new snapshot, and every answer carries the dev-mode warnings and errors the instance logged since the previous call (unknown classes at run time, missing keys…). **Windowed** instances (the agent and a person looking at one real window) are left for a later ADR. **Implementation.** The instance is a test binary (`go test -c` of the overlay file, run directly with `-test.timeout=0`) that reads commands on standard input and answers on standard output; it mounts with a `testing.TB` of its own that embeds the real `*testing.T` and turns `Fatalf` into a panic its command loop recovers, so a failed action is that call's error and a panic of the app remounts the screen. A ref is `ByRole(role, name)` with the `Nth` of its line, given only when the instance counts as many matches as the snapshot shows; it keeps its number across actions and rebuilds while the element keeps its role and name (within one mount, also its position when only the name changed); a ref given right after a rebuild is checked against a new snapshot. `press` may name an element to focus first; `wait` also waits for a `text` to appear or `textGone` to go. **Added to `telatest`:** `(*App).Resize`, `(*App).SetScale` and `(*App).LayoutJSON` (the live app's layout tree), which `resize` and `inspect` need; to `cmd/tela/internal/watch`: `Fingerprint`.

## Rationale

The agent loop of §17 (write, look, inspect, fix) needs a screen that stays up between edits and answers in milliseconds; MCP is how agents call tools, and Playwright MCP's snapshot-with-refs model is the one LLMs already use for UIs. Reusing the snapshot driver and the public `telatest` keeps one way to mount a screen and makes the server work outside this repository; rebuilding on the next call instead of watching avoids a background process the client cannot see. Returning the dev warnings closes the gap `tela lint` leaves (computed values).
