# ADR-121: Second phase-9 review of `tela dev`

- **Date:** 2026-10-22
- **Status:** Accepted

## Decision

Second phase-9 review of `tela dev` (amends ADR-115, ADR-116 and ADR-119). **Exit during a promotion.** Once the supervisor has posted a new child's promotion to the host, the promotion's result alone decides the swap (ADR-119 already kept the first-frame timeout from undoing it): an exit or disconnect of that child in between is not classified until `evPromoted` arrives. If the promotion succeeded, the host showed the child and detached the old one, so the swap completes (the old child is stopped, the reload line is printed) and the exit is a crash of the app now shown: "the app panicked/exited …" over its last frame, and the next good build starts fresh. If it failed (the host saw the connection end first), the exit fails the swap as before and the old child stays. A quit while the result is pending classifies the exit at once (the host's loop may never run the promotion). **GOFLAGS** is read with `go env GOFLAGS` in the target's module root with the environment of every go command of `tela dev` (`CGO_ENABLED=0`), where the builds and `go list` run; the `go list` that finds the package, which runs in the current directory, keeps that directory's. A module that selects another toolchain (`toolchain` line, `GOTOOLCHAIN`) gets that toolchain's `go.env`. **Tags of GOFLAGS** are read as the go command reads them (`cmd/go/internal/base` and `work`'s `tagsFlag`): one entry is one flag, so only `-tags=…`/`--tags=…` counts and the last wins; a value with a space or a single quote is the legacy list, split by `cmd/internal/quoted`, any other value is split on commas; tags no build constraint can name (`go/build/constraint`: letters, digits, `_`, `.`) are dropped, since a tag with a space joined into the command line's `-tags` would make the go command read the whole list, `teladev` included, as the legacy form. **Children's output.** The pipes of a child's standard output and error are the supervisor's own (`os.Pipe`, copied by `childOutput` in `cmd/tela/dev_tail.go`), not `exec`'s, so `cmd.Wait` returns at the child's exit instead of waiting for the copies (`exec.Cmd.WaitDelay` is gone). The exit is classified once the output has reached its end, at most 200 ms after the exit (the end comes at once unless a process the child started and left running holds the pipes; the tail that finds a crash needs what the child wrote before it exited); 1 s after the exit, output still held that way is detached (the copies stop, the read ends close, so that process gets a broken pipe when it writes) and one line, printed without `-v`, says so: "a process started by build N still holds its output after it exited: detached, what it writes now is not shown". Without a writer for the standard output a child gets the null device (no pipe and goroutine that discard)

## Rationale

The host may promote a child the supervisor has seen exit, since the two learn of it through different paths; deciding on the promotion's result keeps the supervisor's `active` equal to the child on screen, so a crash right after a reload shows over the right frame and restarts fresh. GOFLAGS can depend on the directory through the toolchain a module selects, and the builds should get the flags the go command applies where they run. A GOFLAGS the go command rejects cannot be built anyway, and splitting it differently from the go command could enable tags the user's own builds do not see. Bounding `Wait` with `WaitDelay` delayed every classification of a child that left a process behind by a second and cut that process's output without a word; owning the pipes separates the exit from the end of the output
