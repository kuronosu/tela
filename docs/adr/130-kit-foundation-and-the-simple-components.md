# ADR-130: `kit` foundation and the simple components

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

`kit` foundation and the simple components (phase 10, T1; builds on ADR-129). **Pinned look:** shadcn/ui commit `617134d5810bba521803b3ed787190bacbb80b35` of main (2026-10-24), `apps/v4/registry/new-york-v4/ui`, exported as `kit.ShadcnCommit`; every later component follows it (`THIRD_PARTY.md`). **Recipes:** `kit.Style` has one field per component (`Button ButtonStyle`...); each file declares its recipe type and fills `defaultStyle.<Component>` in an `init`, so a component touches `Style` only to add its field; `DefaultStyle()` deep-copies by reflection (structs, maps of strings), `StyleProvider{Style *Style, Children}` provides it through a context (nil = defaults), `UseStyle() *Style` reads it (shared: read, do not edit; build a new style instead). **Part-naming rule (public API):** `Root` is the root element; other parts are named after the shadcn slot (`Header`, `Title`, `Description`, `Action`, `Content`, `Footer`, `Image`, `Fallback`, `Label`, `Error`, `Icon`); `Variants map[Variant]string`, `Sizes map[Size]string`, `Orientations map[Orientation]string` (the empty key is the default; an app adds a key to add a variant or size); a boolean state is a string named after it (`Disabled`); a class that only applies in a condition shadcn writes as a selector is a string named `<Part>With<Condition>` or `<Orientation>With<Condition>` (`HeaderWithAction`, `DescriptionWithError`, `HorizontalWithContent`, `HasIcon` per size) that the component adds in Go. Classes are applied in the order Root, variant, size, state, `Class`. Instances: `Class` (root) and `<Part>Class` for the other parts (`HeaderClass`), `Props tela.Child` (root props). **Slots:** a part that can hold anything is a `tela.Component` (nil = absent); the text of a `Field` (`Label`, `Description`, `Error`) is a string (empty = absent), since it also names and describes the control. An image is a `tela.Child` (`h.Src*`), an icon a `tela.Icon`. **Values:** `Variant` gains no more than ADR-129's constants; `Size` adds `Xs` and `IconXs`, which the pinned commit's button has; `Orientation` (`Horizontal`, `Vertical`) has the component's own default as its zero value. A variant or size the active recipe lacks panics in dev mode (`kit: Button.Variant "ouline" is not defined by the active style, which defines Default, "destructive"...; did you mean "outline"?`). **Dev mode from public API:** `tela` exposes no query for it, so `kit` asks `h.Role` (which panics in dev mode on an unknown role and checks nothing else) with a probe role inside `recover`; it runs only on the way to a panic. A `tela.DevMode()` would replace it (open for the owner). **Behavior:** `Button` is an `h.Button` with `OnClick` (HTML's default type: submit inside an `h.Form`), not `aria.UseButton`; `Input` and `Textarea` follow the value rule with `Value *string`/`DefaultValue`/`OnValueChange func(string)`; `Field` ties a label to its control with `tela.UseID` through a context (`fieldCtx`, shared by every text control in `control.go`; a control takes the field's id when it has none, and `aria-describedby` points to the error, else the description) and does not need ids written. A hook used by a helper is named `useXxx` (dev mode enforces it). **Deviations from shadcn (all in the recipes):** the invalid state is in (ADR-131): the `aria-invalid:*` classes are in the Button, Badge, Input and Textarea recipes, `Input` and `Textarea` have `Invalid bool` (`h.AriaInvalid(true)`), and a `Field` with an `Error` (or `Invalid: true`) marks its control invalid through its context and adds `FieldStyle.Invalid` (`text-destructive`, shadcn's `data-[invalid=true]:`) to its root; `border` with no color becomes `border border-border` (Tela's default border color is `currentColor`; shadcn sets it in its base layer); `[&_svg]:` classes are the `Icon` part and `[&_svg:not([class*='size-'])]:size-N` the `IconSizes` map; `has-[>svg]:px-N` is `HasIcon` and a Go condition; `@container/*`, `[.border-b]:pb-6`, `[.border-t]:pt-6`, `[a&]:hover:`, `file:*`, `[&>*]:w-full` (a vertical field's label is fit-width here, full-width there; invisible), the responsive Field orientation, the checkbox/radio `mt-px` and `has-data-[state=checked]` rules of `FieldLabel`, `FieldSet`, `FieldLegend`, `FieldGroup`, `FieldSeparator`, `FieldTitle`, `AvatarBadge`, `AvatarGroup` and `AvatarGroupCount` are not ported (the checkbox and radio rules arrive with those components); the avatar image is `absolute inset-0 object-cover` over the fallback (Radix swaps the two), a `Separator` is hidden from the semantics tree unless `Semantic`. Every class shadcn uses and Tela's parser lacks: none (`selection:`, `field-sizing-content`, `peer-disabled:`, `underline-offset-4` and the rest parse). **Conformance harness (public API only; `kit/harness_test.go`):** a `sheet` of `cell`s (Tela component + shadcn markup + probe names) gives `golden` (`testdata/<name>_{light,dark}_x{1,2}.png`) and `chromium` (`testdata/chromium/<name>/`: `page.html`, the Tailwind 4.3.3 `gallery.css`, `geometry.json` of every `data-probe` element, `x1.png`, `x2.png`; regenerated with `TELA_CHROMIUM=1 TELA_TAILWIND=...`; the test fails when `page.html` is not the page the sheet makes). Light and dark panels are one page; probes are `h.TestID(name)` on Tela's side and `data-probe=name` on the markup, matched by occurrence (light, dark). Cells sit in fixed-width slots in sheets of small cells, because Chromium rounds text widths to 1/64 px and the sum drifts along a row up to 0.1 px, which snaps a box to another device pixel. The markup is shadcn's `cn()` output: `cn` in the harness is a small tailwind-merge (shadcn's classes conflict, such as `gap-2` and `gap-1` or `border-transparent` and `border-border`, and raw CSS order decides without the merge; a later component adds the groups it needs). **Measured (Chromium pages with Tailwind 4.3.3, 10 components, 142 cells per scale, light and dark):** box edges differ by at most 0.012 px at x1 and 0.011 px at x2 (bound 0.06 and 0.5); mean pixel difference per channel around a cell (the box grown 8 px): Avatar 0.69/0.31 (x1/x2, worst cell), Badge 1.59/0.89, Button 1.44/1.11, Card 1.01/2.54, Field 1.75/3.08, Input 4.60/1.74, Label 3.00/3.29, Separator 2.99/2.20, Skeleton 0.03/0.01, Textarea 2.73/2.24; the averages over each sheet's cells are 0.01 to 2.0. Shapes, borders, shadows and rings match (differences are under 1 level); what remains is text: Skia and Tela anti-alias differently (about 1 level per channel over a cell of text), and a text whose line box is shorter than its content area (`leading-none`: card titles, labels, an input's value) sits one device pixel off vertically, as Chromium rounds a font's ascent and descent to whole pixels before placing the baseline and Tela does not (a `core` and `text` matter, not `kit`'s); the default bound is 3.5 levels, and 5 for `Input` at x1.

## Rationale

The owner's design (ADR-129) needed its foundation written down before eight more agents build on it: recipe and part names are public API, the harness is what makes "looks like shadcn" a test, and every deviation is a line in a recipe an app can edit
