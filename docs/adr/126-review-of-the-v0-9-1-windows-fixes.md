# ADR-126: Review of the v0.9.1 Windows fixes

- **Date:** 2026-10-22
- **Status:** Accepted

## Decision

Review of the v0.9.1 Windows fixes (amends ADR-125). **Directory set** (`cmd/tela/internal/watch`, Windows): the walk that finds a root's directories now finishes before `open` returns (with the first read pending, so nothing made during the walk is lost); before, `SetRoots` returned first and a directory removed or moved away right after it was reported as a file, so no rebuild. `SetRoots` keeps the watches of roots that did not change instead of reopening and rewalking all of them. Records may carry 8.3 short names (`MYPACK~1`; the documentation leaves the form unspecified), which a set of long names never matches: a removed name not in the set that looks like one (at most 8 characters, `~` and digits at the end of the name, an extension of at most 3) is reported both as a file and as a possible directory. A parent-to-children index limits a removal to the removed subtree (it scanned the whole set, quadratic on a recursive delete), and the walks stop when the root or the watcher is closed, so `Close` does not wait for a large tree. **Hint:** only a reload's build counts (the first start of a session is where an app slow to initialize shows, and it got the hint every session, exclusions or not), measured from its start to its connection, which includes the scan (it happens before any code runs) and not the app's first render; `-v` prints `start→connect` in the timing line. The test makes every build wait past the threshold before connecting, so it no longer depends on how fast a process starts. **Build directory:** `%TEMP%\tela-dev` is reused only if it is not a reparse point and is owned by this user or by the token's default owner (the Administrators group for an elevated administrator); on a shared temporary directory (`C:\Temp`) a directory or link made there by another user would let them replace a build before it runs. Otherwise each session gets a fresh `tela-dev-*` of the temporary directory, and the hint names the temporary directory. Accepted and not changed: a child's `Close` may wait up to `closeTimeout` (1 s) for acknowledgments from a host that stopped reading it

## Rationale

Review findings of the patch. The directory set is only useful once it is complete, and a watcher that answers before it is can miss the very change it was built for; short names and recursive deletes are ordinary on NTFS. Counting reloads only, and up to the connection, keeps the hint about the scan rather than the app. Reusing a fixed directory is safe only when no one else controls it
