# ADR-145: Examples `settings` and `pricing` on `kit`

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

Examples `settings` and `pricing` on `kit` (phase 10, migration D2; implements ADR-129's K12 for these two). **settings** (default style, theme tokens, `kit.Theme()` in `var App`): the five switch rows are a horizontal `kit.Field` (`flex-row-reverse`, control after the text) with a `kit.Switch`; the cards `kit.Card`; the theme picker a `kit.RadioGroup[string]` with `Render` (cards with the miniatures, `RadioState.Props` and `Indicator`, `aria-checked:` variant); the density a `kit.ToggleGroup` (Outline, `DisallowEmptySelection`) with the hint of the chosen one below; Save a `kit.Button` plus a `kit.Toaster` toast through `kit.UseToast`; Reset a `kit.AlertDialog` (Destructive) whose trigger is a `kit.Button`; status icons from a Lucide subset (`examples/settings/icons`, `tela icons gen`). `Preview()` is replaced by `var App` (the tests mount it with `telatest.MountApp`). Narrow rebuilds survive (the unchanged rows and the Appearance card skip) but cost more: a toggle builds 17 components against 9, as each kit part is a component (the test bound goes from 12 to 20). New goldens: dark, Reset dialog open, toast shown, at x1 and x2. **pricing**: plans `kit.Card` (the highlighted one `bg-primary text-primary-foreground` plus a `kit.Badge` placed with `absolute`), buttons `kit.Button`, the billing period a `kit.ToggleGroup` (a segmented control in place of the switch) with a `kit.Badge` inside the yearly option, checks `icons.Check` from a Lucide subset (`examples/pricing/icons`); a dark golden and an aria snapshot are added. **Kit addition** (backwards compatible, tested by `TestDisabledTrigger`): `Disabled bool` on `Dialog`, `AlertDialog` and `Popover`, passed to `aria.UseOverlayTrigger`, because the trigger props set `disabled` after the trigger's own and a `Disabled` on the `kit.Button` used as a trigger was lost. **API gaps found, not filled:** a heading for `Card.Title` (it is a `div` as in shadcn; the examples pass `H2`/`H3` as the slot); `Field` takes the control before the text only (shadcn's switch rows put it after: `flex-row-reverse` in `Class`); a group caption (shadcn's FieldSet/FieldLegend; `Field`'s label wires `for` to an input and warns on a group, so the examples use a plain caption span and `AriaLabel`); no `Disabled` on `Tooltip` and the other trigger slots; a component that returns a kit component needs `Fragment(...)` to be a `tela.Node`; the two `icons/` subsets copy what `icons/lucide` has, since the root module cannot import it; hand-made, kept: the theme miniatures (decoration inside a `RadioGroup.Render` card), the round backing of the pricing checks and the status line of the settings footer

## Rationale

K12 asks the app screens to be written on the kit so that the API is tested before it freezes; these two found one real hole (a disabled overlay trigger) and four small gaps, all workable with `Class` or a slot. Segmented control for the billing period and the density, as the plan suggested, is what `ToggleGroup` is for, and it gives arrow-key behavior the divs lacked
