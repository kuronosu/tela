# ADR-144: `examples/dashboard` rebuilt on `kit` with a glass style

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

`examples/dashboard` rebuilt on `kit` with a glass style (phase 10, migration D1 of ADR-129's K12; the done criterion "dashboard built only on kit with a glass style"). **What is kit now:** the period, format and sort segmented controls (`ToggleGroup`, whose pill is a child of its item so a `LayoutID` slides it), the Day/Night switch and the weekly switch (`Switch`), the task checkboxes (`Checkbox`), the report dialog (`Dialog` with the New report `Button` as its `Trigger`, a `Field`/`Input`, `Label` and `Switch`), the toasts (`Toaster` around the page, `UseToast` in the components that show them), the metric tabs (`Tabs` with the `line` variant), the nav entries and every button (`Button`), the stat, chart, traffic, insight, priorities and sales panels (`Card`), the priorities and sales lists (`Table`), the avatars (`Avatar`), the badges (delta, Live/Syncing, count, due date, Insight chip: `Badge`), the seats bar (`Progress`) and the icons (a Lucide subset in `examples/dashboard/icons`, `tela icons gen`, no hand-drawn icon is left). **Still the example's own, and why:** the charts (12 bars, 48 sparkline bars, the donut) and the goal meter, which are content, not controls, and whose heights, widths and colors are springs read in layout and paint closures; the meter is not a `Progress` because that is built from a value that changes between builds, and this one changes every frame with no build; the gradient chips, the logo and the promo blocks (decoration); an `h.Form` around the dialog's fields (kit has no form element). **The glass recipe** (`glass.go`, the three levels of K17): *tokens*: `kit.Theme()` with `border` = white/60 (white/10), `card` white/55 (white/5), `popover`, `secondary`, `accent`, `muted`, `input`, `ring` and the slate foregrounds as translucent or palette values, so `border-border`, `bg-card` and `text-muted-foreground` are already glass and the page needs no `dark:` pair where a token fits; *recipes* (`glassStyle()`, applied by `kit.StyleProvider`): `Card.Root` rounded-2xl with no shadow or blur, `Button` default as the indigo-to-fuchsia gradient plus variants `glass`, `tint`, `nav`, `fab` and sizes `nav`, `fab`, `Badge` variants `live`, `syncing`, `up`, `down`, `soft`, `tint`, `Switch`, `Checkbox` (round), `Toggle`/`ToggleGroup` (a pane with a pill), `Tabs` (line, indigo selected), `Input`, `Avatar` (white ring), `Table` (hairlines, row hover, `w-full` so a `1fr` column truncates), `Dialog` (frosted, scrim with no fade), `Toast` (frosted, bottom center, a close button inside); *per instance*: `lift` on the stat cards, the gradient `Class` of the insight card, the sort chips. **API gaps found and the two kit additions** (both backwards compatible, with tests): (1) `Avatar.FallbackClass`, since the gradient of an avatar is per person and the recipe holds one fallback; (2) `Tabs.Indicator tela.Component`, drawn inside the selected tab only, which replaces the recipe's always-mounted underline so that a `LayoutID` on it slides between tabs (the old page's shared underline). Gaps *not* closed, for the owner: **a)** `Toaster` has no countdown bar or per-toast progress (its close button's place is only a recipe); **b)** a `Tabs` used only as a tab list (the content is a chart elsewhere) has dangling `aria-controls` since no panel is rendered; **c)** a toast shown from an effect or a handler is state in the Toaster, delivered by a post, so `telatest.Render` and `tela snapshot` (one-shot renders that do not receive posts) draw the page without it (`telatest.MountApp` does show it: `TestGoldenToast`); **d)** `Progress` and the segmented control have no deferred (`HeightFn`/`WidthFn`) forms; **e)** `Table` rows are `display: contents`, so a card made of separate rounded row panels (the old task list) is not expressible, and the list became a table with hairlines; **f)** kit components keep their `aria` hook state in `UseRef`s the dev state cannot snapshot (14 slots reset, silently, in `TestDevStateDashboard`). **Deviations from the old look, accepted:** the Day/Night control is a sun, a switch and a moon (the old one had the words on its knob), the task rows are table rows with hairlines under a header, the toast has a close button at its right and no countdown bar, the delta and count chips are badges (icons are Lucide's), the dialog's labels and spacing are the `Field`'s. **Performance** (`bench_test.go`, an i5-10400 with `-cpu 4`, i.e. 4 raster workers, old and new interleaved, 1080p scale 1, medians of three): before p50 3.0, p95 23.1, p99 29.0 ms (644 frames); after p50 3.2, p95 26.7, p99 32.2 ms (527 frames); a scroll frame (`BenchmarkScrollFrame`) 24.7 against 26.9 ms (+9%). The session has 117 fewer, cheap, frames (a waiting toast draws none and has no countdown tween; the theme switch has no knob transition), so the percentiles of the session rose by 15% while the expensive frames rose by 9%. A first version of the page had a `backdrop-blur` on the `tint` button inside the insight card (a layer), which turned off parallel rasterization and tripled scroll frames: the recipe's variant has none (the glass budget of `backdrop.go` is unchanged). The tests that depended on the hand-made roles now ask for the kit's (`radio` for a `ToggleGroup` item, the switch's name from its `Label`), `TestRange`'s build bound went from 90 to 120 (67 builds before, 96 now: the kit components inside each card), and the bench's frame floor from 600 to 450; the `teladev` dev-state test, which did not compile (an unused import), builds again. The kit's goldens and Chromium sheets are unchanged

## Rationale

The page the glass look came from is the test that recipes suffice, and they do for everything but the two things above: the glass is tokens (translucent borders and fills that follow the scheme) plus a handful of variants, and no class of a kit component was copied into the app. The list of gaps is the product of the migration, as K12 asks; two small additions were cheaper than a workaround that would have bypassed the component (a hand-made tab list, an avatar built from a `Div`)
