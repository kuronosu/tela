# ADR-073: CSS grid

- **Date:** 2026-10-18
- **Status:** Accepted

## Decision

CSS grid (phase 6, T1). `internal/layout` ports Taffy v0.14.0's grid (`src/compute/grid/`) into `grid*.go`: explicit grid with line names and `repeat()` (`auto-fill`/`auto-fit` counted from the size, max size or min size), implicit tracks (`grid-auto-rows/columns`, cycled), placement (sparse and dense, both flows, spans, negative and named lines, 10,000-track limit), the track sizing algorithm, content alignment and self alignment (baseline included in rows). `Style` gains `DisplayGrid`, a `Grid *GridTemplate` (track lists, auto tracks, named areas; compared by pointer, so core keeps the pointer while `GridTemplate.Equal` holds), `GridAutoFlow`, `JustifyItems`, `GridRow`/`GridColumn` placements and `JustifySelf`; Dim gains `UnitFr`. Conformance: Taffy's `grid`, `blockgrid` and `gridflex` fixtures measured by Chromium 152 like the others (all 553 included ones match within 0.5 px; the excluded ones are vertical writing modes and margin collapsing), plus Tela cases for named lines and areas, auto-repeat, dense placement, static positions, baselines and content-sized grids. Where Chromium and Taffy disagree, layout follows Chromium: an auto-width grid under definite available space is fit-content (sized under max-content and min-content constraints) and an auto height is a max-content constraint (CSS Grid 1 11.1); size queries include the second column/row passes; a track holding a span-1 item gets a finite growth limit even for zero contributions; beyond-limit distribution caps fit-content() only for max-content contributions and counts auto as max-content; the automatic minimum looks at the spanned tracks and the other axis' min size does not transfer through the aspect ratio; items with an aspect ratio and an auto width are measured with a row estimate sized first; named lines follow CSS Grid 1 8.3; the container's first baseline is its first item's. Absolutely positioned children follow ADR-043's containing blocks: a positioned grid lays them out in their grid area (auto lines at the padding edges) with CSS 2's rules, a static grid gives them a static position in its content box aligned by `justify-self`/`align-self`. `core` maps grid and inline-grid onto it; flex and grid containers share the item structure (element children are items, text runs anonymous items). Classes reach line names in arbitrary track lists and named placements (`col-[main]`, `col-start-[main]`, `col-span-[name]`) plus Tailwind v4's `col-N`/`-col-start-N`; `grid-template-areas` and `grid-area` have no Tailwind utility, so area templates are not reachable from classes

## Rationale

Grid is in §9's scope; Taffy is the reference whose fixtures Chromium agrees with on all but script-driven ones, and the deviations come from probing Chromium where the fixtures (or Tela's own context, which sizes grids inside real containers instead of at the root) disagree with Taffy. Keeping templates behind one pointer keeps `layout.Style` comparable, which core's restyle relies on
