# ADR-206: The project website at telaui.dev, built from `site/`

- **Date:** 2026-10-31
- **Status:** Accepted

## Decision

The project website lives in this repository under `site/` and is published at `https://telaui.dev` by GitHub Pages. It is built with Astro and its documentation theme Starlight. `site/` has a `go.mod` of its own (`github.com/kuronosu/tela/site`, no Go code), so it is outside the core module: `./...` patterns skip it and it is not in the module zip users download. The Node toolchain and npm packages are allowed only inside `site/`; nothing in Go imports or ships them, so §2's dependency rules do not apply to them.

`docs/wiki` stays the one source of the documentation. A sync script in `site/` turns its pages into Starlight pages at build time (title from the H1, wiki links to site routes, `docs/images` copied in, the sidebar from `_Sidebar.md`); generated pages are not committed. The GitHub wiki keeps being published from `docs/wiki` until the owner retires it. Internal links and anchors are checked at build time.

A workflow of its own (`.github/workflows/site.yml`) deploys the site code of `main` with the docs of the latest release tag, so the site describes the API people install; pull requests and pushes that touch the site or the docs build it with their own docs, as a check.

## Rationale

The docs, the API reference pages generated by `internal/gen/wikidoc` and the screenshots already live here and change with the code; a separate repository would need them copied and would drift. Tela draws desktop windows only (§1 non-goals), so the site cannot be built with Tela.

## What it changes

§5's repository layout lists `site/`. The CI workflow ignores pushes that touch only `site/`. DNS and the Pages settings are the owner's.
