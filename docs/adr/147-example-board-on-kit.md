# ADR-147: Example `board` on `kit`

- **Date:** 2026-10-25
- **Status:** Accepted

## Decision

Example `board` on `kit` (phase 10, migration; implements ADR-129's K12 for it, with ADR-141's menus and ADR-145's conventions). The cards are `kit.Card` (title in the `Title` slot as an `H3`, the note as `Description`, the tag/comments/assignee row as `Children`, compacted with `Class`, `HeaderClass`, `ContentClass`; the slots fit a compact card, so no hand-made card), tags and column counters `kit.Badge` (a palette dot before the tag is decoration), assignees `kit.Avatar` (`Sm`), Invite `kit.Button`. Each card's action is a `kit.DropdownMenu[string]` with an icon-button trigger (`kit.Ghost`, `kit.IconSm`, `icons.Ellipsis`) and the card is a `kit.ContextMenu[string]` area with the same `[]kit.MenuItem` (`Move to` label and one item per other column, disabled when that column is full; separator; `Edit card`; `Delete card` with `kit.Destructive`); Edit is a `kit.Dialog` opened by state (no trigger) with `kit.Field` + `kit.Input`, `kit.Textarea` and `kit.Select`, its draft kept by the card; Delete is a `kit.AlertDialog`; moves, edits and deletes show `kit.UseToast` toasts under a `kit.Toaster` (`Kanban()` now returns the Toaster; `var App` with `kit.Theme()` and `bg-background text-foreground`, tests use `telatest.MountApp`). New behavior: edit and delete (`Board.Remove`, `Board.Full`, `Tasks` as a comparable array in `UseState`, `Task.Colors` replaced by `tags`/`tagDots`); moving by menu works from the keyboard, which dragging does not. Theme tokens replace every zinc/indigo pair and `dark:` class (lane `bg-muted`, drop target `bg-accent ring-primary/50`, insertion bar `bg-primary`); icons are a Lucide subset in `examples/board/icons` (`tela icons gen`; ellipsis, message-square, pencil, trash, arrow-right) in `THIRD_PARTY.md`. The drag handlers and the translate stay on a plain element around the `kit.Card` (layout, not a control). New goldens: dark, menu open, edit dialog, delete question, toast, at x1 and x2, and an aria snapshot; test locators now use a test id (`card`) and the token classes. **Accepted visual differences:** the header avatars are a row of `kit.Avatar` on a muted disc (no gradients, no overlap: the fallback text of a stacked avatar is clipped by the next one); tags are outline badges with a dot instead of tinted chips; cards take the kit's radius, border and `shadow-sm`. **API gaps found, not filled:** `Props` of `kit.Card` and the other kit components is one `tela.Child` and `core.MergeProps` is not public, so an app cannot give a kit component several props (the drag handlers, the translate and a test id), hence the wrapper element (proposal: export `tela.MergeProps` or an `h.Props(...)`); `kit.Badge` has no leading-dot or color-tone variant (the tag colors need a dot in `Children`); `kit.Avatar` has no color or stack/group (`AvatarGroup` in shadcn); `DropdownMenu` and `ContextMenu` take their `Items` separately, so sharing them is a slice built once in the app; telatest has no secondary-button click, so the context menu is tested through Shift+F10; no add-card flow (the roadmap's `Dialog`/`Field`/`Select` form is the edit dialog). Hand-made, kept: the lane (a layout box with the drop ring and the column dot) and the empty-column hint (decoration)

## Rationale

K12 asks the app screens to be written on the kit so the API is tested before it freezes. The board adds the first use of a dropdown and a context menu sharing one item list, of dialogs controlled by state from a menu, and of a draggable `kit.Card`; all worked with `Class` and slots, the one real gap being how to give a kit component more than one prop
