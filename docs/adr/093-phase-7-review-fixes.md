# ADR-093: Phase-7 review fixes

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Phase-7 review fixes (amends ADR-085, ADR-087, ADR-088, ADR-090, ADR-091 and ADR-092). **Dev mode of node constructors** (ADR-085): `Role`, `Type`, `Dir`, `h.If`'s check and the call-site captures of `CP`, `Memo` and `List` follow `core.devNow`, the dev mode of the Tree being built when they run inside a build phase, else the process default, so `telatest.NoDev` and `App.Dev = false` (`FromApp`, `MountApp`) turn them off; a root built in a test's body before `Mount` still follows the process default. Build phases are serialized by `buildMu`; `lockBuild` publishes the goroutine running one (its id, from the header of `runtime.Stack`) and its Tree's mode, only when Trees of both modes exist or one differs from the default, so release apps and all-dev test binaries never read a goroutine id. **i18n** (ADR-087) reports missing keys and argument problems in that dev mode (`core.DevNow`: on unless a release build, `App.Dev` once `Run` starts, the mode of the Tree whose component calls `T`), `TELA_DEV=1`/`0` overriding at each call; i18n now uses `core.DevNow` besides `core.EnvDev`. **Messages** (ADR-085): one deduplication, `Tree.once` (mutex-guarded, keys prefixed by kind: `dep:`, `deps-count:`, `nil-deps:`, `once-deps:`, `anon:`, `ctx-default:`, `get-pending:`, `bg-url:`, `anim:`...), replaces `warnOnce`'s set and `firstReport`/`reportOnce`; class errors have their own set, which `SetTheme` clears (it cleared everything, so each theme printed the dependency warnings again). **Struct components** (ADR-088): an embedded interface with `Build` (`tela.Component`, `tela.Child`) is skipped when the hook-boundary owners are collected (its reflect `Func` is the zero Value, whose `Pointer` panicked on the type's first use, in every mode). **Dir("auto")** (ADR-090): an auto element is resolved again only when marked (`markAutoDir`: a text update, a TextFn's Value, children reconciled or an exit finished, a child's `Dir`), not at every style phase; the walk evaluates stale TextFns (`textOf`), so a Value change flips the direction in the same frame. **Handlers** (ADR-091): the constraints are `~func() \| ~func(E)` and `Setter[string] \| ~func(string)`, so a named func type compiles again (converted with reflect; literals keep the type switch); `OnClick(nil)` still does not compile. **CLI** (ADR-092): the runner declares `telaApp, telaHasApp = telaAppOf(App)`, a type assertion to `tela.App` or a non-nil `*tela.App` that compiles for any type, and applies `FromApp` only when it matched, so `var App = server.New()` next to a `Preview` renders as in v0.6.0; the source scan also takes `&tela.App{...}` and `*tela.App` (a dot-imported `App{...}` cannot compile next to `var App`). **UseInterval** (ADR-085) catches a late tick up in one step (`next += ((now-next)/d + 1) * d`), one call per late tick as before

## Rationale

Review findings of phase 7. Following the Tree being built is what `NoDev` promised; a goroutine id is the only race-free way to know that a constructor runs in the build of a given Tree while another test builds, and reading it only in mixed processes keeps it off every hot path that matters. Marking on change keeps hover frames free of text walks, at the cost of an ancestor walk per text or child change while some auto element exists. Rendering is unchanged: every golden is bit-identical
