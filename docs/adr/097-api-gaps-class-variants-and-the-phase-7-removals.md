# ADR-097: API gaps, class variants and the phase-7 removals

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

API gaps, class variants and the phase-7 removals (phase 8, T3; every shape is the owner's; amends §9, §10, §16, §17, §19, ADR-055, ADR-058, ADR-059, ADR-080, ADR-085, ADR-088 and ADR-091). **Width variants (Tailwind v4).** `max-sm:` … `max-2xl:` (one per theme breakpoint) match a window narrower than the breakpoint (`@media (width < 40rem)`), the arbitrary `min-[600px]:` and `max-[40rem]:` take a length in `px`, `rem` or `em` (rem and em against the theme's root font size, as media queries resolve them against the initial one) and stack with `sm:` … `2xl:` and with each other (`md:max-xl:` is the conjunction of both limits). `style.Condition` gains `MaxWidth` and `HasMaxWidth` (the smallest of the class's max variants; `MinWidth` stays the largest min); `max-[0px]:` never matches. Decided without the owner: `min-sm:` … `min-2xl:` exist as in Tailwind and equal `sm:` … `2xl:`. A typo suggests the closest variant (`max-smm:` → `max-sm:`), a length without a valid unit is an invalid-class error that shows `min-[600px]:`, and `max-` plus an unknown name is an unknown variant. Resizing restyles every box as for `sm:` (ADR-055's narrower marking is a known gap). **aria variants (Tailwind v4).** `aria-busy:`, `aria-checked:`, `aria-disabled:`, `aria-expanded:`, `aria-hidden:`, `aria-pressed:`, `aria-readonly:`, `aria-required:` and `aria-selected:`, with `group-aria-*:` and `peer-aria-*:`, match Tailwind's selectors `[aria-x="true"]`: the element's own `h.Aria…` prop set to true, not an implicit state (`Disabled(true)` does not match `aria-disabled:`; `AriaChecked(false)` and a mixed value do not match `aria-checked:`). `style.StateFlags` widens to `uint32` with `StateAriaBusy` … `StateAriaSelected` (the set `style.AriaStates`), which are ordinary flags of `Element.istate`: a node sets them at mount from `ariaStates(d.aria)`, and a build whose props differ goes through `setAriaStates`, which calls `setState` per changed flag, so the existing marking (`stateUse`, `groupUse`, `peerUse`, ADR-055) restyles only the elements whose classes test them (a test counts one restyle among six elements). The arbitrary `aria-[checked=true]:` (also after `group-` and `peer-`) is the same as `aria-checked:` for the nine states; any other selector (`aria-[sort=ascending]:`, `=false`, no value) is an unsupported-class error that lists the supported variants, since Tela has no prop for it; `aria-` plus another name is an unknown variant with a suggestion. `h.AriaRequired(bool)`, `h.AriaReadOnly(bool)` and `h.AriaBusy(bool)` set `semantics.StateRequired`, `StateReadOnly` (also set by a `ReadOnly` text field) and `StateBusy` on the node and the matching variants; Playwright 1.61's aria snapshot prints none of the three, so neither does Tela's (the telatest failure message lists them). **NoSettle queries (amends ADR-080).** Under `NoSettle()`, `AriaSnapshot`, `Count`, `Bounds`, `Stats` and `Cursor` handle only the work due (`flush`: queued events, state updates and the frames they request) and never run the clock for animations, like the events of an action; the expectations (`Expect…`, `WaitFor`, locator resolution for `Bounds`) poll as before, but their first try is a `flush` and the clock moves, a frame at a time, only between failed tries. The wait before an action (`target`, `Focus`) still settles fully, as ADR-080 says. Without `NoSettle` nothing changes. **Settling in app time (amends ADR-059; added after the phase-8 merge).** Whether an app goes quiet is decided in app time alone: `settle` and `flush` give up on an app still requesting frames after the timeout of app time (an endless animation, a goroutine that sets state all the time; the log says so), and real time bounds only rounds that do not move the clock (work to deliver and no frame to wait for: a goroutine posting slow functions; its own log). Before, a 5 s real-time limit also cut finite animations on a starved machine, so a golden could be captured mid-animation (`examples/dashboard`'s at 12 % CPU); `TestSettleRunsSlowFiniteAnimations` sleeps in every frame of an 18-frame tween to prove it now runs to its end. **Removals (amends ADR-085 and ADR-088).** `h.Id`, `tela.UseId`, `tela.Key` and `tela.Code` (deprecated in v0.7.0), their tests and every mention are deleted; use `h.ID`, `tela.UseID`, `tela.KeyName` and `tela.KeyCode`. A single `nil` dependency list (`UseEffect(f, nil)`, also `UseLayoutEffect`, `UseMemo`, `UseEffectDo`, `UseUpdateEffect`, `UseGo`) panics in dev mode when the hook slot is created, with the fix (`tela.Once`, `UseMount`, `UseOnce`: decision D5), and outside dev mode keeps meaning "mount only"; a typed nil is a dependency as before, and `UseUpdateEffect(f, Once)` is still a warning. **`h.Range`.** `Range[R ~func(int) tela.Node | ~func(int) tela.Component](n int, render R) tela.Node` renders `render(0)` … `render(n-1)` as a list keyed by index (`tela.WithKey(item, i)`, so a key the node set itself is replaced, and `Map`'s missing-key warning does not apply: a static range does not reorder); a struct component needs no `Fragment`; `n < 0` panics in dev mode (the dev mode of the tree being built, ADR-093) and renders nothing otherwise, and a nil `render` panics. **VirtualList.** `renderItem` is the same union (`VirtualList[R ~func(int) tela.Node | ~func(int) tela.Component]`): existing calls infer `R` and compile unchanged; a component is turned into its node (`core.NodeOf`) inside the item wrapper, and a Prop panics with the fix; its docs show struct rows. **`tela.StopPropagation`.** `tela.StopPropagation(f func()) tela.StopHandler` with `type StopHandler func()`: it panics for a nil `f`; every `h.On…` handler already accepts it because a named `func()` type satisfies the `~func()` branch of ADR-091's constraints, so no constraint changes: `onEvent` tells it from a plain `func()` by its dynamic type (`case tela.StopHandler`), wraps it in a `func(E)` that calls `e.StopPropagation()` before `f`, and `E` is now constrained to `interface{ StopPropagation() }`, which every event type has. The call shape is the owner's: `Button(OnClick(tela.StopPropagation(ctrl.Remove)))`, `Div(OnKeyDown(tela.StopPropagation(close)))`; a zero `StopHandler` panics like `OnClick(nil)`. `aria.UsePress` will stop propagation by default.

## Rationale

The owner's shapes. The aria variants reuse `istate` instead of a second state set because group and peer lookups, the narrow marking and the first-style computation already read it, so the whole feature is nine flags and a mapping; Tailwind's `aria-x` selects the attribute value `"true"`, which is what the props set, so implicit states stay with `disabled:`, `checked:` and `read-only:`. A named func type as the `StopPropagation` result keeps ADR-091's union closed and adds no type parameter Go could not infer; the price is that it is also accepted where a plain `func()` is (it is one). Playwright's snapshot is the contract of ADR-058, so the new states are readable in the semantics tree and in `telatest`'s messages but not in the YAML. Under `NoSettle` an expectation that passes at once must not move the clock, or a test could not assert a mid-animation state; polling stays so that expectations on goroutine-set state still work. Rendering is unchanged: every golden is bit-identical
