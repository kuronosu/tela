# ADR-109: Second phase-8 review, core

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Second phase-8 review, core (amends ADR-096, ADR-098 and ADR-107). **Float retry frames per element (ADR-107).** The frames that limits left by a spent relayout budget ask for are counted per floating element (`floatState.retries`, up to `maxFloatRetryFrames`), not per tree: an element's count starts again in a frame that places it without dropping limits, so one whose limits never settle spends its own frames and no longer keeps another from getting its frames (the tree's count was reset only by a frame where no element dropped limits). The run of frames that ask in a row is bounded by `maxFloatRetryFrames` × the floating elements, so elements that drop limits in turn, each settling while another drops, cannot ask forever. **Asset cache lock (ADR-098, ADR-107).** `cachedMedia` and `convertBgImage` take `assets.mu` only in functions that unlock with `defer` (`lookupMedia`, `addMedia`, `lookupConv`), and run no decoding under it: a key that panics when hashed no longer leaves the lock held (the root cause of the `SrcFS` deadlock; `hashable` stays the guard). `convertBgImage` uses `hashable` too instead of the dynamic type's `Comparable`, so a comparable image type holding a non-comparable value in an interface field is converted without the cache. `hasInterface` is cached per `reflect.Type` (`interfaceTypes`, a `sync.Map`). **Touch pan (ADR-107).** When a pan wins a touch, the click sequence is reset (`pointerCancel` did, the pan did not: a tap recognizer's rejection reset it only for paths with click handlers), so a quick tap after the scroll is a single click. After the `pointercancel` the pointer leaves its boundary chain at once (pointerleave, then mouseleave for a primary pointer: the Pointer Events spec fires pointerout and pointerleave after pointercancel), and while `panned` a move updates no boundary chain, so the elements the finger passes over (once the implicit capture was released or its element unmounted) get no enter or leave events, and the release fires none.

## Rationale

Each finding was reproduced by a test that fails without its fix: `TestFloatingRetriesPerFloat` (the second element stopped at 80 px of a 50 px limit), `TestCachedMediaUnlocksOnPanic` and `TestBgImageUnhashable` (the lock stayed held), `TestTouchPanResetsClicks` (click counts 1, 2 after the pan), `TestTouchPanNoBoundaryEvents` (enter and leave on three rows during the pan and a leave at the release); `TestHasInterfaceCached` covers the cache. Leaving the chain at the cancel rather than at the release follows the spec and keeps ADR-107's contract that nothing of the touch is dispatched after its cancellation. Every golden is bit-identical
