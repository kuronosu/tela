# ADR-100: Behavior hooks of package `aria`

- **Date:** 2026-10-21
- **Status:** Accepted

## Decision

Behavior hooks of package `aria`: press, hover, focus, buttons, toggles (phase 8, T5a; E5 and the extra hooks are the owner's decisions; amends §10, §14, ADR-055, ADR-056, ADR-096 and ADR-097). **Shape (E5).** A hook takes an options struct and returns a struct with a `Props tela.Prop` field (the handlers, ref, role and aria props merged with `core.MergeProps`, so the handlers of an event all run and the caller's own props combine) and its state fields (`Pressed`, `Hovered`, `Focused`, `FocusVisible`, `Selected`) and `Ref`. State is integrated, with no stately layer: uncontrolled by default (`DefaultSelected`), controlled when `OnChange` is set (`Selected: on, OnChange: setOn.Set`: the control shows `Selected` and only asks `OnChange`, so a change the caller does not store is refused; `Disabled`, `ReadOnly` and the names of React Aria translated to Go: `OnPressStart`, `OnPressEnd`, `OnPressUp`, `OnPressChange`, `OnPress`, `ShouldCancelOnPointerExit`, `PreventFocusOnPress`). An uncontrolled control with a listener is not expressible (a plain bool cannot say "unset"); read `Selected` of the result. **One ref per element.** An element holds one `h.Ref`, so the hooks that need the element (press: pointer exit by bounds, capture, keyboard focus check; focus ring; scope; the controls built on press) take a `Ref` option and return the `Ref` they attach; several hooks on one element share one made with `tela.UseElementRef`, and a hook without it makes its own (the last `h.Ref` of the element wins: documented in `aria/doc.go`; a ref attached to nothing makes a press never leave rather than fail). **UsePress** is React Aria's usePress over Tela's events: pointer down, move, up and cancel (not mouse events) plus click, key and blur handlers. A press starts on the primary button, a touch or a pen; a mouse is captured with `core.SetPointerCapture` and a touch keeps its implicit capture, so the hook checks the element's `Bounds` on every move: leaving ends the press (`OnPressEnd`, `OnPressChange(false)`, no `OnPress`), coming back while held starts it again, and `ShouldCancelOnPointerExit` ends it for good; a release over the element is `OnPressUp`, `OnPressEnd` and `OnPress`; a pointer cancel ends it. Pressing stops the propagation of the events that make it (pointer down and up, key down and up, the click) unless a callback of the step calls `PressEvent.ContinuePropagation()` (any one continues), and prevents the default action of the click (a Button does not submit its Form, a Label does not forward the click). The keyboard works on the element itself only (a key typed in a field inside it is the field's: `ElementRef.Focused`): Enter presses at once on the key down (start, up, end, press; repeats ignored; the key up is swallowed), Space starts on the key down and completes on the key up (repeats ignored, cancelled by a blur), both with the default of a Button prevented, and checkboxes and switches take Space only. A click that no pointer pressed (the "click" action of the semantics tree, a Label forwarding its click, an agent) is a virtual press: the hook knows a click is its own press's by the release it saw (`tracking`, `expectClick`; a press that left and was cancelled still owns its click), not by the click count, which a semantics click sets to 1. **Deviation from React Aria:** Enter fires on the key down, as the HTML button does and the owner asked, where React Aria fires `onPress` for both keys on the key up; a virtual press reports the center of the element; `PressEvent` has the window position and the position local to the element; `Disabled` also stops the propagation of the click and prevents its default (React Aria does); the press hook adds no props of its own beyond handlers and the ref. **UseHover** uses pointer enter and leave and ignores touch by `PointerEvent.Kind` (Tela does not emulate hover from touch, but a touch press enters the element). **UseFocusRing** (`Within` option) reads the engine after focus, blur, key down and pointer down (`ElementRef.Focused`, `core.FocusVisible`, and `core.ContainsFocus` and the new `core.FocusVisibleWithin` for `Within`), because the focus-visible state changes without a focus event when a key follows a click; a blur clears both and the focus that follows restores them (the window losing focus fires a blur but leaves `ElementRef.Focused` true). **UseFocusScope** returns `{Props, Manager, Ref}` with `core.Scope` (contain, restore, auto-focus) and `FocusManager`, whose `FocusNext`, `FocusPrevious`, `FocusFirst` and `FocusLast` take `FocusOptions{Tabbable, Wrap, From}` and call the engine's focus manager; `UseFocusManager` for descendants (a context) is not added: the manager is a value to pass. **Controls.** `UseButton` adds `Role("button")`, `Disabled` and a tab stop to the press and has no `Type` option (`h.Type` panics on a Div, and Tela has no programmatic click to submit a form from a press: a Button with the hook never submits; call the handler from `OnPress`); `UseToggleButton` adds `AriaPressed`; `UseCheckbox` and `UseSwitch` (`checkbox` and `switch` roles, `AriaChecked`, `AriaReadOnly` when `ReadOnly`, `Disabled`, an `ID` that `tela.UseID` makes or the caller gives, for `Label(For(id))`, which names the control and toggles it with its click: render them with a `Button`, the element a Label can label) toggle on `OnPress`; there is no indeterminate state (`h.AriaChecked` takes a bool). **Engine changes (small, tested).** (1) `checked:`, `peer-checked:` and `group-checked:` now match: `ariaStates` also sets `style.StateChecked` when `AriaChecked` is true (it was defined and never set; amends ADR-097's note that `checked:` never matches), through the same `setAriaStates` path, so only the elements whose classes test it restyle and a mixed or false value does not match. (2) A touch pan that wins the arena fires `pointercancel` at the element the finger pressed (`panRecognizer` takes the pointer), as a browser does when it takes a touch over for scrolling, so a press ends with the scroll instead of firing on release; the later pointer up still arrives and the tap is already rejected. (3) `core.FocusVisibleWithin(ref)`. Every golden is bit-identical.

## Rationale

The owner's shapes (E5, state integrated, the hooks and the `checked:` fix). Pointer events plus a bounds check give React Aria's exit and re-entry rules for mouse, touch and pen with one code path, since the engine's capture makes the element the target of the whole press; the click handler is what lets a Label, an agent or a screen reader press without pointer events. Preventing the click's default and stopping its propagation is React Aria's rule and keeps a pressable card from also clicking its row. Controlled-by-`OnChange` is the rule closest to the owner's example (`Selected: on, OnChange: setOn.Set` versus `DefaultSelected`) and the one a plain bool allows. Sharing one ref is the price of one `desc.ref` per element: a multi-ref engine would touch the focus, scroll and bounds bookkeeping. The pan cancel is the DOM's own rule and the smallest way to give a press the scroll signal the arena already has
