# ADR-080: Explicit animations, enter and exit

- **Date:** 2026-10-18
- **Status:** Accepted

## Decision

Explicit animations, enter and exit (phase 6, T7; implements §12 "Explicit animation" and "Enter/exit"; the public API is the owner's decision; refines ADR-076). **API.** `tela.UseSpring[T Animatable](initial, target T, opts ...AnimationOption) *Value[T]` and `tela.UseTween` (same shape) follow a target that changes between builds: the first build holds `initial` and moves to `target` if it differs, and a new target restarts the motion from where the value is, a spring keeping its velocity (Compose's `animate*AsState`, Motion's `useSpring`). `tela.Animate[T](v *Value[T], target T, opts ...AnimationOption)` animates any Value from handlers, effects or goroutines: it is queued like `Set`, in order with `Set` and `Update`; applied inside a frame it starts at that frame's time, applied between frames at the next frame; a new `Animate` interrupts the running motion from its position and velocity, `Set` and `Update` stop it, `Latest` does not anticipate it. `Animatable` is `float32 | Color | Point | Size | Rect`, with the new `tela.Point{X, Y}` and `tela.Size{Width, Height}` (aliases of core types, like `Rect`); colors move as `anim.LerpColor` interpolates (premultiplied, sRGB for two legacy colors, Oklab otherwise), the other types component by component, each with its own velocity and rest thresholds. `AnimationOption`: `Stiffness`, `Damping` (physics; Motion's defaults 100 and 10, mass 1), `Bounce`, `Duration` (a spring found by `SpringForDuration`, defaults 800 ms and bounce 0.3, ending no earlier than its duration and at rest; or a tween's duration, default 300 ms), `Ease` (a CSS <easing-function>, default `ease`) and `Spring(opts...)`. `UseSpring` is always a spring and `UseTween` a tween; `Animate` is a spring unless its options are only `Duration` and `Ease`. Contradicting options (Ease on a spring, physics with Duration or Bounce, spring options on UseTween), invalid numbers and invalid easings (with a suggestion: the keyword the string starts with or the closest one; Tailwind's `in`/`out`/`in-out` get the CSS keyword and Tailwind's cubic-bezier) panic in dev mode and are ignored otherwise (physics wins, as in Motion). **Model.** `anim.Motion` moves an `anim.Vec` of up to four components with a closed-form spring (Motion's rest thresholds per component, ended at 20 s) or a tween (its velocity by a 5 ms finite difference, Motion's), and reports position and velocity at any time. Each animated Value has one `valueAnim` in the Tree's ticker that stores the Value on the UI thread at every frame (`storeUI`), so its readers are redone in the phase that read it: a `TranslateFn` or `OpacityFn` only composites, a `WidthFn` only lays out, the body builds. A tree that no frame clock drives (`Render`, `tela snapshot`) and reduced motion apply targets at once; a Host marks its tree driven from creation, so the animations of the first builds wait for the first frame instead of jumping. **starting:** a `Condition.Starting` variant (`Input.Starting` computes the starting style). A box that starts being rendered (it mounts, or its own `display: none` ends) has no before-change style: it starts no transition and running ones end (ADR-076 transitioned out of `display: none`), except from its starting style when its classes have `starting:` rules and the tree is driven without reduced motion (CSS Transitions 2, `@starting-style`). Starting rules follow §10's order of appearance like the other variants. **Presence.** `h.Presence(children ...tela.Child)` is a component element without a function, like a Provider. A child that a build removes (by key, or by position for an `h.If` hole) and that has exit work, primitives with `h.Exit` classes in its subtree (not inside a nested Presence) or components that called `UsePresence`, stays mounted at its old index (Motion's merge; it keeps its layout position, `popLayout` false) with its last node; a child without exit work unmounts at once. The exit appends the Exit classes to those primitives' classes (the restyle starts ADR-076 transitions), rebuilds the `UsePresence` components with `present` false, and makes the subtree inert: not hit by the pointer, not focusable nor in the Tab order (the focus inside is lost as on unmount, and focus scopes end, restoring the focus at once), absent from the semantics tree (aria snapshots, locators). It ends when every `UsePresence` component called `done` (one stable function per slot, safe from any goroutine; a call made during an exit that was then cancelled is ignored by a generation count) and the transitions of the Exit primitives have ended, as checked after the style phase of the frame that starts it (no transition, reduced motion and `Render` end in that frame), in the animation phase of every frame and when `done` applies; the child then unmounts. Adding an exiting child back cancels the exit: the Exit classes come off (its transitions run back from where they are), the scopes return, `present` is true again. **telatest.** Auto-wait waits for exits (their transitions ask for frames). `NoSettle()` (the owner's addition): Mount, the settles after an action's events, `Screenshot` and `Golden` handle only the work due (state updates and the frames they request) without advancing the clock for animations, so `Advance` steps them; only the waits before an action still settle (amended by ADR-097: the expectations, `AriaSnapshot`, `Count`, `Bounds`, `Stats` and `Cursor` handle only the work due too).

## Rationale

The owner's API, with Motion's and Compose's behavior (retargeting keeps velocity, exits wait for `done`) and CSS's for `starting:`, so that what users and LLMs write in React, Motion and Tailwind works. Measured against Chromium 152's `@starting-style` (`internal/core/testdata/chromium/starting`: 8 cells, fade, fade and scale, translate and rotate, an Oklch color, width, a delayed fade, blur, and a box without transition; paused with the Web Animations API at 100, 250, 500 and 750 ms): mean differences of 0.000 to 0.431 levels per cell, maxima 1 to 65 on anti-aliased circle and corner edges (also at rest). The retarget is exact: the new motion starts at the old one's position and velocity at that frame. The app is idle once its springs come to rest and its exits end. Known gaps for the owner: `Animate` has no completion signal (a manual exit reads the value in its body to call `done`), no deferred color style props (`BgFn`), no initial velocity option (a drag release starts its spring from rest unless a running motion gives one), `starting:` does not apply when an ancestor's `display: none` ends
