# ADR-079: CSS effects in `core` painting

- **Date:** 2026-10-18
- **Status:** Accepted

## Decision

CSS effects in `core` painting (phase 6, T6; the public API is the owner's decision). **mix-blend-mode:** a stacking context with a blend mode is painted in a layer that composites with it (`PushLayer`'s `Blend`, ADR-074; all Level 1 modes and plus-lighter, `mix-blend-*`). CSS blends it with its parent stacking context only, an isolated group: a stacking context whose own scope (descendants not inside nested stacking contexts, `Box.blendDesc`, computed when boxes are placed) has blending boxes pushes a source-over layer even without opacity or filters, so content painted before it is not the backdrop; the root's group is the canvas. `bg-blend-*` (background-blend-mode, one mode for every layer, no plus-lighter) blends each image layer in a layer of that mode inside an isolated group of the element's background. **clip-path:** written as the Tailwind arbitrary property `[clip-path:<shape>]` (underscores for spaces; variants apply), the only arbitrary property accepted (every other keeps its error). Shapes: `inset()` with 1–4 lengths and optional `round` radii (with `/`), `circle()` and `ellipse()` with lengths, `closest-side`/`farthest-side` and `at <position>`, `polygon()` with an optional `nonzero`/`evenodd`, and `none`; the reference box is the border box (an explicit `border-box` is accepted, other boxes, `path()`, `url()`, `rect()`, `xywh()` are reported as unsupported). `style.ClipPath` keeps a shape and its lengths in a fixed layout (`Values []LP`), so shapes of the same kind and length interpolate value by value: `transition-[clip-path]` (`TransitionClipPath`, `anim.PropClipPath`, an ink-class property) animates them, other pairs switch halfway. A clip path makes a stacking context; it is resolved against the unsnapped border box and pushed inside the transform, before the backdrop filter and the layer (circle, ellipse and inset as rounded-rectangle clips, polygons as path clips), so it clips shadows, outline, filter results and descendants like CSS; hit-testing applies the same shape after undoing the transform (point in rounded rectangle, polygon winding by fill rule). **Background images:** `bg-[url(p)]` names a file of the file systems registered with `tela.Assets(fs.FS)` (called from `init`; several calls are searched in registration order, the first that has the file wins; paths are relative to their roots, a leading `/` or `./` is dropped, `..`, remote and `data:` URLs are refused); files are decoded once by content (PNG, JPEG, GIF's first frame, WebP via `golang.org/x/image/webp`) and cached by cleaned path for the life of the process (failures until another registration); a missing or undecodable file paints nothing and is reported once per path in the dev log with the registered file systems. `tela.BgImage(image.Image)` sets a decoded image as the layer (the background classes apply to it); each image value is converted once, in a 256 MiB least-recently-used cache keyed by the value. `bg-[a,b]` lists layers (first on top) and the size, position, repeat and origin classes apply to every layer. Painting follows CSS Backgrounds 3: natural size, `cover`, `contain`, lengths with an auto side keeping the ratio, `round` rescaling, `space` spreading whole tiles (position ignored when two fit), tiles repeated over the painting area; like Blink an image tile's size is rounded to whole device pixels before it is positioned and its edges snap to device pixels. A tile drawn smaller than its image is drawn from mip level ⌊log2(1/k)⌋ (k the device scale of the tile, the level just larger than the tile, Chromium's choice): `gfx.Image.Level(n)` builds Skia's box-filtered levels (2 taps on even sides, 1-2-1 on odd ones) once per image. **bg-clip-text:** the backgrounds are painted in `PushMaskLayer` whose mask is the element's foreground text: the glyph runs (and decorations) of its paragraphs and of its in-flow descendants', painted opaque, under their overflow clips; an inline element's fragment uses the glyphs of its line (its background is already clipped to the fragment). Text in a moving scroll container's content inside the element is not part of the mask. Like Chromium, a solid text paint's alpha now also applies to color glyphs (emoji) drawn as cached sprites, and a transparent text color draws no color glyphs, so `text-transparent` shows the clipped background through emoji (amends ADR-074's builder note)

## Rationale

Measured against Chromium 152 with Tailwind 4.3.3 (`internal/core` `TestChromiumEffects`, 62 cells at scales 1 and 2): blend cells (8 modes, isolated by `isolate`, `z-10` and opacity, over images) mean 0.11–0.51 levels per channel, max 77 on anti-aliased edges, and blended text 0.57/0.85 (glyph edges); clip-path cells (circle, ellipse, inset round, polygons with percentages, evenodd star, under rotation/scale, with shadows, outline, opacity, overflowing children, over an image) mean ≤ 0.51, max ≤ 89 on curve and tip edges; background images (cover, contain, lengths, percentages, positions, every repeat mode, origin/clip boxes, rounded with border, layer lists with gradients, `bg-blend-multiply`/`luminosity`, JPEG, WebP) mean ≤ 0.91 at x1 and ≤ 1.27 at x2, where Chromium's repeating shader interpolates across tile seams and Tela clamps each tile; downscaled photos and a zone plate mean 0.29–1.39 with mip levels against 0.67–21.2 without (zone plate 192→64 px: 21.24 → 0.56); bg-clip-text headings (gradient, photo, three wrapped lines, an inline span over two lines, emoji) mean 1.05–3.63 from glyph anti-aliasing and baselines, as ADR-074's measurements. Incremental frames stay bit-identical to full ones in a property test that scrolls and restyles blended, clipped, image and clip-text rows and moves a clipped, blended `TranslateFn` layer at five scales. Per-tile repeat (no seam interpolation) and the color-glyph alpha only on sprites (not on glyphs too large or transformed for the cache) are known differences
